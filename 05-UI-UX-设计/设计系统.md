## 1. 设计原则

### 1.1 核心设计理念

| 原则 | 描述 | 应用 |
|------|------|------|
| **工业美学** | 专业、简洁、信息密集 | HMI/SCADA风格界面 |
| **数据优先** | 优先考虑数据的可见性和可访问性 | 高信息密度 |
| **上下文操作** | 操作在需要的位置提供 | 内联操作、上下文菜单 |
| **渐进式披露** | 先显示基本信息，按需显示详细信息 | 可折叠区域、工具提示 |
| **一致的模式** | 相同操作使用相同模式 | 统一的组件行为 |

### 1.2 可访问性标准

- **WCAG 2.1 AA级** 合规性
- **颜色对比度**：普通文本最小4.5:1，大文本最小3:1
- **键盘导航**：完整的键盘可访问性
- **屏幕阅读器**：ARIA标签和语义化HTML
- **焦点状态**：清晰、可见的焦点指示器

#### 2.4.1 工艺色优先级判定规则（F3-016，前端实现 & SAC-6 验收依据）

**判定顺序（高优先级覆盖低优先级）：温控精度 > 洁净度 > 压差。**

按下列顺序自上而下匹配，命中第一档即取该色，不再向下判定：

| 优先级 | 条件 | 颜色 | 色值 | 数据字段（取值） |
|--------|------|------|------|------------------|
| ① 最高 | 温控精度 = ±1°C | 红 | `#FF4D4F` | `room.temp_precision` ∈ {`±1`} |
| ② | 温控精度 = ±2°C | 橙 | `#FA8C16` | `room.temp_precision` ∈ {`±2`} |
| ③ | 洁净度等级 = ISO7 | 黄 | `#FADB14` | `room.cleanliness_level` = `ISO7` |
| ④ | 洁净度等级 = ISO8 | 绿 | `#52C41A` | `room.cleanliness_level` = `ISO8` |
| ⑤ | 洁净度等级 = ISO7.5 | 蓝 | `#1890FF` | `room.cleanliness_level` = `ISO7.5` |
| ⑥ | 正压区（功能区域压差 > 0 Pa） | 紫 | `#722ED1` | `Room.pressure_diff` > 0 |
| ⑦ 兜底 | 负压 / 普通区域（不满足以上任何一档） | 灰 | `#BFBFBF` | 其余情况（含字段为空/未设置） |

**字段映射说明（来源：数据库设计 §4、PRD 附录 G）：**

- **温控精度** `room.temp_precision`：枚举值 `±1` / `±2` / `±3` / `±5` / `无要求`；仅 `±1`、`±2` 命中工艺色（对应红/橙），`±3`/`±5`/`无要求` 不命中本档，继续向下判定洁净度与压差。
- **洁净度等级** `room.cleanliness_level`：文本，如 `ISO7`、`ISO7.5`、`ISO8`；无要求时留空（不命中）。
- **功能区域压差** `Room.pressure_diff`：数值（Pa），正值为正压（紫），负值为负压（落兜底灰）。注意：`±3`/`±5` 的温控精度不参与着色，直接转入洁净度→压差→灰的判定链。
- **兜底（F3-019）**：当上述三字段均为空/未设置时，使用灰色 `#BFBFBF`，并在未关联方块上标注"未关联"。

**判定伪代码（前端 `HeatmapCanvas` 实现参考）：**

```ts
function getProcessColor(room: Room): string {
  // ①② 温控精度
  if (room.temp_precision === '±1') return '#FF4D4F';
  if (room.temp_precision === '±2') return '#FA8C16';
  // ③④⑤ 洁净度（统一比较前做大小写/空格归一）
  const cls = (room.cleanliness_level ?? '').toUpperCase().replace(/\s/g, '');
  if (cls === 'ISO7')   return '#FADB14';
  if (cls === 'ISO8')   return '#52C41A';
  if (cls === 'ISO7.5') return '#1890FF';
  // ⑥ 正压区
  if ((room.pressure_diff ?? 0) > 0) return '#722ED1';
  // ⑦ 兜底：负压/普通
  return '#BFBFBF';
}
```

> 关联需求：F3-015（双模式切换）、F3-016（工艺色优先级）、F3-019（未关联灰色兜底）；验收场景 SAC-6。

#### 2.4.2 双模式颜色编码切换（F3-015）

2D 可视化查看器（工作台 Tab5）提供两种着色模式，用户可随时切换：

| 模式 | 规则 | 用途 |
|------|------|------|
| **冷量热力图模式** | 按 `total_load` / 冷指标映射蓝→红连续渐变（§2.5），可叠加 5 级分级图例 | 识别高负荷区域 |
| **工艺要求编码模式** | 按 §2.4.1 优先级规则取 7 色之一 | 按工艺约束分区查看 |

切换后立即重新着色（刷新 < 1 秒，F3-024）；模式切换不影响数据，仅改变渲染。

### 5.9 Conversational UI（对话式采集）

> 适用范围：模块二「对话式采集」独立全屏页面（PRD 3.1 页面六、6.10）。该页面采用**类 Codex 三栏布局**，但视觉**严格复用本设计系统**的色板、字体、间距、主题与 i18n 体系——不另行定义独立设计语言。

**Layout（三栏全屏）：**
```
┌──────────┬────────────────────────────┬──────────────────┐
│ 阶段导航  │   对话主区（类 Codex）      │   结构化预览侧栏   │
│ （固定宽）│  · 系统提问气泡              │  · 实时数据树        │
│ ①~⑥     │  · 用户回答气泡              │  · 当前区域摘要      │
│ 当前/已完成│  · 确认/摘要卡片 + 工具卡片  │  · 缺失项提示        │
│ 可点跳转   │  · 输入框 + 快捷芯片（Chip）  │  · 结果表格（可展开）│
└──────────┴────────────────────────────┴──────────────────┘
```

**Components & Tokens：**
- **Chat Bubble（对话气泡）：** 系统提问左对齐、用户回答右对齐；背景与边框使用 `--panel` / `--line`，圆角 4~12px（参考 5.2/5.4 容器规范），不引入新色值。
- **Tool Card（工具结果卡片）：** 气象拉取等异步结果以可折叠卡片呈现；标题用等宽字体 `--mono`，左侧状态点用 Semantic 色（进行中=主色、成功=OK、失败=危险），遵循 §2.4 / §8.2。
- **Summary Card（确认摘要卡片）：** 关键节点结构化摘要；操作按钮（确认/修改/跳过）复用 §5.7 Modal/Dialog 与 §5.2 按钮规范，主操作移至右侧。
- **Chip（快捷芯片）：** 复杂枚举的快捷作答项，描边 `--line2` 虚线、悬停变主色，复用 `--mono` 字体；尺寸与 §4.1 Spacing 一致。
- **Stage Nav（阶段导航）：** 六阶段（①产品工艺…⑥结果表格）竖向列表，状态用圆点（未完成=`--line2`、当前=主色+辉光、已完成=OK 色）；与顶部进度条（§5.1 导航条右侧）联动。
- **Structured Preview（结构化侧栏）：** 实时数据树复用 §5.2 Tree Navigation 组件；缺失项提示用 Warning 语义色（§2.4）。

**Theme & i18n：** 暗/浅双主题与语言切换由 §6 / §7 统一管理；对话页不覆盖主题变量，仅按 `--bg` / `--panel` / `--text` / `--muted` 取色。所有气泡/卡片/芯片文案走 i18n 语言包，不硬编码。

**Responsive：** 参照 §9，窄屏（≤1100px）隐藏结构化侧栏、保留阶段导航 + 对话主区；超窄屏（≤720px）阶段导航收起为顶部步骤条，对话主区全宽。
