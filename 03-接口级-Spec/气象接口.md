## 1. 概述

气象数据是动态仿真（方式一 weather_driven）与负荷预测（API 模式）的输入源。系统支持两种获取方式（A2）：
1. **外部 API 拉取**：Celery 异步任务调用气象 API，获取最近连续 3 年逐时数据（闰年 8784、平年 8760，总量约 26280~26304 条，F4-047）。
2. **手动上传**：CSV/EPW 文件上传，用于 API 失败时的降级补数据。

气象数据存储于 `WeatherRecord` 表（**TimescaleDB 超表，按 `city_id + timestamp` 分区**），字段含干球/湿球/相对湿度/大气压/风速/太阳辐射/来源/插补标记。

### 1.1 端点总览（附录D 权威清单）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/weather/fetch/{cityId}` | 触发 Celery 异步拉取气象数据 |
| POST | `/api/v1/weather/upload` | 手动上传 CSV/EPW 气象数据 |
| GET | `/api/v1/weather/{cityId}/summary` | 气象数据概况（来源/时间范围/记录数/缺失率） |

## 2. WeatherRecord 表字段（TimescaleDB 超表）

`WeatherRecord` 为 TimescaleDB hypertable，按 `city_id + timestamp` 分区（详见分区策略.md）。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| city_id | BIGINT FK → `CityConfig.id` | 是 | 城市外键 |
| timestamp | TIMESTAMP | 是 | 逐时时间戳（UTC），超表 time 列 |
| dry_bulb | DECIMAL(5,2) | 是 | 干球温度 ℃ |
| wet_bulb | DECIMAL(5,2) | 否 | 湿球温度 ℃ |
| humidity | DECIMAL(5,2) | 否 | 相对湿度 % |
| pressure | DECIMAL(10,2) | 否 | 大气压 hPa |
| wind_speed | DECIMAL(4,1) | 否 | 风速 m/s |
| solar_radiation | DECIMAL(8,2) | 否 | 太阳辐射 W/m²（F1-020：v0.5 采集不参与计算，v0.6 评估纳入） |
| source | enum | 是 | `api`（外部 API）/ `manual`（手动上传） |
| imputed_flag | bool | 是 | true=该小时数据缺失已被插补；false=原始数据 |
| created_at | TIMESTAMP | 是 | 写入时间 |

**索引**：`(city_id, timestamp)` 复合索引（见索引设计.md），支撑按城市+时间范围高效查询。

## 3. POST /api/v1/weather/fetch/{cityId}

触发 Celery 异步任务调用气象 API，拉取该城市最近连续 3 年逐时数据。

**请求**：无 body。可选 query 参数 `years`(array[int]，默认最近 3 年)。

**响应 202**（异步）

```json
{
  "success": true,
  "data": {
    "task_id": "weather-fetch-20260714-001",
    "city_id": 2,
    "city_name": "深圳",
    "status": "processing",
    "years_requested": [2023, 2024, 2025],
    "estimated_records": 26280,
    "message": "Weather data fetch started",
    "websocket_url": "ws://localhost:8000/ws/tasks/weather-fetch-20260714-001"
  }
}
```

**行为**：
1. 服务端校验 `cityId` 存在于 `CityConfig`。
2. 派发 Celery 任务 `fetch_weather_data(city_id, years)`。
3. 任务内：逐小时调用气象 API（或批量接口），解析后流式 `COPY` 写入 `WeatherRecord`（TimescaleDB 按时间块追加，顺序写友好）。
4. 数据完整性校验：记录数应接近 8760×N（闰年容差），缺失小时由插补算法填充并置 `imputed_flag=true`。
5. 完成后推送通知「气象数据已就绪」（F1-021，<5 分钟）。

**降级**：API 调用失败时（F1-022），任务标记 failed，项目 `weather_data_status` 置为 `missing`，用户可稍后重试或手动上传。

**错误码**

| HTTP | code | 触发条件 |
|------|------|----------|
| 404 | RESOURCE_NOT_FOUND | cityId 不存在于 `CityConfig` |
| 409 | CONFLICT | 该城市已有进行中的 fetch 任务（防重复） |
| 503 | SERVICE_UNAVAILABLE | 气象 API 暂时不可用（同步预检阶段） |

## 4. POST /api/v1/weather/upload

手动上传气象数据 CSV/EPW 文件，用于 API 失败时的降级补数据。

**请求**：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| file | file | 是 | CSV 或 EPW 文件 |
| city_id | int | 是 | 关联城市 ID |
| source_format | enum | 否 | `csv`（默认）/ `epw` |
| overwrite | bool | 否 | true=覆盖同时间范围既有数据；false=跳过冲突记录（默认） |

**响应 200**

```json
{
  "success": true,
  "data": {
    "city_id": 2,
    "city_name": "深圳",
    "source": "manual",
    "total_rows": 26304,
    "imported_count": 26280,
    "skipped_count": 24,
    "imputed_count": 0,
    "time_range": { "start": "2023-01-01T00:00:00Z", "end": "2025-12-31T23:00:00Z" },
    "invalid_rows": [
      { "row": 100, "reason": "dry_bulb 超出合理范围 [-50, 60]" }
    ],
    "imported_at": "2026-07-14T10:00:00Z"
  }
}
```

**CSV 格式**：`timestamp, dry_bulb, wet_bulb, humidity, pressure, wind_speed, solar_radiation`（首行表头）。

**EPW 格式**：标准 EnergyPlus Weather 格式，按其字段映射解析。

**行为**：
- 解析文件并校验字段类型与范围。
- 写入 `WeatherRecord`，`source='manual'`，`imputed_flag=false`（原始数据）。
- 缺失小时由调用方负责（上传文件应完整）；不自动插补。
- `overwrite=true` 时，同 `city_id + timestamp` 既有记录被新值覆盖。

**错误码**

| HTTP | code | 触发条件 |
|------|------|----------|
| 400 | VALIDATION_ERROR | 文件格式不支持、必填字段缺失、city_id 未提供 |
| 404 | RESOURCE_NOT_FOUND | city_id 不存在 |
| 422 | IMPORT_ERROR | 文件解析失败（格式损坏、字段非法） |

## 5. GET /api/v1/weather/{cityId}/summary

获取该城市气象数据概况，用于气象数据管理页（Tab4）展示。

**查询参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| year | int | 否 | 限定年份；省略=全部 |

**响应 200**

```json
{
  "success": true,
  "data": {
    "city_id": 2,
    "city_name": "深圳",
    "sources": ["api", "manual"],
    "primary_source": "api",
    "time_range": { "start": "2023-01-01T00:00:00Z", "end": "2025-12-31T23:00:00Z" },
    "total_records": 26280,
    "expected_records": 26280,
    "missing_rate": 0.012,
    "imputed_records": 315,
    "by_year": [
      { "year": 2023, "records": 8760, "missing_rate": 0.010 },
      { "year": 2024, "records": 8784, "missing_rate": 0.015 },
      { "year": 2025, "records": 8736, "missing_rate": 0.011 }
    ],
    "statistics": {
      "temp_range": { "min": 5.2, "max": 36.8, "avg": 23.5 },
      "humidity_avg": 75.5,
      "last_fetched_at": "2026-07-14T08:00:00Z"
    },
    "quality_status": "good"
  }
}
```

**字段说明**

| 字段 | 说明 |
|------|------|
| sources | 数据来源列表（api/manual 混合时都列出） |
| primary_source | 主要来源（记录数多的） |
| time_range | 最早/最晚时间戳 |
| total_records | `WeatherRecord` 实际行数 |
| expected_records | 期望行数（年份×8760/8784） |
| missing_rate | 缺失率 = (expected - actual) / expected |
| imputed_records | `imputed_flag=true` 的行数 |
| quality_status | `good`（缺失率<2%）/ `warning`（2%~5%）/ `poor`（>5%） |

**数据来源**：对 `WeatherRecord` 表按 `city_id` 聚合统计（COUNT/MIN/MAX/AVG），走 `(city_id, timestamp)` 索引。

**错误码**：`404 RESOURCE_NOT_FOUND`（cityId 不存在或无气象数据）。

## 6. 鉴权与数据隔离

- `/weather/fetch/{cityId}` 与 `/weather/upload` 需工程师及以上角色（触发数据写入）。
- `/weather/{cityId}/summary` 需项目成员（关联该城市的项目成员可查）。
- 气象数据为城市级共享资源（多项目关联同城市复用），不按项目隔离。
