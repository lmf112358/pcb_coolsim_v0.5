## 1. 概述

静态冷量计算在「设计日最不利工况」下逐房间计算：末端负荷（土建+照明+人员+电动+电热设备） + 新风冷负荷（按水温档分类，ADR-0001）。本文件覆盖附录D 计算端点：静态计算、结果查询、实时预览。

**核心桥梁**：`Q_terminal`（末端负荷）计算一次，静态与动态两端复用（PRD §8.1）：
- 静态设计负荷 = Q_terminal + Q_fresh_air_static（一个固定值）
- 动态仿真 Q_dynamic(t) = Q_terminal + Q_fresh_air(t)（约 26280 逐时值，详见仿真接口.md）

### 1.1 端点总览（附录D 权威清单）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/calc/static/{projectId}` | 项目级静态计算（异步 Celery，202 + task_id） |
| POST | `/api/v1/calculations/preview` | 实时预览（单节点增量重算，<500ms，NF-012） |
| GET | `/api/v1/calc/results/{projectId}` | 静态计算结果查询（按建筑/楼层/水温聚合） |

> 动态仿真端点（`/api/v1/calc/dynamic/{projectId}` 等）见 **仿真接口.md**。

## 2. POST /api/v1/calc/static/{projectId}

项目级批量静态计算（异步 Celery）。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| building_ids | array[int] | 否 | 限定建筑范围 |
| floor_ids | array[int] | 否 | 限定楼层范围 |
| room_ids | array[int] | 否 | 限定房间范围 |
| recalculate_all | bool | 否 | 强制重算（覆盖既有结果），默认 false |

```json
{ "building_ids": [1, 2], "floor_ids": null, "room_ids": null, "recalculate_all": false }
```

**响应 202**（异步）

```json
{
  "success": true,
  "data": {
    "task_id": "calc-static-20260714-001",
    "status": "processing",
    "message": "Static calculation started (135 rooms)",
    "websocket_url": "ws://localhost:8000/ws/tasks/calc-static-20260714-001"
  }
}
```

**计算链路（6 步流水线，对齐 F4-001~F4-014 与 ADR-0001）**

```
for each room in scope:
  1. enthalpy: 室内外焓值（psychrolib，F4-010）
     h_indoor = psychrolib(indoor_calc_temp, indoor_calc_humidity, pressure_summer)
     h_outdoor = psychrolib(temp_dry_ac_summer, temp_wet_ac_summer, pressure_summer)
     Δh = h_outdoor - h_indoor（新风冷负荷可为负，冬季室外焓低于室内）
  2. terminal_load（末端，F4-001~F4-006）：
     civil_load     = civil_load_index × area / 1000
     lighting_load  = lighting_load_index × area / 1000
     personnel_load = personnel_load_index × personnel_count / 1000  （空值 0）
     electric_load  = electric_equipment_power × electric_equipment_coefficient
     heated_load    = power_with × coef_with + power_without × coef_without
     Q_terminal = civil + lighting + personnel + electric + heated
  3. air_volume（F4-007~F4-009）：
     V_exhaust = Σ(heat+acid+alkali+organic+dust)
     V_infiltration = room.volume × k(pressure_diff)  （k 由压差系数表查得，线性插值）
     V_fresh_air = V_exhaust + V_infiltration
  4. fresh_air_load（按水温档，ADR-0001）：
     Q_fresh = V_fresh_air × ρ × Δh / 3600   （ρ 从 DefaultConfig 读取，默认 1.2）
  5. total_load：
     Q_total = Q_terminal + Q_fresh；若 < 0 截断为 0（统一规则）
  6. aggregate → LoadSummary（scope: floor/building/project）
```

**写入映射（PascalCase 表名）**

| 步骤字段 | 写入表 | DB 字段 |
|----------|--------|---------|
| step2 各末端分项 + Q_terminal | `RoomCalcResult` | civil_load, lighting_load, personnel_load, electric_equipment_load, heated_equipment_load, terminal_load, cold_load_index |
| step3 风量结果 | `RoomCalcResult` | fresh_air_volume, supply_air_volume, return_air_volume, total_exhaust_volume, infiltration_air_volume, actual_air_change_rate |
| step1 焓值中间量 | `RoomCalcResult` | indoor_enthalpy_calc, outdoor_enthalpy_calc, enthalpy_diff |
| step4/5 按水温档 | `RoomLoadByWaterTemp` | fresh_air_load, terminal_load, total_load（每 `water_temp_config_id` 一行；末端按 `Room.terminal_water_temp_config_id` 归属） |
| step6 聚合 | `LoadSummary` | fresh_air_load, terminal_load, total_load（scope: floor/building/project） |

**行为**：遍历范围内房间，逐项执行计算并写入 `RoomCalcResult` / `RoomLoadByWaterTemp`，再聚合写 `LoadSummary`。跳过缺必填参数的房间并记 `warnings`。进度通过 WebSocket 推送。

**错误码**：`404 RESOURCE_NOT_FOUND`（项目不存在）、`422 CALCULATION_ERROR`（范围为空或无任何可算房间）、`422 WEATHER_DATA_MISSING`（城市室外参数缺失）、`403 INSUFFICIENT_PERMISSIONS`。

## 3. POST /api/v1/calculations/preview

**实时预览**（NF-012：单节点增量重算，参数修改后 <500ms 刷新）。用于功能区域表单底部实时展示冷量计算明细（F2-018）。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| room_id | int | 否 | 已存在房间：从库读取基准参数，再覆盖 override 字段 |
| room_params | object | 否 | 新建房间场景：直接传完整 Room 参数（不落库） |
| override | object | 否 | 针对 room_id 场景的字段覆盖（用户当前编辑中的瞬时值） |
| city_id | int | 否 | 取室外参数；若省略则用 room 关联项目的 city_id |

```json
{
  "room_id": 1,
  "override": {
    "civil_load_index": 55.0,
    "lighting_load_index": 22.0,
    "area": 850.0
  }
}
```

**响应 200**（6 步明细 + summary，同静态单房间结果但 **不落库**）

```json
{
  "success": true,
  "data": {
    "room_id": 1,
    "steps": {
      "step1_enthalpy": { "indoor_enthalpy": 52.34, "outdoor_enthalpy": 90.12, "enthalpy_diff": 37.78, "status": "success" },
      "step2_terminal_load": {
        "civil_load": 23375.00, "lighting_load": 9350.00, "personnel_load": 1800.00,
        "electric_equipment_load": 51200.00, "exhaust_heated_equipment_load": 16800.00,
        "no_exhaust_heated_equipment_load": 12000.00,
        "terminal_load": 114525.00, "status": "success"
      },
      "step3_air_volume": {
        "total_exhaust_volume": 2000.00, "infiltration_volume": 450.00,
        "fresh_air_volume": 2450.00, "supply_air_volume": 15000.00,
        "return_air_volume": 12550.00, "status": "success"
      },
      "step4_fresh_air_load": { "fresh_air_load": 92561.00, "water_temp_config_id": 2, "status": "success" },
      "step5_total_load": { "terminal_load": 114525.00, "fresh_air_load": 92561.00, "total_load": 207086.00, "status": "success" }
    },
    "summary": {
      "terminal_load_kw": 114.525,
      "fresh_air_load_kw": 92.561,
      "total_load_kw": 207.086,
      "load_density_w_m2": 243.63,

        { "water_temp_config_id": 2, "name": "中温12/17", "terminal_load_kw": 114.525, "fresh_air_load_kw": 92.561, "total_load_kw": 207.086 }

    "truncated": false,
    "warnings": []

```

**性能要求（NF-012 <500ms）**：
- 单房间单次重算，不走 Celery；同步阻塞返回。
- 参数哈希缓存：`preview:{room_id}:{params_hash}` Redis TTL 30s，参数未变直接命中。
- 室外焓值/压差系数表常驻内存或 Redis，避免每次查库。
- 复杂场景（如同时改 10+ 字段）须仍 <500ms；否则前端降级为前端本地轻量计算。

**截断规则**：`total_load < 0` 截断为 0，`truncated=true` 标记（统一规则）。

**错误码**

| HTTP | code | 触发条件 |
|------|------|----------|
| 400 | VALIDATION_ERROR | room_id 与 room_params 同时提供，或两者都缺 |
| 404 | RESOURCE_NOT_FOUND | room_id 不存在 |
| 422 | CALCULATION_ERROR | 必填参数缺失（如 civil_load_index 缺） |
| 422 | WEATHER_DATA_MISSING | 关联城市无室外参数 |

> 此端点不写库，仅返回预览结果；保存动作由 `PUT /api/v1/rooms/{id}` 触发。

## 5. 验收映射（SAC-2）

| 验收项 | 实现点 |
|--------|--------|
| 与手工 Excel 验算偏差 < 0.1% | 公式严格对齐 PRD §8 与 ADR-0001，系数一致 |
| 结果按水温分类 | `RoomLoadByWaterTemp` 按 `water_temp_config_id` 多行 |
| 进度条（批量） | WebSocket progress 消息 |
| 错误带房间标识 | `CALCULATION_ERROR` 携带 `room_id` |
| 实时预览 <500ms（NF-012） | §3 preview 端点 + Redis 缓存 |

## 6. 待确认 / 开放问题

- **O-1 实时预览的执行位置**：后端 `/calculations/preview`（统一公式、与批量结果一致）与前端本地计算（更低延迟）二选一或混合，待确认。**当前基线：后端预览为主，参数哈希缓存保障 <500ms。**
- **O-2 负荷截断的展示语义**：`total_load` 截断为 0 时，是否在结果中保留原始负值字段供调试查看，待确认。
- **O-3 by_water_temp 聚合口径**：当一个房间的 `fresh_air_water_mode=dual`（两阶段）时，新风冷负荷如何拆分到两个水温档（按时间比例/按风量比例），待暖通校准。
