## 1. 概述

本文档是 `01-系统级-Spec/数据库设计.md` §4「表结构详细设计」的**字段级细化**。数据库设计 V2.0 已给出 28 张表的字段概览与分类（用户输入 `[INPUT]` / 系统预置 `[SEED]` / 中间结果 `[CALC]` / 最终结果 `[RESULT]`），本文档在**不改动字段名与归类**的前提下，为全部 28 张表补齐可直接建表的工程要素：

- **字段类型**：与数据库设计一致（BIGINT / VARCHAR / DECIMAL / DATETIME / JSON / TEXT）
- **约束**：`NOT NULL` / `UNIQUE` / `FK`（含 `ON DELETE` 语义）
- **默认值**：建表与运行时默认值
- **校验规则**：后端录入校验、范围、业务规则
- **枚举值**：有限取值字段的取值集合
- **字段级索引建议**：单列索引建议（复合/全文索引见 `索引设计.md`）

> 约定：所有主键为 `BIGINT GENERATED ALWAYS AS IDENTITY`（自增）。`FK` 默认 `ON DELETE RESTRICT`（被引用方不可随意删除），仅当级联删除在业务中明确时标注 `CASCADE`。

### 1.1 命名约定（重要）

- **表名 PascalCase**（ORM 模型名）：`Project`、`Room`、`WaterTempConfig`、`DynamicLoadHourly` 等，对齐 PRD 附录 E。
- **字段名 snake_case**（DB 列名 / Python 属性名）：`room_name`、`terminal_water_temp_config_id`、`fresh_air_water_mode` 等。
- 物理表名（`db_table`）由 Django ORM 迁移统一映射，本文档以 PascalCase 逻辑表名为准。
- **超表**：`WeatherRecord`、`DynamicLoadHourly` 建为 TimescaleDB 超表，分区见 `分区策略.md`。

## 3. 全局约定

| 约定 | 取值 |
|------|------|
| 主键 | `BIGINT` 自增，`PRIMARY KEY` |
| 时间字段 | `DATETIME`，服务端写入，UTC 存储，API 返回 ISO-8601（`...Z`） |
| 数值精度 | 负荷/风量用 `DECIMAL(10,4)`~`DECIMAL(12,4)`；指标用 `DECIMAL(8,4)`；系数用 `DECIMAL(5,4)` |
| CityConfig 引用 | `REFERENCES CityConfig(id) ON DELETE RESTRICT` |
| 层级引用 | Building→Project / Floor→Building / Room→Floor 均为 `ON DELETE CASCADE` |
| 量纲 | 负荷 kW，指标 W/m² 或 W/人，新风量 m³/h，焓值 kJ/kg，ρ 默认 1.2 kg/m³ |
| 表名 | PascalCase（ORM 模型名） |
| 字段名 | snake_case（DB 列名） |
