## 1. 概述

本文档是 `01-系统级-Spec/数据库设计.md` §4「表结构详细设计」的**字段级细化**。§4 已给出 15 张表的字段概览与分类（用户输入 `[INPUT]` / 系统预置 `[SEED]` / 中间结果 `[CALC]` / 最终结果 `[RESULT]`），本文档在**不改动 §4 任何字段名与归类**的前提下，为全部 15 张表补齐可直接建表的工程要素：

- **字段类型**：与 §4 一致（BIGINT / VARCHAR / DECIMAL / DATETIME / JSON）
- **约束**：`NOT NULL` / `UNIQUE` / `FK`（含 `ON DELETE` 语义）
- **默认值**：建表与运行时默认值
- **校验规则**：后端录入校验、范围、业务规则
- **枚举值**：有限取值字段的取值集合
- **字段级索引建议**：单列索引建议（复合/全文索引见 `索引设计.md`）

> 约定：所有主键为 `BIGINT GENERATED ALWAYS AS IDENTITY`（自增）。`FK` 默认 `ON DELETE RESTRICT`（被引用方不可随意删除），仅当级联删除在业务中明确时标注 `CASCADE`。

## 2. 与数据库设计 §4 的关系

| 项 | 说明 |
|----|------|
| 字段名 | 严格沿用 §4，未重命名、未新增列（新增建议一律列入 §12「待确认」） |
| 字段分类 | 沿用 §4 的 `[INPUT]`/`[SEED]`/`[CALC]`/`[RESULT]` 标记 |
| 15 张表 | project, building, floor, room, city_config, water_temperature_config, season_config, room_load_parameter, room_load_result, room_air_volume_parameter, room_air_volume_result, room_load_summary, extra_load, load_summary, conversation_session |
| 四级层级 | project → building → floor → room |
| 聚合链路 | room_load_result / room_air_volume_result → room_load_summary → load_summary |

## 3. 全局约定

| 约定 | 取值 |
|------|------|
| 主键 | `BIGINT` 自增，`PRIMARY KEY` |
| 时间字段 | `DATETIME`，服务端写入，UTC 存储，API 返回 ISO-8601（`...Z`） |
| 数值精度 | 负荷/风量用 `DECIMAL(10,2)`~`DECIMAL(12,4)`；指标用 `DECIMAL(8,4)`；系数用 `DECIMAL(5,4)` |
| city_config 引用 | `REFERENCES city_config(id) ON DELETE RESTRICT` |
| 层级引用 | building→project / floor→building / room→floor 均为 `ON DELETE CASCADE` |

## 19. 待确认

1. **room 房间默认水温档**：API 总览 §6 以 `water_tier_id` 表达房间级水温档，但 §4.4 `room` 表无该列；§4.12 以 `room_load_summary.water_temp_config_id` 承担按水温分类。建议房间默认水温档由 `room_load_summary` 推导，或在 `room` 新增 `default_water_temp_config_id` 列——**待确认**。

5. **JSON 列索引**：`stage_status`/`draft_payload` 是否需 GIN 索引按阶段/字段查询——**待确认**。
6. **软删除**：schema 未含 `deleted_at`；如需审计/回收站，引入软删除为 v0.7 待确认项（模块-01 §10）。
