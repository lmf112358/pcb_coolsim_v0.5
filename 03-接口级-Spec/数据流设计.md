## 1. 概述

本文档描述 **API ↔ 状态（React Query / Context）↔ 组件** 的端到端数据流，覆盖从创建项目到导出报告的主链路，以及对话式采集分支。状态管理细节见 `状态管理.md`，组件接口见 `组件规范.md`，表结构见 `表结构详细设计.md`。

**统一原则**：
- 服务端数据唯一来源是 API；组件不直接改库，只触发 mutation。
- 所有写操作"保存即落库"（模块-02 §3.2），对话与 Tab1/Excel 共享同一数据集、互不覆盖。
- 计算（静态/动态）为异步任务，经 WebSocket 回流。

## 2. 主链路：创建项目 → 建层级 → 录入 → 计算 → 汇总 → 导出

### 2.1 时序（组件 → 状态 → API → 表）

```
[Map Home] 点击 +New Project
   | 弹窗表单（FormField）
   v
[State] AuthContext 注入 token；ProjectContext 准备
   | POST /api/v1/projects/  {project_name, city_id, location, description}
   v
[API] 建 project（city_id->CityConfig 取室外参数）
   | -> 默认建 WaterTempConfig(7/12,12/17)
   | -> 触发 Celery fetch_weather_data(project_id)
   v
[表] project 新增； WaterTempConfig 新增； (异步) weather 后续写入 TimescaleDB
   | 响应 201 -> 前端 invalidate ['projects']
   v
[组件] 进入 Workbench，TreeNav 显示 project 节点

[TreeNav] 右键 building->新增
   | POST /api/v1/buildings/  {project_id, building_name,...}
   v [表] building 新增 -> invalidate ['buildings',{project_id}]
[TreeNav] 展开 building->新增 floor
   | POST /api/v1/floors/  {building_id, floor_name}
   v [表] floor 新增
[TreeNav] 展开 floor->新增 room
   | POST /api/v1/rooms/  {floor_id, room_name, area, height, ...,
   |                        load_parameters, air_volume_parameters}
   v [表] room 新增 (volume=area*height 自动算)； Room 新增； Room 新增
   | invalidate ['rooms',{floor_id}], ['floors',{building_id}]
```

### 2.2 录入参数（实时预览）

```
[Tab1 表单] FormField 输入 civil_load_index 等
   | onChange -> 本地受控态（瞬时）
   | 防抖 500ms -> POST /api/v1/rooms/{id}/preview/  (或前端即时算)
   v
[State] ['room', id, 'preview'] 写入（staleTime 30s）
   v
[组件] 底部 Calculation Preview 面板刷新：terminal_load / fresh_air_load / total_load
[保存] PUT /api/v1/rooms/{id}/
   v [表] Room / Room UPSERT
   | invalidate ['room', id]
```

### 2.3 静态计算

```
[Tab1 计算按钮] POST /api/v1/rooms/{id}/calculate-static/
   | 单房间：同步 200 返回 steps + summary
   | 批量：POST /api/v1/projects/{id}/calculate-static/ -> 202 {task_id, ws_url}
   v
[API->引擎] 6 步流水线（模块-04 §2）：
   enthalpy -> terminal_load -> air_volume -> fresh_air_load -> total_load -> aggregate
   v
[表] RoomCalcResult 新增； RoomCalcResult 新增；
     RoomLoadByWaterTemp（按水温档 N 条）新增； LoadSummary（floor/building/project）新增
   v
[WS] progress/completed -> [State] invalidate
   ['calculations','static',pid], ['room',id,'load-result'], ['load-summary',pid]
[组件] Tab2 表格/图表/汇总卡刷新
```

### 2.4 动态仿真（8760h）

```
[Tab3 Run Simulation] POST /api/v1/projects/{id}/simulate/
   {simulation_type:'weather_driven', years:[...], building_ids?, room_ids?}
   v 202 {task_id, ws_url}
[Celery Worker] 逐时循环 8760h*N年*房间：
   室外焓(逐时) -> 新风负荷(随气象) + 末端负荷(固定) -> 总负荷 -> 聚合
   v
[表] TimescaleDB DynamicLoadHourly（chunk 写）；聚合结果落 DynamicLoadSummary
   v [WS] completed -> invalidate ['calculations','dynamic',pid]
[组件] Tab3 负荷曲线 / 持续曲线 / 统计刷新
```

### 2.5 负荷汇总与导出

```
[LoadSummary] 已由静态/动态计算聚合生成（scope: floor/building/project）
[Tab2/Tab5] GET /api/v1/calculations/static/{pid}/ 或 /dynamic/{pid}/
   v 展示分级汇总 + 按水温/建筑分布
[导出] POST /api/v1/exports/static-report/{pid}/  (或 equipment-list / simulation-data)
   v 202 {task_id} -> WS/轮询完成 -> GET /api/v1/exports/download/{task_id}/
```

## 3. 对话式采集分支（F2-001）

```
[Workbench 对话采集按钮] POST /api/v1/conversation/sessions/ {project_id}
   v 200 {session_id, current_stage:'s1_project', stage_status}
[State] ConversationContext: sessionId, currentStage, stageStatus, draftPayload
[阶段推进] POST /conversation/sessions/{id}/message/ {message}
   v 200 {stage, next_question, extracted}
   | -> 抽取结果写入对应实体（building/floor/room/ExtraLoad/WaterTempConfig）
[每阶段完成] PUT /conversation/sessions/{id}/draft/ {draft_payload}
   v [表] ConversationSession(stage_status, draft_payload) 新增；room.status='draft' 新增
[断点续采] 刷新 -> GET /conversation/sessions/{id}/ -> 回填 Context，从 current_stage 续
[⑥ 汇总确认] POST /conversation/sessions/{id}/finalize/
   v room.status: draft->active；会话标记完成；返回汇总预览
```

> 对话与 Tab1/Excel 为**同一数据集两种通道**：对话落库结构与 Excel 模板列一一对应，互不覆盖、可混合（模块-02 §3.4）。

## 4. 状态变迁（房间生命周期）

| 阶段 | room.status | 数据状态 | 触发 |
|------|-------------|----------|------|
| 创建 | draft（对话）或 active（Tab1 直接建） | room + 参数空/部分 | POST /rooms/ |
| 参数录入 | 不变 | Room/air_volume_parameter 填充 | PUT /rooms/{id} |
| 静态计算 | 不变 | RoomCalcResult / summary 生成 | calculate-static |
| 对话确认 | draft -> active | finalize | POST .../finalize/ |
| 动态仿真 | 不变 | TimescaleDB 逐时结果 | simulate |

---

## 5. 错误处理与回滚

| 环节 | 错误 | 处理 |
|------|------|------|
| 任何 API | 401 | AuthContext 用 refresh 重试；失败->登出 |
| 创建/更新 | 409 | 重复资源提示（如 UNIQUE 冲突） |
| 计算 | 422 CALCULATION_ERROR | 返回 field+message，回填表单/提示 |
| 批量/仿真 | WS error | 进度条转错误态，可重试任务 |
| 网络中断 | - | React Query 重试 + 乐观回滚 |

---

## 6. 关键数据流不变量

1. **project -> building -> floor -> room** 删除级联；计算结果随父级删除而删。
2. **聚合链路**：RoomCalcResult / RoomCalcResult -> RoomLoadByWaterTemp（按水温）-> LoadSummary（分级），任一上游重算须级联失效下游。
3. **CityConfig 只读**：project.city_id 引用，删除受限（RESTRICT）。
4. **对话/表单/Excel 三通道同写一份数据**，以 `ConversationSession` 与 `room.status` 协调草稿态。
