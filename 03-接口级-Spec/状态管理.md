## 1. 概述

前端状态分两层（系统架构设计 §2.1 / §1.2 Client Layer）：

- **服务端状态（Server State）**：项目/建筑/楼层/房间/计算结果等，由 **React Query v5** 管理（缓存、失效、后台刷新、分页）。
- **客户端状态（Client State）**：登录态、主题、语言、当前选中节点、对话会话草稿等，由 **React Context** 管理。

本文档规定 React Query 使用规范、Context 划分、状态更新流程、缓存策略与服务端同步方式。组件不应直接持有服务端数据副本，统一经 React Query 获取。

## 2. React Query 使用规范

### 2.1 Query 键命名（snake_case 资源 + 参数对象）

统一约定：`['{resource}', ...params]`，参数对象保持字典序，便于失效匹配。

```typescript
// 列表（含层级过滤）
['projects', { page, page_size, search, status }]
['buildings', { project_id }]
['floors', { building_id }]
['rooms', { floor_id, search }]
['calculations', 'static', project_id, { building_id?, water_tier_id? }]
['calculations', 'dynamic', project_id, { room_id?, year?, month?, aggregation? }]
['weather', { city_id }]
['conversation', 'session', session_id]

// 详情
['project', id]
['room', id]
['room', id, 'load-result']
['room', id, 'air-volume-result']
```

### 2.2 查询 / 变更

```typescript
// 查询：房间列表
const { data, isLoading, isError } = useQuery({
  queryKey: ['rooms', { floor_id }],
  queryFn: () => api.get('/api/v1/rooms/?floor=' + floor_id),
  staleTime: 30_000,         // 与架构 §7.2 API Redis TTL 30s 对齐
  keepPreviousData: true,    // 分页/过滤时不闪烁
});

// 变更：创建房间（乐观更新 + 失效）
const mutation = useMutation({
  mutationFn: (payload) => api.post('/api/v1/rooms/', payload),
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ['rooms', { floor_id }] });
    queryClient.invalidateQueries({ queryKey: ['floors', { building_id }] }); // 刷新 room_count
  },
});
```

### 2.3 失效策略（Invalidation）

| 操作 | 失效键 |
|------|--------|
| 创建/更新/删除 room | `['rooms', {floor_id}]`、`['floors',{building_id}]`、`['project', id]`（计数） |
| 录入 load/air_volume 参数 | `['room', id]`、`['room', id, 'load-result']` |
| 静态计算完成 | `['calculations','static',project_id]`、`['room',id,'load-result']`、`['load-summary', project_id]` |
| 动态仿真完成（WS） | `['calculations','dynamic',project_id]` |
| 更新 water_temperature_config | `['room', id, 'load-result']`、`['calculations','static',project_id]`（水温影响汇总） |
| 对话 finalize | `['rooms',...]`、`['extra_load',...]`、`['conversation','session',id]` |

## 3. Context 状态管理

| Context | 职责 | 状态片段 |
|---------|------|----------|
| `AuthContext` | JWT 登录态、用户、角色、刷新（F1-001） | `accessToken`, `refreshToken`, `user`, `role`, `login()`, `logout()`, `refresh()` |
| `ThemeContext` | 暗/浅主题（F1-007） | `theme`, `toggleTheme()`；持久化 localStorage |
| `LocaleContext` | 中/英切换（F1-008） | `locale`, `t(key)`；i18n |
| `ProjectContext` | 当前项目、四级选中节点、Tab 切换 | `currentProjectId`, `selectedNode {type,id}`, `activeTab` |
| `ConversationContext` | 对话采集会话（F2-001 分支） | `sessionId`, `currentStage`, `stageStatus`, `draftPayload` |

**划分原则**：服务端数据（房间列表、计算结果）**不进 Context**，只进 React Query；Context 仅放真正全局、非服务端派生的 UI/身份状态。

## 4. 状态更新流程

### 4.1 录入参数 → 实时预览

1. 用户在 FormField 输入 → `onChange` 更新本地受控态（瞬时，不请求）。
2. 防抖 500ms（设计系统 §5.3 / 架构 §4.2）→ `POST /api/v1/rooms/{id}/preview/` 或前端轻量计算。
3. 预览结果写入 `['room', id, 'preview']`（短 staleTime），底部预览面板刷新；不落库。
4. 用户点「保存」→ `PUT /api/v1/rooms/{id}/` → 失效 `['room', id]` 与列表。

### 4.2 计算触发 → 结果回流

1. 点「计算」→ `POST /api/v1/rooms/{id}/calculate-static/` 或批量 `POST /api/v1/project/{id}/calculate-static/`（返回 task_id + ws url）。
2. 批量任务：前端订阅 `ws://.../ws/tasks/{task_id}/`，按 `progress`/`completed` 消息更新进度条。
3. `completed` → 失效 `['calculations','static',project_id]`、`['room',id,'load-result']`、`['load-summary',project_id]`。
4. 组件重新拉取，展示结果（Tab2 表格/图表）。

### 4.3 对话采集 → 草稿持久化

1. `ConversationContext` 维护 `currentStage` / `stageStatus` / `draftPayload`。
2. 每阶段完成 `PUT /conversation/sessions/{id}/draft/` → 服务端持久化（断点续采）。
3. 刷新/重开 → `GET /conversation/sessions/{id}/` 回填 Context，从 `current_stage` 续采。
4. `finalize` → room 草稿 `status` 由 draft 转 active，失效 `['rooms',...]`。

## 5. 缓存策略

| 层 | 策略 | 值 | 失效 |
|----|------|----|------|
| 浏览器 React Query | staleTime | 列表 30s、详情 30s、预览 30s（对齐 Redis） | 写操作后 invalidate |
| React Query gcTime | 5 min 未用回收 | 默认 |
| API（服务端 Redis） | TTL | 30s（架构 §7.2） | On Update |
| 计算缓存 | `preview:{room_id}:{params_hash}` | 30s（模块-04 §4.2） | 参数变更即 miss |
| 登录态 | accessToken 内存 + refreshToken | access 15min / refresh 7d | 401 自动 refresh |

**并发/竞态**：同一 room 参数编辑与计算并发时，以 `invalidateQueries` 保证最终一致；乐观更新仅用于列表计数类轻量变更，计算类以服务端返回为准。

---

## 6. 与服务端数据同步

- **拉取**：所有列表/详情经 React Query，失败按 API 错误码处理（401→refresh 或登出；409→冲突提示；422→校验错误回填表单）。
- **推送**：长任务（批量计算/动态仿真/气象拉取）经 WebSocket（架构 §5.1 `/ws/tasks/{task_id}/`），前端据消息更新进度并失效查询。
- **离线恢复**：对话草稿已落库（`conversation_session`），刷新不丢；表单自动保存 30s（设计系统 §8.5）建议走 `PUT /rooms/{id}/` 防抖保存（待确认是否独立 autosave 端点）。
- **数据隔离**：所有请求带 `project_id` 维度；React Query 键含 `project_id`，天然隔离跨项目缓存。

## 7. 待确认

1. **表单自动保存端点**：设计系统 §8.5 的 30s 自动保存是否复用 `PUT /api/v1/rooms/{id}/`，或新增轻量 `PATCH` 端点——**待确认**。
2. **预览计算位置**：实时预览由后端 `/preview/` 还是前端直接计算（架构 §4.2 指向 `/preview/`；前端亦可依模块-04 公式本地算以降延迟）——**待确认**。
3. **ConversationContext 与 React Query 边界**：`draft_payload` 是否完全由 Context 持有、仅在 save 时落库，还是每次输入即走 React Query `useMutation`——倾向 Context 持有 + 显式 save（符合"保存即落库"语义）。
