## 1. 概述

动态仿真在「逐时气象驱动」下，对每房间每小时 t 计算负荷，输出全年（8760h × N 年）负荷序列。**逐时数据统一存于 `DynamicLoadHourly`（TimescaleDB 超表）**，聚合统计存于 `DynamicLoadSummary`。已删除 `DynamicLoadHourly`/`DynamicLoadSummary` 旧表名歧义。

**核心桥梁（PRD §8.1）**：末端负荷 `Q_terminal` 由静态计算一次生成（写入 `RoomCalcResult`），动态仿真直接复用：
- `Q_dynamic(t) = Q_terminal + Q_fresh_air(t)`（约 26280 个逐时值）

### 1.1 端点总览（附录D 权威清单）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/calc/dynamic/{projectId}` | 启动动态仿真（异步 Celery，202 + task_id） |
| GET | `/api/v1/calc/dynamic/{projectId}/hourly` | 获取逐时数据（8760h × N 年） |
| GET | `/api/v1/calc/dynamic/{projectId}/summary` | 获取极值统计（max/min/avg/total_energy） |
| GET | `/api/v1/calc/results/{projectId}` | 静态结果查询（见计算接口.md §4） |

> 实时预览 `/api/v1/calculations/preview` 见计算接口.md §3。

## 3. POST /api/v1/calc/dynamic/{projectId}

启动动态仿真（异步 Celery）。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| mode | enum | 是 | `weather_driven` / `ratio_coefficient` |
| years | array[int] | 是 | 仿真年份，1~3 年（如 [2023,2024,2025]，约 26280h） |
| start_date | string(date) | 否 | 起始日期 YYYY-MM-DD |
| building_ids | array[int] | 否 | 限定范围 |
| room_ids | array[int] | 否 | 限定范围（null=全部） |

```json
{
  "mode": "weather_driven",
  "years": [2023, 2024, 2025],
  "start_date": "2023-01-01",
  "building_ids": null,
  "room_ids": null
}
```

**响应 202**（异步）

```json
{
  "success": true,
  "data": {
    "task_id": "sim-dynamic-20260714-001",
    "status": "processing",
    "message": "Dynamic simulation started (8760h × 3 years × 135 rooms)",
    "estimated_time_seconds": 25,
    "websocket_url": "ws://localhost:8000/ws/tasks/sim-dynamic-20260714-001"
  }
}
```

**计算链路**

**方式一 weather_driven（F6-001~F6-003）**：
```
for each year, for each hour t (0..8759):
  1. 读 WeatherRecord 当前小时的室外干湿球/大气压（F6-001）
  2. h_outdoor(t) = psychrolib(temp, humidity, pressure)  （F6-002）
  3. h_indoor = const（取 Room.indoor_calc_temp/humidity，F6-003）
  4. 逐房间：
     Q_fresh_air(t) = V_fresh_air × ρ × (h_outdoor - h_indoor) / 3600
     Q_terminal = const（从 RoomCalcResult.terminal_load 复用，桥梁）
  5. Q_dynamic(t) = Q_terminal + Q_fresh_air(t)；若 <0 截断为 0（F6-006）
  6. 写入 DynamicLoadHourly（逐时）；聚合写 DynamicLoadSummary
```

**方式二 ratio_coefficient（F6-008, ADR-0003）**：
```
for each hour t:
  1. 读室外温度 T(t)（来自 WeatherRecord）
  2. k(t) = 查统一比例系数表（ADR-0003），取负荷率=100% 列
  3. Q_dynamic(t) = Q_terminal_design × k(t)
     （Q_terminal_design 来自静态 RoomCalcResult；线性插值）
```

**前置校验**：
- 项目须具备对应年份的 `WeatherRecord` 数据，否则 `422 WEATHER_DATA_MISSING`。
- 须先完成静态计算（`RoomCalcResult.terminal_load` 存在），否则 `422 CALCULATION_ERROR`。

**写入映射（PascalCase 表名）**

| 数据 | 写入表 | 关键字段 |
|------|--------|---------|
| 逐时负荷（8760h × N年 × 房间） | `DynamicLoadHourly`（TimescaleDB 超表） | timestamp, project_id, room_id, calc_batch_id, outdoor_temp, outdoor_humidity, outdoor_enthalpy, terminal_load, fresh_air_load, total_load |
| 极值统计（max/min/avg/total_energy） | `DynamicLoadSummary` | project_id, room_id, calc_batch_id, max_load_kw, max_load_timestamp, min_load_kw, avg_load_kw, total_energy_kwh |

**错误码**：`404 RESOURCE_NOT_FOUND`（项目不存在）、`422 WEATHER_DATA_MISSING`、`422 CALCULATION_ERROR`（房间缺静态结果或参数）、`403 INSUFFICIENT_PERMISSIONS`。

## 4. GET /api/v1/calc/dynamic/{projectId}/hourly

获取逐时负荷数据（用于负荷曲线、持续曲线展示）。

**查询参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| room_id | int | 否 | 指定房间；省略=项目级聚合 |
| building_id | int | 否 | 指定建筑 |
| floor_id | int | 否 | 指定楼层 |
| year | int | 否 | 指定年份 |
| start | datetime | 否 | ISO-8601 起始时间 |
| end | datetime | 否 | ISO-8601 结束时间 |
| aggregation | enum | 否 | `hourly`（默认）/ `daily` / `monthly` |

**响应 200**

```json
{
  "success": true,
  "data": {
    "project_id": 1,
    "mode": "weather_driven",
    "calc_batch_id": "batch-20260714-001",
    "aggregation": "hourly",
    "series": [
      {
        "room_id": 1,
        "room_name": "内层曝光区",
        "points": [
          { "timestamp": "2023-01-01T00:00:00Z", "outdoor_temp": 5.20, "outdoor_humidity": 75.00, "outdoor_enthalpy": 14.50, "terminal_load_kw": 113.30, "fresh_air_load_kw": 7.20, "total_load_kw": 120.50 },
          { "timestamp": "2023-01-01T01:00:00Z", "outdoor_temp": 4.80, "outdoor_humidity": 77.00, "outdoor_enthalpy": 13.80, "terminal_load_kw": 113.30, "fresh_air_load_kw": 6.50, "total_load_kw": 119.80 }
        ]
      }
    ],
    "total_points": 26280
  }
}
```

**数据来源**：`DynamicLoadHourly` 表（TimescaleDB hypertable，按 timestamp range + project_id 分区）。`aggregation=daily/monthly` 由查询层实时下采样（或 LTTB 降采样，NF）。

**性能**：单房间单年查询走 `(timestamp, project_id, calc_batch_id)` 复合索引（见索引设计.md），剪枝到相关 chunk，毫秒级；前端按需分块加载 26280 点。

**错误码**：`404 RESOURCE_NOT_FOUND`（项目无仿真结果）、`403 INSUFFICIENT_PERMISSIONS`。

## 5. GET /api/v1/calc/dynamic/{projectId}/summary

获取极值统计（用于报表、设备选型参考）。

**查询参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| room_id | int | 否 | 指定房间；省略=项目级 |
| building_id | int | 否 | 指定建筑 |
| year | int | 否 | 指定年份 |

**响应 200**

```json
{
  "success": true,
  "data": {
    "project_id": 1,
    "mode": "weather_driven",
    "calc_batch_id": "batch-20260714-001",
    "years_simulated": 3,
    "summary": {
      "max_load_kw": 18000.50,
      "max_load_timestamp": "2024-07-15T14:00:00Z",
      "min_load_kw": 2000.30,
      "min_load_timestamp": "2024-01-20T06:00:00Z",
      "avg_load_kw": 8500.20,
      "total_energy_kwh": 223260000,
      "truncated_hours": 120
    },
    "by_room": [
      { "room_id": 1, "room_name": "内层曝光区", "max_load_kw": 250.50, "min_load_kw": 50.20, "avg_load_kw": 150.30, "total_energy_kwh": 1318000 }
    ]
  }
}
```

> 极值规则（PRD §8.1）：`min_load_kw` 取 `Q > 0` 的有意义最小值；`truncated_hours` 为总负荷<0 被截断为 0 的小时数。

**数据来源**：`DynamicLoadSummary` 表（由仿真任务聚合写入，非实时重算）。

**错误码**：`404 RESOURCE_NOT_FOUND`、`403 INSUFFICIENT_PERMISSIONS`。

## 6. 进度获取（WebSocket / 轮询）

- 仿真为异步 Celery 任务；进度通过 `websocket_url` 订阅：`progress` / `completed` / `error` 三类消息，`completed` 携带 `result_url` 指回本组查询端点。
- 若无 WebSocket 通道，前端可周期性调用 `/summary` 端点轮询（待任务完成态由后端标记后返回数据）。

---

## 7. 待确认 / 开放问题

- **O-1 ratio_coefficient 模式的系数精度**：ADR-0003 统一系数表值待暖通校准（C10）；>35℃/100% 列当前为 1.2。
- **O-2 aggregation 实时聚合 vs 预存**：daily/monthly 下采样由查询层实时算还是预存到 `DynamicLoadSummary`，取决于查询性能——**当前基线：实时聚合，配合 TimescaleDB continuous aggregate 加速。**
- **O-3 calc_batch_id 复用语义**：每次仿真生成新 batch_id，历史结果是否保留（供版本对比）待确认。
