> 版本：1.0
> 日期：2026-07-13
> 状态：已完成
> PRD 引用：F6-001（连续 3 年逐时气象约 26280 条）、F6-002（逐时室外焓值 psychrolib）、F6-003（室内焓值全年恒定）、SAC-3（方式一与独立脚本偏差 < 1%）
> 依赖文档：01-系统级-Spec/API总览.md（§7.4~§7.5）、02-模块级-Spec/模块-06-动态仿真负荷计算.md、01-系统级-Spec/数据库设计.md（room_air_volume_result / room_load_result / load_summary / city_config / season_config）

---

## 1. 概述

动态仿真在「逐时气象驱动」下，对每房间每小时 t 计算负荷，输出全年（8760h × N 年）负荷序列。本文件覆盖 2 个端点：仿真启动（异步 Celery）与结果查询。进度通过 WebSocket（API总览 §11）或轮询获取。

---

## 2. 端点总览

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/projects/{id}/simulate/` | 启动动态仿真（异步，202 + task_id） |
| GET | `/api/v1/calculations/dynamic/{project_id}/` | 仿真结果查询（hourly/daily/monthly 聚合） |

---

## 3. 启动仿真 POST /api/v1/projects/{id}/simulate/

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| simulation_type | enum | 是 | `weather_driven`（方式一）/ `coefficient`（方式二） |
| years | array[int] | 是 | 仿真年份，1~3 年（如 [2023,2024,2025]，约 26280h） |
| start_date | string(date) | 否 | 起始日期 YYYY-MM-DD |
| building_ids | array[int] | 否 | 限定范围 |
| room_ids | array[int] | 否 | 限定范围（null=全部） |

```json
{
  "simulation_type": "weather_driven",
  "years": 3,
  "start_date": "2023-01-01",
  "building_ids": null,
  "room_ids": null
}
```

**响应 202**（异步）：

```json
{
  "success": true,
  "data": {
    "task_id": "sim-dynamic-20260709-001",
    "status": "processing",
    "message": "Dynamic simulation started (8760h × 3 years × 135 rooms)",
    "estimated_time_seconds": 25,
    "websocket_url": "ws://localhost:8000/ws/tasks/sim-dynamic-20260709-001/"
  }
}
```

**计算链路（方式一 weather_driven，对齐 F6-001~F6-003）**

```
for each year, for each hour t (0..8759):
  1. 读取 city_config 当前季节室外温湿度 + 大气压       # F6-001 气象
  2. h_outdoor(t) = psychrolib(date, temp, humidity, pressure)  # F6-002
  3. h_indoor = const（取房间 indoor_calc_temp/humidity）        # F6-003 恒定
  4. 逐房间：新风量(room_air_volume_result.fresh_air_volume)
             × 焓差(h_outdoor - h_indoor) → 新风冷负荷
             末端负荷(room_load_result.terminal_load) 恒定（设计日）
  5. total_load(t,room) = fresh_air_load(t) + terminal_load
  6. 聚合 → load_summary（8760h 投影）
```

**前置校验**：项目须具备对应年份气象数据（`weather_data_status=available`），否则 `422 WEATHER_DATA_MISSING`。

**错误码**：`404 RESOURCE_NOT_FOUND`（项目不存在）、`422 WEATHER_DATA_MISSING`、`422 CALCULATION_ERROR`（房间缺参数）、`403 INSUFFICIENT_PERMISSIONS`。

## 4. 结果查询 GET /api/v1/calculations/dynamic/{project_id}/

**查询参数**：`room_id`(int)、`year`(int)、`month`(int)、`aggregation`(enum: hourly|daily|monthly)。

**响应 200**（同 API总览 §7.5）：

```json
{
  "success": true,
  "data": {
    "project_id": 1,
    "simulation_type": "weather_driven",
    "simulation_date": "2026-07-09T14:00:00Z",
    "years_simulated": 3,
    "summary": {
      "max_load_kw": 18000.50, "max_load_datetime": "2024-07-15T14:00:00Z",
      "min_load_kw": 2000.30, "min_load_datetime": "2024-01-20T06:00:00Z",
      "avg_load_kw": 8500.20, "total_energy_kwh": 223260000
    },
    "room_results": [
      {
        "room_id": 1, "room_name": "内层曝光区",
        "max_load_kw": 250.50, "min_load_kw": 50.20, "avg_load_kw": 150.30,
        "hourly_data": [
          { "datetime": "2023-01-01T00:00:00Z", "outdoor_temp": 5.20, "outdoor_humidity": 75.00, "load_kw": 120.50 }
        ]
      }
    ]
  }
}
```

**数据来源与 8760h 存储说明**

- `summary`（max/min/avg/total_energy）与按房间聚合值来自 `load_summary`（scope=project/building/floor，category 含 新风负荷/末端负荷/合计），由仿真任务写入。
- `room_results[].hourly_data` 为逐时序列（每房间每年 8760 点）。**15 表锚点中未定义独立的「仿真逐时结果表」**（模块-06 提到的 `simulation_result` / `simulation_summary` 不在锚点 15 表内）。逐时序列的持久化目标实体**待确认**（见 §6 O-1），本接口仅定义对外查询契约，不擅自新增表。

---

## 5. 进度获取（WebSocket / 轮询）

- 仿真为异步 Celery 任务；进度通过 `websocket_url` 订阅（API总览 §11）：`progress` / `completed` / `error` 三类消息，`completed` 携带 `result_url` 指回本查询端点。
- 若无 WebSocket 通道，前端可周期性调用本 GET 端点（待任务完成态由后端标记后返回数据）。

---

## 6. 待确认 / 开放问题

- **O-1 逐时 8760h 数据持久化实体**：锚点 15 表未含仿真逐时结果表。候选：① 复用 `load_summary`（仅存聚合，丢逐时）；② 新增表（违反奥卡姆剃刀，需评审）；③ 落对象存储/列式文件按 room 索引。需在数据库设计层面定稿后再实现查询层。
- **O-2 coefficient 方式（方式二）系数来源**：`coefficient` 模式以静态负荷乘系数，系数表/默认值来源待确认（PRD 提及生产负荷率，v0.5.1 范围外）。
- **O-3 aggregation 聚合实现**：hourly/daily/monthly 由查询层实时聚合还是预存，待确认（影响存储与查询性能）。
