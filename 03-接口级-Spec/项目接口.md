## 1. 概述

项目（project）是系统的顶层组织实体，承载「项目 → 建筑 → 楼层 → 房间」四级层级（SAC-1）的第一级。本文件覆盖项目资源的 6 个端点：列表、创建、详情、更新、删除、汇总。

创建项目时的关键副作用（见模块-01 §4.2）：
1. 关联城市 `city_id`（FK → `city_config`），自动读取该城市国标室外设计参数供展示与计算使用。
2. 自动生成 2 条默认冷冻水温度配置（`water_temperature_config`：低温 7/12℃、中温 12/17℃）。
3. 触发 Celery 异步任务 `fetch_weather_data(project_id)` 拉取气象数据。

> 注：F1-003（登录页左右分栏）属 UI 需求、F1-004（token 续期）属认证切面，此处仅作关联引用，实质实现见「认证接口.md」。

## 2. 端点总览

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/projects/` | 项目列表（分页/搜索/状态过滤） |
| POST | `/api/v1/projects/` | 创建项目（含城市关联与副作用） |
| GET | `/api/v1/projects/{id}/` | 项目详情（含建筑列表、天气态、计算态） |
| PUT | `/api/v1/projects/{id}/` | 更新项目 |
| DELETE | `/api/v1/projects/{id}/` | 删除项目（级联删除下属建筑/楼层/房间） |
| GET | `/api/v1/projects/{id}/summary/` | 项目负荷汇总（聚合口径见 §6） |

## 3. 字段与数据库映射（project 表）

| API 字段 | DB 字段 | 类型 | 必填 | 说明 |
|----------|---------|------|------|------|
| project_name | project.project_name | string(200) | 是 | 项目名称 |
| project_code | project.project_code | string(50) | 否 | 项目编号 |
| city_id | project.city_id → city_config.id | integer | 是 | 关联城市（必填，计算链路前提） |
| location | project.location | string(200) | 否 | 详细地址，仅展示 |
| description | project.description | string(500) | 否 | 描述 |
| — | project.created_at / updated_at | datetime | — | 系统维护 |

- `city` 展开对象（GET 响应）字段来源于 `city_config`：`city_name`、`province`、`outdoor_temp_summer`、`outdoor_humidity_summer`（由 `temp_dry_ac_summer` / `temp_wet_ac_summer` 映射，只读）。
- `water_temperature_configs` 展开对象：`id`、`name`、`supply_temp`、`return_temp`，来源于 `water_temperature_config` 表。

## 4. 端点详细设计

### 4.1 GET /api/v1/projects/

**查询参数**：`page`(int,默认1)、`page_size`(int,默认20,最大100)、`search`(string,按 name/code 模糊)、`status`(enum: active|archived)。

**响应 200**：`data.items[]` 含 `id, project_name, project_code, city{id,city_name,province}, location, building_count, total_cooling_load, status, created_at, updated_at`；`data.pagination{page,page_size,total,total_pages}`。

### 4.2 POST /api/v1/projects/

**请求体**

| 字段 | 必填 | 校验规则 |
|------|------|----------|
| project_name | 是 | 非空，≤200 |
| city_id | 是 | 必须存在于 city_config（否则 404 RESOURCE_NOT_FOUND） |
| location | 否 | ≤200 |
| project_code | 否 | 若提供应唯一（见 O-1） |
| description | 否 | ≤500 |

```json
{
  "project_name": "深圳宝安 PCB 工厂",
  "project_code": "SZ-BA-2026-001",
  "city_id": 2,
  "location": "宝安区XX街道XX号",
  "description": "大型PCB制造工厂"
}
```

**响应 201**：返回创建后的项目（含自动生成的 `water_temperature_configs` 两条、关联 `city` 对象、`created_at`）。

**副作用**（服务端同步+异步）：
- 同步：写入 `project` 记录 + 2 条 `water_temperature_config`。
- 异步：派发 Celery 任务拉取天气（任务 ID 可通过天气接口/WebSocket 跟踪，不在本项目响应内返回）。

**错误码**：`400 VALIDATION_ERROR`（缺必填）、`404 RESOURCE_NOT_FOUND`（city_id 不存在）、`409 DUPLICATE_RESOURCE`（project_code 冲突，若启用唯一约束，见 O-1）。

### 4.3 GET /api/v1/projects/{id}/

**响应 200**：详情含 `buildings[]`（id, building_name, floor_count, room_count）、`weather_data_status`(available/pending/missing)、`last_static_calculation`(datetime|null)、`water_temperature_configs` 等。

**错误码**：`404 RESOURCE_NOT_FOUND`（id 不存在或无权限）。

### 4.4 PUT /api/v1/projects/{id}/

**请求体**：同创建（全部可选，部分更新）。`city_id` 通常不可变更（变更影响气象与计算，见 O-2）。

**响应 200**：同详情结构。

### 4.5 DELETE /api/v1/projects/{id}/

**响应 204**：No Content。级联删除下属 `building → floor → room` 及其负荷/风量/汇总记录（依据数据库设计 §5 外键链）。

**错误码**：`404 RESOURCE_NOT_FOUND`、`403 INSUFFICIENT_PERMISSIONS`（非项目成员/非 PM）。

### 4.6 GET /api/v1/projects/{id}/summary/

**响应 200**（聚合口径见 §6）。

## 5. 鉴权与数据隔离

- 所有端点需 `Authorization: Bearer {access_token}`。
- 项目级数据隔离（F1-026）：仅 `ProjectMember` 关联用户可见；列表返回当前用户有权限的项目。
- 越权访问返回 `403 INSUFFICIENT_PERMISSIONS`。

## 6. 四级层级与 Summary 聚合口径

### 6.1 四级层级（SAC-1）

```
project (1) ──< building (N) ──< floor (N) ──< room (N)
                └─ water_temperature_config (N)
                └─ extra_load (N, building_id 可空)
```

### 6.2 Summary 聚合口径（GET /projects/{id}/summary/）

| 响应字段 | 来源 / 口径 |
|----------|-------------|
| total_buildings | count(building where project_id) |
| total_floors | count(floor where building.project_id) |
| total_rooms | count(room where floor.building.project_id) |
| cooling_load_summary.total_load_kw | sum(load_summary.total_load where scope='project' and project_id) |
| by_water_temperature.low_temp_7_12 / mid_temp_12_17 | 按 water_temp_config 分组的负荷合计（对应 `load_summary.water_temp_config_id`） |
| by_building[] | 逐建筑负荷合计（scope='building'） |
| simulation_status | 最近一次动态仿真状态（pending/processing/completed/failed，参考仿真接口） |
| last_simulation_date | 最近仿真完成时间 |

> 聚合数据来自 `load_summary` 表（scope ∈ {floor, building, project}），由计算/仿真任务写入，非实时重算。

## 7. 相关接口（见 API总览 §8 天气 / §10 设置）

- 天气：GET `/api/v1/weather/?city={city_id}`、POST `/api/v1/weather/fetch/`、POST `/api/v1/weather/upload/` —— 项目创建后由系统自动触发 fetch，亦支持手动补数据。
- 设置：GET `/api/v1/settings/water-temperature/?project={project_id}`（查默认水温配置）、PUT `/api/v1/settings/water-temperature/{id}/`（改供水/回水温度）、GET `/api/v1/settings/defaults/`（系统/项目默认参数）。

## 8. 待确认 / 开放问题

- **O-1 project_code 唯一性**：`project` 表定义中 `project_code` 为可空非唯一；但 API总览 §1.3 含 `409 DUPLICATE_RESOURCE`。是否对 `project_code` 加唯一约束需确认。
- **O-2 city_id 可变性与天气重拉**：创建后修改 `city_id` 是否触发气象与既有计算重算，待确认（建议锁定或软告警）。
- **O-3 级联删除确认弹窗/软删除**：DELETE 为硬删除级联，是否提供软删除（is_deleted）待确认。
