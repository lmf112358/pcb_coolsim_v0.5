> 依赖文档：03-接口级-Spec/表结构详细设计.md（WaterTempConfig / DefaultConfig / RoomTemplate / ExtraLoad）、02-模块级-Spec/模块-09-系统设置与全局交互.md

## 1. 概述

本文件统一定义项目级/系统级配置类数据的 CRUD 端点，覆盖：冷冻水温度配置、默认值四级继承配置、功能区域模板、额外负荷。城市查询（`/api/v1/cities`）已在 `项目接口.md` §6 定义，本文件不重复。

**命名基线**：表名 PascalCase（WaterTempConfig / DefaultConfig / RoomTemplate / ExtraLoad）；字段 snake_case；路径 `/api/v1/`。

---

## 2. 冷冻水温度配置（WaterTempConfig）

项目级冷冻水温度档 CRUD（PRD F9-001~F9-005、§13.1）。项目创建时自动预置低温 7/12°C、中温 12/17°C（F1-018）。

### 2.1 端点总览

| 方法 | 路径 | 说明 | PRD |
|------|------|------|-----|
| GET | `/api/v1/projects/{projectId}/water-temp-configs` | 配置列表 | F9-001 |
| POST | `/api/v1/projects/{projectId}/water-temp-configs` | 新增配置 | F9-002 |
| GET | `/api/v1/water-temp-configs/{id}` | 配置详情 | F9-003 |
| PUT | `/api/v1/water-temp-configs/{id}` | 更新配置 | F9-002 |
| DELETE | `/api/v1/water-temp-configs/{id}` | 删除配置 | F9-002 |

### 2.2 数据模型（WaterTempConfig）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT | - | 主键 |
| project_id | BIGINT FK | 是 | 关联 Project |
| temp_type_name | VARCHAR(50) | 是 | 配置名称（如"低温冷冻水""中温冷冻水"） |
| supply_temp | DECIMAL(5,2) | 是 | 供水温度（°C） |
| return_temp | DECIMAL(5,2) | 是 | 回水温度（°C） |
| description | VARCHAR(200) | 否 | 备注 |

### 2.3 请求/响应示例

**POST `/api/v1/projects/{projectId}/water-temp-configs`**

请求体：
```json
{
  "temp_type_name": "低温冷冻水",
  "supply_temp": 7,
  "return_temp": 12,
  "description": "常规洁净室"
}
```

响应 `201 Created`：
```json
{
  "id": 101,
  "project_id": 1,
  "temp_type_name": "低温冷冻水",
  "supply_temp": 7.00,
  "return_temp": 12.00,
  "description": "常规洁净室"
}
```

**错误码**：`400 Bad Request`（必填缺失/温度范围异常 -50~60°C 外）、`404 Not Found`（项目不存在）、`409 Conflict`（同名配置已存在）。

### 2.4 校验规则

- `supply_temp < return_temp`（供水应低于回水）
- 同一项目内 `temp_type_name` 唯一
- 删除前检查：若该配置被 Room（`terminal_water_temp_config_id` / `fresh_air_water_temp_config_id`）或 ExtraLoad 引用，提示受影响的功能区域数量并二次确认（F2-020）

## 3. 默认值配置（DefaultConfig）

系统级/项目级/建筑级/楼层级四级覆盖（PRD F2-040~F2-045、F9-006~F9-010、§13.2）。承载压差渗透系数表、空气密度 ρ、室内温湿度默认、土建/照明/人员指标默认等。

### 3.1 端点总览

| 方法 | 路径 | 说明 | PRD |
|------|------|------|-----|
| GET | `/api/v1/defaults` | 查询默认值（支持 scope/project_id/building_id/floor_id 筛选） | F9-006 |
| PUT | `/api/v1/defaults` | 更新默认值（批量） | F9-008 |
| GET | `/api/v1/defaults/effective?room_id={id}` | 查询某 Room 的有效默认值（四级继承解析） | F2-019/F2-044 |

### 3.2 数据模型（DefaultConfig）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT | - | 主键 |
| scope | VARCHAR(20) | 是 | 层级：system / project / building / floor |
| project_id | BIGINT FK | 否 | scope=project/building/floor 时关联 |
| building_id | BIGINT FK | 否 | scope=building/floor 时关联 |
| floor_id | BIGINT FK | 否 | scope=floor 时关联 |
| params | JSON | 是 | 配置参数键值对（见 §3.3） |

### 3.3 params JSON 结构

```json
{
  "civil_load_index": 30,              // 土建指标 W/m²
  "lighting_load_index": 15,           // 照明指标 W/m²
  "personnel_load_index": 60,          // 人员指标 W/人
  "indoor_calc_temp": 26,              // 室内计算温度 °C
  "indoor_calc_humidity": 55,          // 室内计算相对湿度 %
  "air_density": 1.2,                  // 空气密度 kg/m³（PRD §15.3）
  "terminal_water_temp_default": "mid",// 末端冷冻水档默认（mid 中温 / low 低温，ADR-0001）
  "infiltration_coeff_table": [        // 压差渗透系数表（PRD §8.3 八点，唯一权威）
    {"pressure_diff": 0, "k": 0.0},
    {"pressure_diff": 1, "k": 1.0},
    {"pressure_diff": 2, "k": 1.5},
    {"pressure_diff": 3, "k": 2.0},
    {"pressure_diff": 5, "k": 3.0},
    {"pressure_diff": 10, "k": 3.5},
    {"pressure_diff": 15, "k": 4.0}
  ]
}
```

### 3.4 四级继承优先级（F2-041/F9-009）

```
功能区域显式值 > 楼层级覆盖 > 建筑级覆盖 > 项目级覆盖 > 系统默认值
```

`GET /api/v1/defaults/effective?room_id={id}` 返回该 Room 解析后的有效配置（逐字段标注来源层级）。

**响应示例**：
```json
{
  "room_id": 101,
  "effective": {
    "civil_load_index": {"value": 35, "source": "building"},
    "lighting_load_index": {"value": 15, "source": "system"},
    "air_density": {"value": 1.2, "source": "system"}
  }
}
```

### 3.5 错误码

`400 Bad Request`（scope 与关联 ID 不匹配，如 scope=floor 但 floor_id 为空）、`403 Forbidden`（非管理员改系统级配置）。

## 4. 功能区域模板（RoomTemplate）

功能区域参数模板，含系统内置 PCB 典型工艺模板（PRD F2-026、附录 B）+ 用户自定义模板。

### 4.1 端点总览

| 方法 | 路径 | 说明 | PRD |
|------|------|------|-----|
| GET | `/api/v1/room-templates` | 模板列表（支持 scope=system/custom 筛选） | F2-026 |
| GET | `/api/v1/room-templates/{id}` | 模板详情 | F2-025 |
| POST | `/api/v1/room-templates` | 另存为模板（用户自定义） | F2-024 |
| PUT | `/api/v1/room-templates/{id}` | 更新自定义模板 | F2-024 |
| DELETE | `/api/v1/room-templates/{id}` | 删除自定义模板（系统内置不可删） | F2-024 |

### 4.2 数据模型（RoomTemplate）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT | - | 主键 |
| template_name | VARCHAR(100) | 是 | 模板名称（如"内层曝光区/LDI 区"） |
| scope | VARCHAR(20) | 是 | system（内置）/ custom（用户自定义） |
| category | VARCHAR(50) | 否 | 工艺类别（曝光/电镀/蚀刻等，附录 B） |
| params | JSON | 是 | Room 参数集合（除 room_name/area/height 外的可继承字段） |
| project_id | BIGINT FK | 否 | scope=custom 时关联项目（空=全局可用） |

### 4.3 内置模板（系统预置，PRD 附录 B）

部署时 seed 13 个 PCB 典型工艺模板：内层曝光/LDI、阻焊印刷、文字印刷、钻孔、化学沉铜 PTH、电镀 VCP/线镀、蚀刻、棕化/黑化、压合、表面处理、测试电测/AOI、FQC 检验、成品仓/原料仓。每个含典型温湿度/洁净度/压差默认。

### 4.4 「从模板创建」流程（F2-025）

前端 `POST /api/v1/rooms` 时请求体携带 `template_id`，后端用模板 params 预填 Room 字段，用户可覆盖。

## 5. 额外负荷（ExtraLoad）

项目级/建筑级独立负荷 CRUD（PRD F2-027~F2-031、§6.7）。通过 `building_id` 区分层级：有值=建筑级，空=项目级。

### 5.1 端点总览

| 方法 | 路径 | 说明 | PRD |
|------|------|------|-----|
| GET | `/api/v1/projects/{projectId}/extra-loads` | 额外负荷列表（支持 building_id 筛选） | F2-028 |
| POST | `/api/v1/projects/{projectId}/extra-loads` | 新增 | F2-028 |
| GET | `/api/v1/extra-loads/{id}` | 详情 | F2-028 |
| PUT | `/api/v1/extra-loads/{id}` | 更新 | F2-028 |
| DELETE | `/api/v1/extra-loads/{id}` | 删除 | F2-028 |

### 5.2 数据模型（ExtraLoad）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT | - | 主键 |
| project_id | BIGINT FK | 是 | 关联 Project |
| building_id | BIGINT FK | 否 | 关联 Building（空=项目级） |
| category | VARCHAR(50) | 是 | 类别枚举：PCW / 配电室空调 / 工艺热水 / 消防池保温 / 消防池护层 / 其他 |
| load_value | DECIMAL(12,4) | 是 | 负荷值（kW） |
| water_temp_config_id | BIGINT FK | 否 | 关联冷冻水档（空=不区分水温） |
| description | VARCHAR(200) | 否 | 备注 |

### 5.3 层级规则（F2-030/F2-031）

- `building_id` 有值 → 建筑级（如某厂房 PCW），汇总时纳入该建筑级 LoadSummary
- `building_id` 为空 → 项目级（如消防池保温），汇总时纳入项目级 LoadSummary
- 汇总由静态计算流水线 Step 6 自动纳入（见 `算法伪代码.md` §3 `aggregate_to_load_summary`）

### 5.4 错误码

`400 Bad Request`（load_value ≤ 0 或 category 不在枚举内）、`404 Not Found`。
