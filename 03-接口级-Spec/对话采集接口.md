> 版本：1.0

> PRD 引用：F2-046~F2-061（对话式采集六阶段）、§6.10 对话式采集页、SAC-28（六阶段 SOP 走通）、附录D 对话采集端点
> 依赖文档：02-模块级-Spec/模块-02-数据采集.md、03-接口级-Spec/表结构详细设计.md（ConversationSession / ConversationMessage）、03-接口级-Spec/房间接口.md（Room 单表，status: draft→active）

## 1. 概述

对话式采集是房间/建筑/项目数据的第三录入通道（与 Tab1 树形、Excel 共享同一 Room 单表数据模型）。系统按 SOP（六阶段）主动提问，用户以自然语言或快捷芯片作答，系统做意图识别与字段抽取，落入对应字段。

**核心特性**：
- **断点续采**（F2-057）：会话状态服务端持久化，刷新或下次进入从上次未完成节点继续。
- **同源回写**（F2-060）：对话产出回写同一 Room 单表，Tab1 树形详情立即可见。
- **finalize 事务写入**：草稿态 `Room.status='draft'` → 确认后 `active`。

### 1.1 端点总览（附录D 权威清单：6 个端点）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/projects/{projectId}/conversation-sessions` | 创建/恢复会话 |
| GET | `/api/v1/conversation-sessions/{id}` | 获取会话状态 |
| POST | `/api/v1/conversation-sessions/{id}/messages` | 发送消息（用户）/ 获取系统响应 |
| GET | `/api/v1/conversation-sessions/{id}/messages` | 回看历史消息 |
| PUT | `/api/v1/conversation-sessions/{id}/draft` | 保存草稿 |
| POST | `/api/v1/conversation-sessions/{id}/finalize` | 确认写入（draft→active） |

## 2. 关键枚举

| 枚举字段 | 取值 | 说明 |
|----------|------|------|
| `current_stage`（对话阶段） | `s1_project`（项目基本信息展示确认）/ `s2_water_temp`（冷冻水温度配置）/ `s3_building`（建筑结构信息）/ `s4_room`（功能区域参数）/ `s5_extra_load`（额外负荷信息）/ `s6_summary`（汇总预览与确认） | SOP 六阶段 |
| `role`（消息角色） | `system`（系统提示/工具结果）/ `user`（用户作答）/ `assistant`（系统提问/确认卡片） | 三种角色 |

## 3. 数据表（PascalCase）

### 3.1 ConversationSession（对话会话）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT PK | 是 | |
| project_id | BIGINT FK → `Project.id` | 是 | 归属项目 |
| current_stage | enum | 是 | 当前阶段，默认 `s1_project` |
| stage_status | JSON | 否 | 各阶段完成状态，如 `{"s1_project":"done","s2_water_temp":"active"}` |
| draft_payload | JSON | 否 | 已采集字段草稿（结构对应 Room/ExtraLoad/WaterTempConfig） |
| status | enum | 是 | `in_progress` / `finalized`，默认 in_progress |
| created_at / updated_at | TIMESTAMP | 是 | |

### 3.2 ConversationMessage（对话消息）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT PK | 是 | |
| session_id | BIGINT FK → `ConversationSession.id` | 是 | 归属会话 |
| role | enum | 是 | `system` / `user` / `assistant` |
| content | TEXT | 是 | 消息文本 |
| stage | enum | 否 | 该消息所属阶段 |
| extracted_fields | JSON | 否 | 抽取结果（assistant 消息附带），如 `{"room_name":"电镀车间","area":800}` |
| metadata | JSON | 否 | 工具卡片/确认卡片/芯片选项结构 |
| timestamp | TIMESTAMP | 是 | 消息时间（索引字段） |

**索引**：`(session_id, timestamp)` 复合索引（见索引设计.md），支撑历史消息回看。

## 4. 端点详细设计

### 4.1 POST /api/v1/projects/{projectId}/conversation-sessions

创建新会话或恢复该项目最近未完成的会话。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| resume | bool | 否 | true=恢复该项目最近的 `in_progress` 会话；false=创建新会话（默认） |

**响应 200**（恢复）或 **201**（新建）

```json
{
  "success": true,
  "data": {
    "id": "sess-abc123",
    "project_id": 1,
    "current_stage": "s4_room",
    "stage_status": {
      "s1_project": "done",
      "s2_water_temp": "done",
      "s3_building": "done",
      "s4_room": "active",
      "s5_extra_load": "pending",
      "s6_summary": "pending"
    },
    "status": "in_progress",
    "draft_payload": {
      "buildings": [{"id": 1, "building_name": "1#厂房", "floors": [...]}],
      "rooms_in_progress": [{"room_name": "电镀车间", "area": 800, "status": "draft"}]
    },
    "next_prompt": "请描述电镀车间的人员数量与设备功率...",
    "created_at": "2026-07-14T09:00:00Z",
    "updated_at": "2026-07-14T09:30:00Z"
  }
}
```

**行为**：
- `resume=true` 且存在未完成会话：返回该会话，前端据 `current_stage` 续采（F2-057）。
- `resume=true` 但无未完成会话：返回 404 提示无可恢复会话。
- 新建会话：`current_stage='s1_project'`，系统首条消息展示已关联的城市国标参数与气象数据（F2-054，不重复拉取）。

**错误码**：`404 RESOURCE_NOT_FOUND`（projectId 不存在，或 resume=true 但无可恢复会话）、`403 INSUFFICIENT_PERMISSIONS`。

### 4.2 GET /api/v1/conversation-sessions/{id}

获取会话当前状态（用于刷新页面后回填 Context）。

**响应 200**：同 §4.1 响应结构（无 next_prompt，由前端据 current_stage 推导）。

**错误码**：`404 RESOURCE_NOT_FOUND`。

### 4.3 POST /api/v1/conversation-sessions/{id}/messages

发送用户消息，获取系统响应（提问/确认卡片/工具结果）。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| content | string | 是 | 用户消息文本（自然语言）或快捷芯片值 |
| stage | enum | 否 | 用户当前所在阶段（默认=会话 current_stage） |
| action | enum | 否 | `answer`（默认）/ `edit`（修改上一步）/ `skip`（跳过待补）/ `back`（回退） |

```json
{
  "content": "电镀车间有 20 个操作工，电动设备功率 100kW，系数 0.7",
  "stage": "s4_room",
  "action": "answer"
}
```

**响应 200**

```json
{
  "success": true,
  "data": {
    "user_message": {
      "id": 201,
      "role": "user",
      "content": "电镀车间有 20 个操作工...",
      "stage": "s4_room",
      "timestamp": "2026-07-14T09:31:00Z"
    },
    "assistant_message": {
      "id": 202,
      "role": "assistant",
      "content": "已识别：人员数量=20，电动设备功率=100kW，系数=0.7。请确认或修改：",
      "stage": "s4_room",
      "extracted_fields": {
        "personnel_count": 20,
        "electric_equipment_power": 100.0,
        "electric_equipment_coefficient": 0.7
      },
      "metadata": {
        "card_type": "confirmation",
        "fields": [
          {"name": "personnel_count", "value": 20, "editable": true},
          {"name": "electric_equipment_power", "value": 100.0, "editable": true},
          {"name": "electric_equipment_coefficient", "value": 0.7, "editable": true}
        ],
        "chips": ["确认", "修改", "跳过", "稍后补"]
      },
      "timestamp": "2026-07-14T09:31:01Z"
    },
    "session_update": {
      "current_stage": "s4_room",
      "stage_status": { "s4_room": "active" },
      "draft_payload_updated": true
    }
  }
}
```

**行为**：
- 服务端做意图识别与字段抽取（F2-049），落入 `ConversationMessage.extracted_fields`。
- 抽取结果写入 `ConversationSession.draft_payload`（草稿，不直接落 Room 表）。
- 复杂枚举提供快捷芯片（F2-050），如 `fresh_air_water_mode` 提供「单水温/两阶段」芯片。
- 关键节点输出确认卡片（F2-051），支持确认/修改/跳过/稍后补。
- 上下文记忆（F2-052）：引用前文决定后续分支（如已选冷冻水配置影响区域默认末端冷冻水档）。
- `action=edit/back` 时回退到指定阶段或修改前序字段。

**错误码**：`400 VALIDATION_ERROR`、`404 RESOURCE_NOT_FOUND`、`409 CONFLICT`（会话已 finalized，不可再发消息）。

### 4.4 GET /api/v1/conversation-sessions/{id}/messages

回看历史消息（F2-058 跳转修改时加载上下文）。

**查询参数**

| 参数 | 类型 | 说明 |
|------|------|------|
| stage | enum | 按阶段过滤 |
| limit | int | 默认 50，最大 200 |
| before_id | int | 分页游标（早于该消息 ID） |

**响应 200**

```json
{
  "success": true,
  "data": {
    "session_id": "sess-abc123",
    "messages": [
      { "id": 1, "role": "assistant", "content": "项目已关联深圳国标参数...", "stage": "s1_project", "timestamp": "..." },
      { "id": 2, "role": "user", "content": "确认", "stage": "s1_project", "timestamp": "..." },
      { "id": 3, "role": "assistant", "content": "请配置冷冻水温度...", "stage": "s2_water_temp", "timestamp": "..." }
    ],
    "has_more": true,
    "next_cursor": 50
  }
}
```

**错误码**：`404 RESOURCE_NOT_FOUND`。

### 4.5 PUT /api/v1/conversation-sessions/{id}/draft

保存草稿（F2-058 保存退出）。每阶段完成或用户主动保存时调用。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| draft_payload | object | 是 | 草稿数据（结构对应 Room/ExtraLoad/WaterTempConfig 等） |
| current_stage | enum | 否 | 更新当前阶段 |
| stage_status | object | 否 | 更新阶段状态 |

```json
{
  "draft_payload": {
    "rooms_draft": [
      {"temp_id": "tmp-1", "room_name": "电镀车间", "area": 800, "height": 5, "civil_load_index": 50, "status": "draft"}
    ]
  },
  "current_stage": "s4_room",
  "stage_status": {"s4_room": "active"}
}
```

**响应 200**

```json
{
  "success": true,
  "data": {
    "session_id": "sess-abc123",
    "current_stage": "s4_room",
    "stage_status": {"s4_room": "active"},
    "saved_at": "2026-07-14T09:35:00Z"
  }
}
```

**行为**：覆盖 `ConversationSession.draft_payload / stage_status`；不落 Room 表（草稿仅在 session 内）。刷新或下次进入可通过 GET 会话恢复。

**错误码**：`400 VALIDATION_ERROR`、`404 RESOURCE_NOT_FOUND`、`409 CONFLICT`（会话已 finalized）。

### 4.6 POST /api/v1/conversation-sessions/{id}/finalize

确认写入（F2-060 同源回写）。将草稿事务性写入 Room 单表（`status: draft→active`）、Building、Floor、ExtraLoad、WaterTempConfig 等。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| confirm | bool | 是 | 必须为 true（NF-015 二次确认） |
| scope | enum | 否 | `all`（默认，全部草稿）/ `partial`（部分，需配合 partial_ids） |
| partial_ids | array | 否 | scope=partial 时指定写入哪些草稿实体 |

**响应 200**

```json
{
  "success": true,
  "data": {
    "session_id": "sess-abc123",
    "status": "finalized",
    "written_entities": {
      "buildings": [{"temp_id": "tmp-b1", "id": 5, "building_name": "1#厂房"}],
      "floors": [{"temp_id": "tmp-f1", "id": 10, "floor_name": "1F"}],
      "rooms": [
        {"temp_id": "tmp-1", "id": 105, "room_name": "电镀车间", "status": "active"}
      ],
      "extra_loads": [{"temp_id": "tmp-e1", "id": 8, "category": "PCW", "load_value": 500.0}]
    },
    "summary_preview": {
      "total_rooms": 12,
      "total_load_kw": 2400.50
    },
    "finalized_at": "2026-07-14T10:00:00Z"
  }
}
```

**行为**：
- 在单一数据库事务内：将 `draft_payload` 中的实体写入对应表；Room 记录的 `status` 由 `draft` 转 `active`。
- 写入前校验：草稿字段完整性（必填字段不缺）、外键有效性（如 `terminal_water_temp_config_id` 引用的 WaterTempConfig 存在）。
- 写入后会话状态置为 `finalized`，不可再发消息或保存草稿。
- 返回汇总预览，前端展示多维表（按建筑/水温分类筛选汇总，F2-059），支持导出 CSV/JSON（与导出接口对齐）。

**错误码**

| HTTP | code | 触发条件 |
|------|------|----------|
| 400 | VALIDATION_ERROR | confirm != true，或草稿缺必填字段 |
| 404 | RESOURCE_NOT_FOUND | 会话不存在 |
| 409 | CONFLICT | 会话已 finalized |
| 422 | FINALIZE_ERROR | 事务写入失败（外键无效、字段非法），整体回滚 |

> finalize 是事务操作：任一实体写入失败则全部回滚，会话保持 `in_progress`，用户可修正后重试。

## 5. 断点续采语义（F2-057）

1. 用户中途退出（关闭页面/刷新）→ 前端在 `beforeunload` 调用 `PUT /draft` 保存当前草稿。
2. 重新进入 → 调用 `POST /conversation-sessions {resume: true}` 获取该项目最近 `in_progress` 会话。
3. 前端据 `current_stage` 与 `stage_status` 跳转到对应阶段，加载历史消息（`GET /messages`）回填对话上下文。
4. 用户可「修改上一步」「跳过待补」「跳转任意已完成节点」（F2-058）。

---

## 6. 鉴权与数据隔离

- 所有端点需工程师及以上角色（写入权限）；项目数据按 `project_id` 隔离。
- 会话归属于单一项目，跨项目不可访问。

## 7. 待确认 / 开放问题

- **O-1 意图识别与字段抽取的实现**：基于规则模板（关键词匹配）还是 LLM 调用，待确认——**当前基线：规则模板优先（确定性高），复杂语句降级 LLM。**
- **O-2 finalize 部分写入**：scope=partial 的具体语义（允许只确认部分草稿、其余保留 draft）是否支持，待确认。
- **O-3 草稿实体 temp_id 命名规则**：前端生成的临时 ID 与后端写入后真实 ID 的映射方案，待确认。
