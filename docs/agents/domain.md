# 领域文档

工程技能在探索代码库时如何消费本仓库的领域文档。

## 探索前先读

- **`CONTEXT.md`**（仓库根目录）—— 领域词汇与上下文入口
- **`09-参考文档/架构决策记录/`** —— 阅读与即将工作的领域相关的 ADR（架构决策记录）

> 本仓库为**单上下文**布局，不使用 `CONTEXT-MAP.md`。ADR 沿用现有 `09-参考文档/架构决策记录/` 目录，不另起 `docs/adr/`（遵循奥卡姆剃刀）。

## 文件结构

```
/
├── CONTEXT.md                         ← 领域词汇 / 上下文入口
├── 09-参考文档/架构决策记录/          ← ADR（ADR-0001 ~ ADR-0005）
└── src/
```

## 使用术语表的词汇

当输出中命名一个领域概念（issue 标题、重构提案、假设、测试名），使用 `CONTEXT.md` 中定义的术语，不要漂移到术语表明确避免的同义词。

若所需概念尚未进入术语表，这是一个信号——要么你在发明项目不使用的语言（重新考虑），要么存在真实缺口（记录待 `/domain-modeling` 处理）。

## 标记 ADR 冲突

若输出与某现有 ADR 矛盾，显式指出而非静默覆盖：

> _与 ADR-0005（PID 与水蓄冷范围）矛盾 —— 但值得重开，因为…_
