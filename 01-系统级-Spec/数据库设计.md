## 1. 文档概述

### 1.1 目的

本文档描述 PCB 冷量仿真系统的数据库设计方案，是后续开发实施（建表、ORM 模型、迁移）的权威依据。

### 1.2 系统简介

PCB 冷量仿真系统用于计算 PCB 工厂各功能区域的冷热负荷。系统以**功能区域（Room）为最小计算单元**，核心计算公式（详见 §4 计算公式与 PRD §15）：

```
区域总负荷 = 末端负荷 + 新风冷负荷
末端负荷 = 土建负荷 + 照明负荷 + 人员负荷 + 电动设备负荷 + 电热设备负荷
新风冷负荷 = ρ × 新风量 × (室外焓值 − 室内焓值) / 3600      (kW)，ρ 默认 1.2
新风量 = 总排风量 + 压差渗透风量                             (简单加法，不加卫生/净化风量)
总负荷 < 0 时截断为 0
```

负荷按不同温度的冷冻水进行分类（如低温 7/12℃、中温 12/17℃），末端负荷按功能区域"末端冷冻水档"归入对应分类（ADR-0001）。

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| 表名 PascalCase | 表名（ORM 模型名）统一 PascalCase，对齐 PRD 附录 E；字段名（DB/Python 层）统一 snake_case |
| 字段分类 | 明确区分**用户输入字段**、**系统预置**、**计算中间结果**、**最终计算结果** |
| 必填标识 | 区分必填字段与可选字段，允许部分字段空缺（空值按规则取默认值） |
| 扩展性 | 冷冻水温度、比例系数、压差渗透系数表、默认值配置独立存储，支持项目级覆盖 |
| 无季节表 | v0.5.1 不设 season_config；动态仿真由 8760h×3 年逐时气象数据自然覆盖全年（PRD §15.4） |

### 1.4 字段分类约定

本文档所有表字段按以下四种类型标注：

| 类型 | 标记 | 说明 |
|------|------|------|
| 用户输入 | `[INPUT]` | 用户手动录入的原始数据 |
| 系统预置 | `[SEED]` | 系统部署时从外部数据源批量导入的参考数据，用户不直接输入 |
| 中间结果 | `[CALC]` | 系统根据公式计算得出的中间值 |
| 最终结果 | `[RESULT]` | 最终输出的计算结果 |

### 1.5 命名约定

- **表名**：PascalCase（即 ORM 模型类名，如 `Room`、`WaterTempConfig`、`DynamicLoadHourly`）。
- **字段名**：snake_case（DB 列名 / Python 属性名，如 `room_name`、`terminal_water_temp_config_id`）。
- **物理表名**：Django ORM 默认 app_model 映射，本文档以 PascalCase 逻辑表名为准；迁移脚本与 ORM `db_table` 由模块级文档统一约定。
- **超表**：`DynamicLoadHourly` 与 `WeatherRecord` 建议建为 TimescaleDB 超表，分区策略见 §5 与 `03-接口级-Spec/分区策略.md`。

## 2. 总体 ER 关系

```
CityConfig (城市配置 / 国标参数，系统预置只读) [SEED]
WeatherRecord (逐时气象，TimescaleDB 超表，按 city_id+timestamp 分区) [SEED]

Project (项目/工厂)
  ├── city_id → CityConfig
  ├── WaterTempConfig (项目级冷冻水温度配置，可多条) [INPUT]
  ├── DefaultConfig (项目/建筑/楼层级默认值覆盖；系统级另存) [SEED/INPUT]
  ├── Building (建筑)
  │     ├── Floor (楼层，含 floor_plan JSON 平面图)
  │     │     └── Room (功能区域 — 单表，30+ 字段含全部用户输入) [INPUT]
  │     └── ExtraLoad (建筑级额外负荷，building_id 有值) [INPUT]
  ├── ExtraLoad (项目级额外负荷，building_id 为空) [INPUT]
  ├── ConversationSession (对话采集会话)
  │     └── ConversationMessage (对话消息历史)
  ├── SimulationRun (仿真任务，对齐 CeleryTaskMeta)
  └── 计算结果：
        RoomCalcResult (区域级静态计算全部中间值/最终值)
        RoomLoadByWaterTemp (按水温分类：末端 + 新风分别记录)
        LoadSummary (楼层/建筑/项目多级聚合)
        DynamicLoadHourly (动态仿真逐时，TimescaleDB 超表)
        DynamicLoadSummary (动态仿真聚合统计)

系统级（不挂项目）：
  RoomTemplate (功能区域模板，含内置 PCB 工艺模板，附录 B)
  RatioCoefficient (比例系数权威表，ADR-0003，温度区间×负荷率)
  DefaultConfig (系统级默认，含压差渗透系数表、空气密度 ρ、室内温湿度默认)
  User / Role (账户与权限)
  OperationLog (操作日志)
  CeleryTaskMeta (Celery 异步任务状态，Redis 结果后端)

负荷预测（按场景）：
  ForecastScenario → ForecastWeatherData / ForecastProductionRate / ForecastHourlyResult
```

## 4. 表结构详细设计

> 量纲约定：负荷单位 kW（不乘 1000），指标单位 W/m² 或 W/人；新风量 m³/h；焓值 kJ/kg；ρ 默认 1.2 kg/m³（取自 DefaultConfig.air_density）。

### 4.1 Project（项目表）

存储项目/工厂基本信息。

| 字段名 | 类型 | 必填 | 分类 | 说明 |
|--------|------|------|------|------|
| id | BIGINT PK | 是 | - | 主键，自增 |
| project_name | VARCHAR(200) | 是 | [INPUT] | 项目名称 |
| project_code | VARCHAR(50) | 否 | [INPUT] | 项目编号 |
| description | VARCHAR(500) | 否 | [INPUT] | 项目描述 |
| location | VARCHAR(200) | 否 | [INPUT] | 项目详细地址（如"黄埔区XX路XX号"），仅展示，不参与计算 |
| city_id | BIGINT FK | 是 | [INPUT] | 关联城市（`CityConfig.id`），获取国标室外参数 |
| created_at | DATETIME | 是 | - | 创建时间 |
| updated_at | DATETIME | 是 | - | 更新时间 |

**字段说明：**
- `city_id` 必填，关联城市配置表，自动获取国标室外设计参数与基础信息，是计算链路的必要前提。
- `location` 非必填，仅展示与备注。

### 4.11 计算公式（PRD §15 对齐）

**末端负荷（量纲 kW，指标 W/m² 或 W/人，故除以 1000）：**

```
civil_load          = civil_load_index × area / 1000
lighting_load       = lighting_load_index × area / 1000
personnel_load      = personnel_load_index × personnel_count / 1000      (空值取 0)
electric_equipment_load = electric_equipment_power × electric_equipment_coefficient   (空取 0)
heated_equipment_load = heated_power_with × heated_coeff_with + heated_power_without × heated_coeff_without  (空取 0)

terminal_load = civil_load + lighting_load + personnel_load
              + electric_equipment_load + heated_equipment_load
```

**风量（PRD §15.2，简单加法）：**

```
total_exhaust_volume = heat_exhaust + acid_exhaust + alkali_exhaust
                     + organic_exhaust + dust_exhaust        (空值取 0)

压差渗透风量 = volume × k(|pressure_diff|)                 (m³/h)
  └─ k 由 8 点系数表查得（离散点线性插值，正/负压对称取绝对值）：
     |ΔP|=0 → 0；|±1|→1.0；|±2|→1.5；|±3|→2.0；|±5|→3.0；|±10|→3.5；|±15|→4.0；>±15 → 封顶 4.0
  └─ 系数表写入 DefaultConfig.pressure_diff_coeff_table，可项目级覆盖（C10）

fresh_air_volume = total_exhaust_volume + 压差渗透风量
  └─ 简单加法：不加 MAX 逻辑，不加卫生风量，不加净化风量（PRD A4 工程简化）

volume = area × height
```

**新风冷负荷与总负荷（PRD §15.3）：**

```
indoor_enthalpy  = psychrolib(indoor_calc_temp, indoor_calc_humidity, pressure_summer)
outdoor_enthalpy = psychrolib(temp_dry_ac_summer, 由湿球推算 RH, pressure_summer)
enthalpy_diff    = outdoor_enthalpy − indoor_enthalpy       (允许为负，冬季/过渡季)

fresh_air_load = ρ × fresh_air_volume × enthalpy_diff / 3600      (kW)
  └─ ρ = DefaultConfig.air_density，默认 1.2 kg/m³

total_load = terminal_load + fresh_air_load
  └─ total_load < 0 时截断为 0（静态与动态统一，PRD §15.3 / F4-014）
  └─ 极值统计 Q_min 只取 Q > 0 的最小值

cold_load_index = total_load / area × 1000      (W/m²)
```

**按冷冻水温度分类（ADR-0001，PRD §15.5）：** 末端负荷按 `room.terminal_water_temp_config_id` 归入对应水温档（默认中温）；新风冷负荷按 `fresh_air_water_mode` 归入（single 全部归入第一段档；dual 按比例分配到两段档）。分类结果落 `RoomLoadByWaterTemp`。

### 4.18 RatioCoefficient（比例系数权威表 / ADR-0003）

**说明：**

## 6. 数据流转关系

```
用户输入阶段（单表 Room + 配置表）：
  CityConfig (城市/国标参数) [SEED]
  WeatherRecord (逐时气象) [SEED]
      ↓
  Room (单表：基本信息 + 温湿度 + 负荷参数 + 设备参数 + 风量参数 + 新风配置 + 末端冷冻水档)
  WaterTempConfig (冷冻水温度档)
  DefaultConfig (默认值 + 压差系数表 + 空气密度 ρ)
  ExtraLoad (额外负荷)
      ↓
计算阶段（RoomCalcResult）：
  室外焓值 ← CityConfig 夏季参数 + psychrolib 实时计算
  室内焓值 ← Room.indoor_calc_temp/humidity（空取默认 26/55）+ psychrolib
      ↓
  RoomCalcResult ← Room（负荷参数 + 风量参数）+ CityConfig + DefaultConfig
      ├─ 末端负荷五项（土建/照明/人员/电动/电热）→ 末端合计
      ├─ 风量（总排风 + 压差渗透 → 新风量，简单加法）
      ├─ 焓值（室内/室外/焓差）
      ├─ 新风冷负荷 = ρ × 新风量 × 焓差 / 3600
      └─ 总负荷 = 末端 + 新风，< 0 截断 0；冷指标 = 总负荷/面积×1000
      ↓
  RoomLoadByWaterTemp ← RoomCalcResult + Room（末端档/新风模式）+ WaterTempConfig
      ↓ 按水温分类：末端按 terminal_water_temp_config_id；新风按 fresh_air_water_mode
      ↓
  LoadSummary ← RoomLoadByWaterTemp + ExtraLoad（聚合）
      ↓ 楼层 ← 该楼层所有区域聚合
      ↓ 建筑 ← 所有楼层 + ExtraLoad（building_id 有值）
      ↓ 项目 ← 所有建筑 + ExtraLoad（building_id 为空）

动态仿真阶段：
  SimulationRun（气象驱动 / 比例系数法）
      ↓ 复用 RoomCalcResult.terminal_load（桥梁）
  DynamicLoadHourly（逐时，超表）← terminal_load + 逐时新风（WeatherRecord 或比例系数）
      ↓ < 0 截断 0
  DynamicLoadSummary（峰值/均值/最小/CV，按 room/floor/building/project + water_temp）

负荷预测阶段：
  ForecastScenario → ForecastWeatherData + ForecastProductionRate
      ↓ 预测负荷 = 静态设计负荷 × K(T,R)（查 RatioCoefficient，双线性插值）
  ForecastHourlyResult（功能区域级逐时）

对话采集通道（与 Tab1 树形/Excel 录入同一数据模型，两种通道）：
  ConversationSession（六阶段状态/草稿）→ ConversationMessage（消息历史/抽取字段）
      ↓ 逐区域提交 / 保存即落库
  回写 Room（status: draft→active）/ WaterTempConfig / Building / Floor / ExtraLoad
```

> **对话采集写入语义（v0.5.1）：** 对话式采集（PRD §6.10）与 Tab1 树形/Excel 录入为同一数据集的两种录入通道，采用**逐区域提交 / 保存即落库**；⑥ 汇总预览仅做校验与确认，确认后状态标记完成。会话状态由 ConversationSession 持久化（F2-057 断点续采），消息历史落 ConversationMessage，房间草稿以 `room.status=draft` 暂存。

## 7. 扩展性设计说明

### 7.1 冷冻水温度灵活配置

不同工厂对冷冻水的温度范围定义不同（如 7/12、7/13、5/10），通过 `WaterTempConfig` 表每个项目独立配置，无需修改表结构。

### 7.2 默认值四级覆盖

`DefaultConfig` 支持 system → project → building → floor 四级覆盖（PRD §6.9）；压差渗透系数表、空气密度 ρ、室内温湿度默认、各项指标默认均可在项目级覆盖。

### 7.3 排风类型扩展

当前排风类型以固定字段存储（热/酸/碱/有机/含尘）。如需扩展：方式一在 Room 表新增字段；方式二建独立排风类型字典表（v0.6 评估）。

### 7.4 负荷类别扩展

`LoadSummary.category` 与 `ExtraLoad.category` 均支持扩展新类别（如"空压机冷却"），无需修改表结构。

### 7.5 比例系数项目级覆盖

`RatioCoefficient` 通过 `is_default` + `project_id` 实现系统默认与项目级覆盖（ADR-0003），v0.6 支持用户自定义。

> **关于季节：** v0.5.1 不设 season_config；动态仿真由 8760h×3 年逐时气象数据自然覆盖全年所有季节（PRD §15.4），7 月高温与 1 月低温由气象数据本身区分。
