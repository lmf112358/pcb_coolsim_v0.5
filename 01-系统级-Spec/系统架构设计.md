## 1. Architecture Overview

### 1.1 Design Principles

| Principle | Description |
|-----------|-------------|
| Separation of Concerns | Clear separation between frontend, backend, calculation engine, and data layer |
| Single Responsibility | Each module handles one distinct business domain |
| Open/Closed Principle | Calculation engine supports formula extensibility without modifying core logic |
| Data Integrity | All calculations traceable to source inputs with clear audit trail |
| Performance | Support 1000+ rooms with sub-second response for common operations |
| Scalability | Horizontal scaling capability for async computation tasks |

## 4. Data Flow Architecture

### 4.1 Static Calculation Flow

```
User Input (Room Parameters)
        │
        ▼
┌─────────────────────────────────┐
│ API Endpoint: /api/v1/rooms/{id}/calculate-static/ │
└─────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│ Input Validation                 │
│  - Required fields check         │
│  - Value range validation        │
│  - Business rule validation      │
└─────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│ Calculation Engine              │
│  Step 1: Enthalpy Calculation   │
│  Step 2: Terminal Load Calc     │
│  Step 3: Air Volume Calc        │
│  Step 4: Fresh Air Load Calc    │
│  Step 5: Room Total Load        │
│  Step 6: Load Aggregation       │
└─────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│ Store Results                   │
│  - room_load_result             │
│  - room_air_volume_result       │
│  - room_load_summary            │
│  - load_summary                 │
└─────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│ Return Response                 │
│  - Calculation results          │
│  - Validation warnings          │
│  - Cache key for real-time      │
└─────────────────────────────────┘
```

### 4.2 Real-time Preview Flow

```
User Modifies Room Parameter
        │
        ▼
┌─────────────────────────────────┐
│ Frontend: Debounce (500ms)      │
└─────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│ API Endpoint: /api/v1/rooms/{id}/preview/ │
│  - Lightweight calculation      │
│  - Returns only affected values │
└─────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│ Redis Cache Check               │
│  - Cache key: room:{id}:params:{hash} │
│  - TTL: 30 seconds              │
└─────────────────────────────────┘
        │
        ▼ (cache miss)
┌─────────────────────────────────┐
│ Calculation Engine              │
│  - Execute Steps 1-5            │
│  - Skip Step 6 (aggregation)    │
└─────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│ Cache Result + Return           │
└─────────────────────────────────┘
```

### 4.3 Dynamic Simulation Flow

```
User Triggers Simulation
        │
        ▼
┌─────────────────────────────────┐
│ API Endpoint: /api/v1/projects/{id}/simulate/ │
└─────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│ Create Celery Task              │
│  - task_id returned immediately │
│  - WebSocket subscription       │
└─────────────────────────────────┘
        │
        ▼ (async)
┌─────────────────────────────────┐
│ Celery Worker                   │
│  1. Load Weather Data (3 years) │
│  2. Load Room Configurations    │
│  3. Execute Simulation          │
│     - 8760h × 3 years × N rooms│
│  4. Store Results               │
│  5. Send WebSocket Notification │
└─────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│ Frontend: Receive Notification  │
│  - Update UI with results       │
│  - Show completion message      │
└─────────────────────────────────┘
```

## 6. Security Architecture

### 6.1 Authentication & Authorization

```
┌─────────────────────────────────────────┐
│ JWT Authentication Flow                 │
├─────────────────────────────────────────┤
│ 1. Client sends credentials             │
│ 2. Server validates & returns:          │
│    - Access Token (15 min TTL)          │
│    - Refresh Token (7 days TTL)         │
│ 3. Client stores tokens securely        │
│ 4. Client sends Access Token in header  │
│ 5. On 401, client uses Refresh Token    │
│ 6. If Refresh invalid, redirect to login│
└─────────────────────────────────────────┘
```

### 6.2 Permission Matrix

| Resource | Admin | PM | Engineer | Viewer |
|----------|-------|-----|----------|--------|
| User Management | CRUD | - | - | - |
| Project (own) | CRUD | CRUD | R | R |
| Project (other) | CRUD | - | - | - |
| Building/Floor/Room | CRUD | CRUD | CRUD | R |
| Calculations | Execute | Execute | Execute | - |
| Exports | All | All | All | View |
| Settings | CRUD | R | R | R |

### 6.3 Data Isolation

- Project-level data isolation enforced at query level
- Users can only access projects they are members of
- Role-based access control within projects
- API endpoints validate project membership before data access

## 7. Performance Architecture

### 7.1 Performance Targets

| Operation | Target | Strategy |
|-----------|--------|----------|
| Tree Navigation (1000 nodes) | < 2s | Virtual Scrolling |
| Real-time Preview | < 500ms | Redis Cache + Lightweight Calc |
| Static Calculation (1000 rooms) | < 10s | Batch Processing |
| Dynamic Simulation (8760h × 3yr) | < 30s | Async + Parallel Processing |
| Map Rendering | < 3s | Tile Caching |
| 2D Editor (100 rooms) | < 3s | Canvas Optimization |

### 7.2 Caching Strategy

| Layer | Cache Type | TTL | Invalidation |
|-------|-----------|-----|--------------|
| Browser | LocalStorage | Session | Manual |
| API | Redis | 30s | On Update |
| Database | Query Cache | 5min | On Write |
| CDN | Static Assets | 1 year | Versioned |

### 7.3 Database Optimization

- Strategic indexing on frequently queried fields
- JSONB for flexible configuration storage
- Materialized views for complex aggregations
- Connection pooling for concurrent requests
- Read replicas for reporting queries

## 9. Monitoring & Observability

### 9.1 Metrics Collection

- **Application Metrics:** Request latency, error rates, active users
- **Business Metrics:** Calculation times, export counts, user activity
- **Infrastructure Metrics:** CPU, memory, disk, network
- **Database Metrics:** Query performance, connection pool, cache hit rate

### 9.2 Logging Strategy

| Level | Purpose | Example |
|-------|---------|---------|
| DEBUG | Development debugging | Variable values, function entry/exit |
| INFO | Business events | User login, calculation started |
| WARNING | Degraded performance | Slow query, cache miss |
| ERROR | Application errors | Calculation failed, API error |
| CRITICAL | System failures | Database connection lost |

### 9.3 Alerting Rules

- API response time > 2s (Warning)
- API error rate > 5% (Critical)
- Database connection pool > 80% (Warning)
- Celery task failure rate > 10% (Critical)
- Disk usage > 80% (Warning)

## 10. Error Handling Strategy

### 10.1 Error Categories

| Category | HTTP Code | Example | Handling |
|----------|-----------|---------|----------|
| Validation Error | 400 | Invalid input | Return detailed validation errors |
| Authentication | 401 | Invalid token | Redirect to login |
| Authorization | 403 | Insufficient permissions | Show permission denied |
| Not Found | 404 | Resource doesn't exist | Show 404 page |
| Conflict | 409 | Duplicate resource | Show conflict message |
| Calculation Error | 422 | Invalid parameters | Return specific calculation error |
| Server Error | 500 | Unexpected error | Log error, show generic message |

### 10.2 Calculation Error Handling

```
Calculation Error Types:
├── Input Validation Errors
│   ├── Missing required fields
│   ├── Out of range values
│   └── Invalid field combinations
├── Calculation Errors
│   ├── Division by zero (handled with defaults)
│   ├── Invalid psychrometric state
│   └── Overflow/underflow
└── System Errors
    ├── Database connection failure
    ├── Cache unavailable
    └── External API failure
```
