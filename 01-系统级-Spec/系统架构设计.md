## 1. 架构概述

### 1.1 设计原则

| 原则 | 描述 |
|-----------|-------------|
| 关注点分离 | 前端、后端、计算引擎与数据层之间的清晰分离 |
| 单一职责 | 每个模块负责一个独立的业务领域 |
| 开闭原则 | 计算引擎支持公式扩展而无需修改核心逻辑 |
| 数据完整性 | 所有计算均可追溯至源输入，并具备清晰的审计轨迹 |
| 性能 | 支持全项目合计 100,000+ 功能区域，常见操作 ≤200ms 响应（NF-001/NF-008） |
| 可扩展性 | 异步计算任务的水平扩展能力 |

### 4.3 动态仿真流程

动态仿真支持两种驱动模式（F6-001 / F6-002，详见 PRD §10），由请求参数 `mode` 区分；二者共用同一异步任务编排，差异仅在「负荷逐时化」步骤的数据来源。

```
用户触发仿真（指定 mode = weather_driven | ratio_coefficient）
        │
        ▼
┌─────────────────────────────────┐
│ API Endpoint: /api/v1/projects/{id}/simulate/ │
│  - mode: weather_driven | ratio_coefficient    │
└─────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│ 创建 Celery 任务 + SimulationRun 记录 │
│  - task_id 立即返回 │
│  - WebSocket 订阅       │
│  - SimulationRun.status: PENDING→STARTED │
└─────────────────────────────────┘
        │
        ▼ (async)
┌─────────────────────────────────┐
│ Celery Worker                   │
│  1. 加载房间配置 + 静态设计负荷 │
│  2. 逐时化负荷（按 mode 分支）：    │
│     ┌─ weather_driven（F6-001）：│
│     │   加载气象数据（连续 3 年逐时，约 26280 条/城市）│
│     │   → 焓值/新风逐时重算 → 末端+新风逐时负荷 │
│     └─ ratio_coefficient（F6-002，ADR-0003）：│
│         读取 RatioCoefficient 系数矩阵 K(t, 生产负荷率)│
│         → 静态设计负荷 × K(t) 得逐时负荷 │
│  3. 执行仿真：8760h × 3 年 × N 个房间 │
│  4. 存储结果（DynamicLoadHourly 超表 / 聚合到 DynamicLoadSummary）│
│  5. SimulationRun.status → SUCCESS，发送 WebSocket 通知 │
└─────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│ 前端：接收通知  │
│  - 使用结果更新 UI       │
│  - 显示完成消息      │
└─────────────────────────────────┘
```

> 说明：比例系数法（`ratio_coefficient`）以静态计算结果（RoomCalcResult.total_load）为基准，按 `RatioCoefficient` 矩阵（季节 / 小时 / 生产负荷率维度，ADR-0003）逐时缩放，不重算焓值，适合无气象数据或快速估算场景；气象驱动法（`weather_driven`）逐时重算焓值与新风负荷，精度更高（SAC-3 < 1%）。

## 6. 安全架构

### 6.1 认证与授权

```
┌─────────────────────────────────────────┐
│ JWT 认证流程                 │
├─────────────────────────────────────────┤
│ 1. 客户端发送凭据             │
│ 2. 服务端校验并返回：          │
│    - 访问令牌（15 分钟 TTL）          │
│    - 刷新令牌（7 天 TTL）         │
│ 3. 客户端安全存储令牌        │
│ 4. 客户端在请求头中发送访问令牌  │
│ 5. 收到 401 时客户端使用刷新令牌    │
│ 6. 若刷新令牌无效，重定向至登录│
└─────────────────────────────────────────┘
```

| 导出 | 全部 | 全部 | 全部 | 查看 |
| 设置 | CRUD | R | R | R |

### 6.3 数据隔离

- 在项目层级实施数据隔离，于查询层强制执行
- 用户仅可访问其所属的项目
- 项目内基于角色的访问控制
- API 端点在数据访问前校验项目成员资格

性能目标统一以 PRD §17.1 非功能需求为权威基线（NF-001 ~ NF-012）。

| 操作 | 目标 | 对应 NF | 策略 |
|-----------|--------|---------|----------|

| 单节点 1000+ 子节点渲染 | < 2s | NF-002 | 虚拟滚动 |
| Excel 10000+ 行导入 | < 30s | NF-003 | Pandas 批量解析 |

| 静态计算（1000+ 功能区域） | < 5s | NF-005 | 批处理 + 向量化 |
| 动态仿真（8760h × 3 年 × 1000+ 功能区域） | < 30s | NF-006 | 异步 + Celery 分片并行 |

| 操作响应（除计算外） | ≤ 200ms | NF-008 | 索引 + 缓存 |

## 8. 部署架构

### 8.1 开发环境

```yaml
# docker-compose.yml
services:
  frontend:
    build: ./frontend
    ports: ["3000:3000"]
    volumes: ["./frontend:/app"]

  backend:
    build: ./backend
    ports: ["8000:8000"]
    volumes: ["./backend:/app"]
    depends_on: [db, redis]

  db:
    image: postgres:16
    ports: ["5432:5432"]
    volumes: ["pgdata:/var/lib/postgresql/data"]

  redis:
    # 作为 Celery broker + result backend + 应用缓存三合一（ADR-0002）
    image: redis:7-alpine
    ports: ["6379:6379"]

  celery:
    build: ./backend
    command: celery -A config worker -l info
    depends_on: [db, redis]

  celery-beat:
    # 周期任务：气象拉取 / 预测天气每小时更新（ADR-0002 / NF-032）
    build: ./backend
    command: celery -A config beat -l info
    depends_on: [redis, db]

  minio:
    image: minio/minio
    ports: ["9000:9000", "9001:9001"]
    command: server /data --console-address ":9001"
```

> 异步任务编排：Redis 作为 Celery broker 与 result backend；`celery` worker 消费队列执行仿真/计算/导出/气象拉取，`celery-beat` 调度周期任务（预测天气每小时更新等）；任务状态落 CeleryTaskMeta / SimulationRun，结果落 PG/TimescaleDB（详见部署架构 §3、§5）。

## 9. 监控与可观测性

### 9.1 指标采集

- **应用指标：** 请求延迟、错误率、活跃用户
- **业务指标：** 计算耗时、导出次数、用户活动
- **基础设施指标：** CPU、内存、磁盘、网络
- **数据库指标：** 查询性能、连接池、缓存命中率

### 9.2 日志策略

| 级别 | 用途 | 示例 |
|-------|---------|---------|
| DEBUG | 开发调试 | 变量取值、函数入口/出口 |
| INFO | 业务事件 | 用户登录、计算开始 |
| WARNING | 性能下降 | 慢查询、缓存未命中 |
| ERROR | 应用错误 | 计算失败、API 错误 |
| CRITICAL | 系统故障 | 数据库连接丢失 |

### 9.3 告警规则

- API 响应时间 > 2s（告警）
- API 错误率 > 5%（严重）
- 数据库连接池 > 80%（告警）
- Celery 任务失败率 > 10%（严重）
- 磁盘使用率 > 80%（告警）

## 10. 错误处理策略

### 10.1 错误分类

| 类别 | HTTP 状态码 | 示例 | 处理方式 |
|----------|-----------|---------|----------|
| 校验错误 | 400 | 输入无效 | 返回详细校验错误 |
| 认证 | 401 | 令牌无效 | 重定向至登录 |
| 授权 | 403 | 权限不足 | 显示权限拒绝 |
| 未找到 | 404 | 资源不存在 | 显示 404 页面 |
| 冲突 | 409 | 重复资源 | 显示冲突消息 |
| 计算错误 | 422 | 参数无效 | 返回特定计算错误 |
| 服务器错误 | 500 | 意外错误 | 记录错误并显示通用消息 |

### 10.2 计算错误处理

```
计算错误类型：
├── 输入校验 Errors
│   ├── 缺失必填字段
│   ├── 取值越界
│   └── 字段组合无效
├── 计算错误
│   ├── 除以零（已通过默认值处理）
│   ├── 无效焓湿状态
│   └── 溢出/下溢
└── 系统错误
    ├── 数据库连接失败
    ├── 缓存不可用
    └── 外部 API 失败
```
