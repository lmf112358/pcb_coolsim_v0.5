## 文档职责

### 系统架构设计

- **职责**：定义系统整体架构、技术选型、部署方案
- **PRD 引用**：F1-001, F2-001, F4-001, F6-001
- **主要内容**：
  - 部署四层（浏览器 → Nginx → Django API（+Celery） → PostgreSQL/Redis/MinIO）
  - 技术栈选型（React, Django, PostgreSQL, Redis, Celery）
  - 部署方案（Docker, Kubernetes）
  - 安全设计（JWT, RBAC）
  - 性能设计（缓存、异步、分区，对齐 PRD §17.1 NF-001~NF-012）

> **关于「四层」的澄清**：本仓库存在两种「四层」语义，勿混淆：
> 1. **Spec 文档四层结构**（本目录体系）：00-PRD → 01-系统级 → 02-模块级 → 03-接口级 → 04-实现级（自上而下逐层细化）。
> 2. **部署四层拓扑**（运行时）：浏览器 → Nginx → Django（API + Celery） → 数据层（PostgreSQL + Redis + MinIO）。
> 上文「4 层架构设计」指部署拓扑，非 Spec 文档分层。

### 数据库设计

- **职责**：定义数据库表结构、字段、关系、索引
- **PRD 引用**：F1-001, F2-001, F4-001
- **主要内容**：
  - 数据表设计（Project / Building / Floor / Room / CityConfig / WaterTempConfig / DefaultConfig / RoomTemplate / ExtraLoad / 计算结果 / 气象 / 动态仿真 / 负荷预测 / 系统表 / 会话表等，**表数与命名以《数据库设计》§3 表总览为准**，PRD 附录 E 列核心 21 张并指向本文档）
  - ER 关系图
  - 字段分类（[INPUT], [SEED], [CALC], [RESULT]）
  - 索引设计
  - 分区策略（TimescaleDB 超表按时间 range）

### API 总览

- **职责**：定义 RESTful API 设计规范、端点、请求/响应格式
- **PRD 引用**：F1-001, F2-001, F3-001, F4-001, F5-001, F6-001, F7-001, F8-001, F9-001, F10-001
- **主要内容**：
  - API 设计原则（RESTful, 版本化 `/api/v1/`, 统一响应格式）
  - 认证与授权（JWT）
  - 60+ API 端点定义（认证 / 层级结构 / 计算 / 气象 / 平面图 / 导入导出 / 负荷预测 / 对话采集 / 数据管理 九大类）
  - 请求/响应格式规范
  - 错误码定义

## 使用指南

1. **架构师**：从系统架构设计开始，了解整体架构和技术选型
2. **后端开发**：参考数据库设计，了解数据模型和表结构
3. **前端开发**：参考 API 总览，了解接口规范和数据格式
4. **DBA**：参考数据库设计，优化索引和分区策略
5. **运维工程师**：参考系统架构设计，了解部署方案和环境要求
