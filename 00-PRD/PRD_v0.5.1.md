## 1. 项目背景与版本目标

### 1.1 项目背景

PCB（印制电路板）制造是典型的高耗能、多工序工业过程。一条完整的 PCB 产线涵盖前处理、内层成像（曝光/LDI）、内层蚀刻、压合、钻孔、沉铜（PTH）、电镀、外层成像、图形电镀、蚀刻、阻焊、文字、表面处理（OSP/沉金/喷锡）、成型、测试、FQC、包装等数十道工序。不同工序分布在大量功能区域中，各区域对冷源的需求差异极大。

冷源系统（冷冻机房、冷却塔、空调箱 AHU、风机盘管 FCU、工艺冷却水 PCW）是 PCB 工厂的能耗核心，通常占全厂总能耗的 30%~45%。当前暖通工程师在进行冷源设计时，存在以下核心痛点：

1. **手工 Excel 计算效率低、易出错**：传统冷源设计依赖工程师用 Excel 逐个功能区域手工计算冷负荷，一个项目动辄上百个功能区域，计算量大、重复劳动多、容易出现公式引用错误。
2. **无法量化气象动态影响**：传统方法只考虑国标夏季最不利工况（一个固定值），无法反映全年 8760 小时的负荷变化，导致设备选型偏大、运行能效偏低。
3. **缺乏可视化分析手段**：计算结果只有 Excel 表格，无法在 2D 平面图上直观看到各区域的冷负荷分布，难以快速识别高负荷区域和优化空间。
4. **数据分散、方案对比困难**：设计院提供的 CAD 图纸、计算书、气象数据、国标参数分散在不同文件中；当需要对比不同设计方案时，需要重新计算所有数据。

### 1.2 v0.5 版本定位

v0.5 是平台从零到一的首个可交付版本，覆盖场景故事的**第一至第三阶段**核心流程，形成完整的"设计闭环"：

```
项目创建 → 数据采集 → 2D可视化标注 → 静态冷量计算 → 负荷分析
    → 8760h动态仿真 → 基础验证 → 负荷预测 → 报告导出
```

**不包含**：HIL 半实物仿真（第四阶段）、实时预测与优化服务（第五阶段）。

本系统共 6 个页面，页面间导航关系如下：

```
登录页 ──登录成功──→ 地图首页 ──点击项目──→ 项目工作台 ──楼层详情──→ 2D编辑页
                          │
                          └──导航栏──→ 系统设置页
                          │
                          └──Tab1「对话式采集」入口──→ 对话采集页（独立全屏）
```

#### 页面一：登录页

| 区域 | 内容 |
| --- | --- |
| 顶部导航条 | 左侧：系统名称；右侧：中英文切换、主题切换 |
| 主体左侧 | 公司LOGO或系统图标 + 系统名称 |
| 主体右侧 | 账号输入框 + 密码输入框 + 登录按钮 |

#### 页面二：地图首页

| 区域 | 内容 |
| --- | --- |
| 顶部导航条 | 左侧：系统名称；右侧：搜索框、中英文切换、主题切换、用户名下拉菜单 |
| 主体区域 | 2D地图（Leaflet + 高德地图瓦片），显示所有项目标点 |
| 右侧滑出面板 | 项目摘要卡片（点击标点后展示） |
| 右下角浮动按钮 | "创建新项目"按钮 |

#### 页面三：项目工作台（核心页面，6 个 Tab）

项目工作台是系统的核心操作页面，采用顶部 Tab 切换 + 内容区的布局。顶部始终显示导航条和 6 个 Tab，用户在 Tab 间切换不丢失上下文（左侧树选中的节点保持不变）。

| Tab | 名称 | 职责 | 左侧 | 右侧 |
| --- | --- | --- | --- | --- |
| Tab1 | 基础配置 | 层级管理 + 参数录入 + 触发计算 | 树形导航（项目→建筑→楼层→功能区域） | 选中节点的详情表单 + 底部实时计算预览 |
| Tab2 | 静态计算 | 查看静态计算结果 | 树形导航（同Tab1，联动） | 柱状图/饼图/汇总表 + 按水温分类统计 |
| Tab4 | 动态仿真 | 触发动态仿真 + 查看结果 | 树形导航（同Tab1，联动） | 逐时曲线 + 极值统计 + 多维度对比 |
| Tab5 | 2D展示 | 热力图可视化展示 | 无（全宽展示） | 2D热力图主区域 + 点击色块后的右侧面板 |
| Tab6 | 负荷预测 | 未来7×24小时负荷预测 | 无（全宽展示） | 预测场景管理 + 天气配置 + 生产负荷率 + 预测结果 |

**Tab 间联动关系：**

- Tab1 左侧树选中的节点，在 Tab2/Tab3/Tab4/Tab6 中保持同步（切换 Tab 后自动定位到同一节点）
- Tab1 中点击"计算静态负荷"按钮 → 后台执行计算 → 计算完成后 Tab2 和 Tab5 数据自动刷新
- Tab4 中点击"运行动态仿真"按钮 → 后台执行仿真 → 计算完成后 Tab4 数据自动刷新
- Tab1 中选中楼层节点时，提供"编辑2D平面图"入口按钮 → 跳转到独立的 2D 编辑页

**按钮位置：**

| 按钮 | 所在 Tab | 位置 |
| --- | --- | --- |
| 计算静态负荷 | Tab1 基础配置 | 右侧详情面板顶部工具栏 |
| 运行动态仿真 | Tab4 动态仿真 | 右侧详情面板顶部工具栏 |
| 编辑2D平面图 | Tab1 基础配置 | 选中楼层节点时，右侧详情面板顶部 |
| 导出报表 | Tab2/Tab4 | 右侧详情面板顶部工具栏 |

#### 页面四：2D 编辑页（独立全屏页面）

| 区域 | 内容 |

#### 页面五：系统设置页

| Tab | 名称 | 内容 |
| --- | --- | --- |
| Tab1 | 冷冻水配置 | 项目级冷冻水温度配置 CRUD |

#### 页面六：对话采集页（独立全屏，新增）

| 区域 | 内容 |
| --- | --- |
| 顶部导航条 | 左侧：返回项目工作台；中部：工厂/会话名；右侧：总进度条、保存状态、演示填充、导出 CSV/JSON、新会话 |

### 4.3 关键假设与约束

| 编号 | 假设/约束 |
| --- | --- |
| A1 | 工厂地理位置为可配置参数，系统支持通过城市名选择或手动输入经纬度 |
| A2 | 气象数据来源：外部 API 获取最近连续三年逐时数据，系统缓存避免重复调用；备选方案为手动上传 CSV/EPW 文件 |
| A3 | 静态冷量计算使用国标夏季室外设计参数（最不利工况），代表设计最大冷量需求；动态仿真使用逐时气象数据，自然覆盖全年各季节 |
| A4 | 新风量 = 排风量 + 压差渗透量，**不含卫生新风量与净化风量**——这是有意的工程简化（见 ADR 与 15.2）；对低排风洁净室可能低估新风，v0.6 评估是否引入卫生风量 |
| A5 | 静态建模以"功能区域（Room）"为最小计算单元，不细分到单台设备内部 |
| A6 | 计算的时间分辨率为 1 小时，不考虑分钟级瞬态 |
| A7 | 不考虑冷源侧的输送损失（管网热损暂不计入） |
| A8 | 国标室外参数已整理到 Excel 文件中，系统需内置该数据表（约 300 城市） |
| A9 | 冷冻水温度由项目级自定义，系统预置 7/12°C（低温）和 12/17°C（中温）作为默认值 |
| A10 | PCW（工艺冷却水）作为 ExtraLoad 处理，只有项目级和建筑级，不挂功能区域级 |
| A11 | v0.5 不实现产品→工序→设备链路，功能区域参数由用户直接录入或 Excel 导入 |
| A13 | 末端负荷按功能区域级冷冻水档分配（ADR-0001），默认归入中温档，用户可逐区指定 |

## 5. 模块一：账户与项目管理

### 5.1 功能概述

本模块管理系统的基础组织单元（项目）和用户权限体系（角色），是整个平台的入口与基座。

| 需求 ID | 需求描述 | 优先级 | 验收标准 |

> 说明：本节为 v0.5.1 新增页面，交互范式参照「类 Codex 对话式采集」原型（阶段导航 + 对话主区 + 结构化侧栏）。对话采集与 6.2~6.5 的树形/表单录入是**同一数据模型（项目→建筑→楼层→功能区域 + 区域参数）的两种录入通道**，对话结果直接回写，二者可混合使用、互不覆盖。

#### 6.10.1 页面定位与入口

- 入口：项目工作台 Tab1（基础配置）顶部新增「对话式采集」按钮，点击进入独立全屏对话采集页（布局见 3.1 页面六）。

- 互补：对已在 Tab1 树形/Excel 录入的数据，对话可在缺失节点续采、补缺；对话产出的数据立即在 Tab1 树形详情可见并可复核微调。

#### 6.10.2 六阶段采集 SOP（对话主线）

系统按下列阶段**主动连续提问**，用户以自然语言或快捷芯片作答；每阶段完成后输出结构化摘要确认，再进入下一阶段。

| 阶段 | 采集内容 | 对应现有数据模型 |
| --- | --- | --- |
| ① 产品工艺 | PCB 产品类别（多层板/HDI/IC 载板/柔性板…）、层数、板厚、月产能、工作制度、工艺路线 | 新增「产品工艺」维度（当前树形/Excel 未覆盖，作为项目级元数据） |

## 8. 模块四：静态冷量计算

### 8.1 计算总览

系统的计算分两个阶段，共享末端负荷 Q_terminal 作为桥梁：

```text
末端负荷 Q_terminal --------+---> 静态设计负荷 = Q_terminal + Q_fresh_air_static（一个固定值）
（计算一次，两端复用）      |
                            +---> 动态仿真 Q_dynamic(t) = Q_terminal + Q_fresh_air(t)（约 26280 个逐时值）
```

> 负值与截断统一规则（ADR 修订）：新风负荷可为负（冬季室外焓低于室内）；总负荷 = Q_terminal + Q_fresh_air，**当总负荷 < 0 时截断为 0**（表示该时刻无冷负荷需求）。静态与动态采用同一截断规则。极值统计 Q_min 取 Q > 0 的有意义最小值。

## 15. 核心计算逻辑

本章详细描述系统的核心计算公式和逻辑，是整个系统的技术核心。

### 15.1 末端负荷计算

```
土建负荷 = 土建指标 × 面积 / 1000  (kW)
照明负荷 = 照明指标 × 面积 / 1000  (kW)
人员负荷 = 人员指标 × 人数 / 1000  (kW)，参数为空时取0
电动设备负荷 = 电动设备功率 × 电动设备系数  (kW)
电热设备负荷 = 有排风功率 × 有排风系数 + 无排风功率 × 无排风系数  (kW)

末端负荷 = 土建负荷 + 照明负荷 + 人员负荷 + 电动设备负荷 + 电热设备负荷
```

### 15.2 新风量计算

```
总排风量 = 热排风量 + 酸性排风量 + 碱性排风量 + 有机排风量 + 含尘排风量（空值取0）
压差渗透风量 = 体积 × k(pressure_diff)        ← k 由 8.3 唯一系数表查得（离散点线性插值）
新风量 = 总排风量 + 压差渗透风量
```

- **新风量就是简单加法，不加 MAX 逻辑，不加卫生风量，不加净化风量**（简化见 A4）
- 压差渗透风量系数根据压差绝对值查 8.3 唯一系数表，正/负压对称
- 体积 = 面积 × 吊顶高度

### 15.3 新风冷负荷计算

```
Q_fresh_air = ρ × V_fresh_air × (h_outdoor - h_indoor) / 3600  (kW)
ρ = DefaultConfig.air_density（默认 1.2 kg/m³）
```

- 焓值使用 psychrolib 库计算：calculate_enthalpy(dry_bulb_temp, relative_humidity, atm_pressure)
- 室外焓值：静态计算使用国标夏季室外设计参数；动态仿真使用逐时气象数据
- 室内焓值：使用功能区域的室内计算温度和湿度（空值取默认 26°C / 55%）
- 新风负荷为负值时（冬季/过渡季室外焓值低于室内）：允许负值参与计算
- **总负荷 = 末端负荷 + 新风负荷；总负荷 < 0 时截断为 0**（静态与动态统一）
- 极值统计时 Q_min 只取 Q > 0 的有意义最小值

### 15.4 静态计算与动态仿真的衔接

**末端负荷 Q_terminal 是桥梁**，计算一次，静态和动态共用：

```
静态设计负荷 = Q_terminal + Q_fresh_air_static（一个固定值，用国标夏季参数算室外焓值）
动态仿真负荷 = Q_terminal + Q_fresh_air(t)（约26280个逐时值，用逐时气象数据算室外焓值）
```

- 静态设计负荷使用国标夏季室外设计参数（固定的最不利工况），得到每个功能区域一个固定值
- 动态仿真使用 8760h × 3 年逐时气象数据，自然覆盖全年所有季节
- **不需要季节配置表**——7 月高温和 1 月低温由气象数据本身区分
- 二者总负荷 < 0 时统一截断为 0

### 15.5 按冷冻水温度分类（ADR-0001 修订）

- **末端负荷**：按功能区域的"末端冷冻水档"归入对应分类（默认中温，可逐区指定）
- **新风冷负荷**：单水温模式全部归入该冷冻水分类；两阶段模式按比例分配
- v0.5 中间状态焓值 h_intermediate 待暖通工程师确认，预留接口，先按比例分配

### 15.6 汇总逻辑

- 功能区域级：每个功能区域独立计算
- 楼层级：汇总该楼层所有功能区域
- 建筑级：汇总所有楼层 + 该建筑级的额外负荷（PCW、配电室空调等）
- 项目级：汇总所有建筑 + 项目级的额外负荷

### 15.7 生产负荷率（预留接口）

v0.5 预留 UI 和接口，公式不实现，默认系数 = 1.0。PCW 动态仿真 v0.5 不做。负荷预测（模块十）独立实现生产负荷率多段配置。

### 15.8 负荷预测计算逻辑

负荷预测基于比例系数法，使用静态设计负荷和未来天气预报数据预测逐时冷负荷。

**核心公式：**

```
预测负荷 Q(t) = 静态设计负荷(总负荷) × 比例系数 K(T(t), R(t))
```

其中：
- `静态设计负荷` = 末端负荷 + 新风负荷（来自静态计算结果）
- `T(t)` = 时刻 t 的室外温度（来自天气预报数据）
- `R(t)` = 时刻 t 的生产负荷率（来自用户配置的多段负荷率）
- `K(T, R)` = 比例系数（查 14.8 统一映射表，支持双线性插值）

**计算流程：**

```
对每个功能区域、每个未来时刻 t：
  1. 查天气数据得到室外温度 T(t)
  2. 查生产负荷率配置得到该时刻的负荷率 R(t)
  3. 查统一比例系数映射表得到系数 K(T(t), R(t))
     - 先按温度区间定位行
     - 再按负荷率定位列
     - 非标准值使用双线性插值
  4. 预测负荷 Q(t) = 静态设计负荷 × K
```

**生产负荷率定位：** 用户配置多段负荷率，每段包含生产负荷率数值（10%~100%，步长 10%）和持续时长（小时）。系统根据时刻 t 所在的段，确定该时刻的负荷率 R(t)。

**线性插值示例：** 若室外温度为 20℃，负荷率为 60%：温度 20℃ 在 15~25℃ 区间，负荷率 60% 在 50%~80% 之间 → 比例系数 = 0.7 + (0.9 − 0.7) × (60% − 50%) / (80% − 50%) = 0.7 + 0.2 × 10/30 ≈ 0.767。

**天气数据更新机制：**

| 天气来源 | 更新方式 | 说明 |
| --- | --- | --- |
| API | 每小时自动 | Celery beat 后台定时任务，仅 active 状态场景执行 |
| 手动上传 | 手动触发 | 用户点击"重新计算"按钮 |
