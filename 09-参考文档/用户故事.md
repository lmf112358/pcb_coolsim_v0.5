## Overview

This document details all user stories for PCB-CoolSim v0.5, with acceptance criteria, priority, and traceability to PRD requirements.

## Module 1: Account & Project Management

### US-1.1: Project Map Dashboard

**User Story:**
As an HVAC engineer,
I want to see all my projects on a map,
So that I can quickly locate and access projects.

**Acceptance Criteria:**
- [ ] Map displays all projects user has access to
- [ ] Projects shown as markers with status colors (blue=design, green=active)
- [ ] Clicking marker shows summary card (name, city, buildings, total load)
- [ ] Summary card has "Enter Project" button
- [ ] Map loads in < 3 seconds
- [ ] Search box filters projects by name

**Priority:** P0
**PRD Reference:** F1-009, F1-010, F1-011, F1-014
**Test Cases:** TC-1.3.1 through TC-1.3.4

---

### US-1.2: Project Creation

**User Story:**
As an HVAC engineer,
I want to create a new project with city selection,
So that the system automatically gets local weather data.

**Acceptance Criteria:**
- [ ] Project creation form has required fields: name, city, location
- [ ] City dropdown has ~300 Chinese cities
- [ ] Selecting city auto-fills outdoor design parameters
- [ ] System triggers async weather data fetch after creation
- [ ] Default water temperature configs created (7/12, 12/17)
- [ ] User notified when weather data is ready

**Priority:** P0
**PRD Reference:** F1-015 through F1-022
**Test Cases:** TC-1.2.1 through TC-1.2.5

---

### US-1.3: User Authentication

**User Story:**
As a user,
I want to login with my credentials,
So that I can access the system securely.

**Acceptance Criteria:**
- [ ] Login form with username and password
- [ ] Valid credentials return JWT access + refresh tokens
- [ ] Invalid credentials show error message
- [ ] Access token auto-refreshes before expiry
- [ ] Expired refresh token redirects to login
- [ ] Logout clears tokens

**Priority:** P0
**PRD Reference:** F1-001 through F1-006
**Test Cases:** TC-1.1.1 through TC-1.1.6

---

### US-1.4: Role-Based Access Control

**User Story:**
As a project manager,
I want to control who can access my project,
So that I can manage team permissions.

**Acceptance Criteria:**
- [ ] 4 roles: Admin, PM, Engineer, Viewer
- [ ] PM can invite users to their projects
- [ ] PM can assign roles (Engineer, Viewer)
- [ ] Engineers can edit data in assigned projects
- [ ] Viewers can only view data
- [ ] Users cannot access projects they're not invited to

**Priority:** P0
**PRD Reference:** F1-024 through F1-029
**Test Cases:** TC-1.1.1 through TC-1.1.6

## Module 2: Data Collection

### US-2.1: Hierarchical Navigation

**User Story:**
As an HVAC engineer,
I want to navigate projects using a tree structure,
So that I can organize data by building/floor/room.

**Acceptance Criteria:**
- [ ] Tree shows: Project → Building → Floor → Room
- [ ] Nodes expand/collapse
- [ ] Selecting node shows details in right panel
- [ ] Right-click context menu (Add, Edit, Delete, Copy)
- [ ] Drag-and-drop reordering within same level
- [ ] Search filters tree nodes
- [ ] Virtual scrolling for 1000+ nodes

**Priority:** P0
**PRD Reference:** F2-001 through F2-008
**Test Cases:** TC-2.1.1 through TC-2.1.6

---

### US-2.2: Room Data Entry

**User Story:**
As an HVAC engineer,
I want to enter room parameters (area, temperature, equipment),
So that I can calculate cooling loads.

**Acceptance Criteria:**
- [ ] Form organized in logical sections (Basic, Thermal, Load, Air)
- [ ] Required fields enforced (name, area, height)
- [ ] Auto-calculated fields (volume = area × height)
- [ ] Validation on input (positive numbers, valid ranges)
- [ ] Auto-save every 30 seconds
- [ ] Real-time calculation preview on parameter change

**Priority:** P0
**PRD Reference:** F2-009 through F2-020
**Test Cases:** TC-2.2.1 through TC-2.2.6

---

### US-2.3: Excel Import

**User Story:**
As an HVAC engineer,
I want to import room data from Excel,
So that I can quickly input data from design documents.

**Acceptance Criteria:**
- [ ] Excel template available for download
- [ ] Import validates all fields
- [ ] Errors show row/column location
- [ ] 10,000+ rows import in < 30 seconds
- [ ] Preview before final import
- [ ] Rollback on critical errors

**Priority:** P0
**PRD Reference:** F2-021 through F2-025
**Test Cases:** TC-2.3.1 through TC-2.3.5

## Module 3: 2D Visualization

### US-3.1: Floor Plan Editor

**User Story:**
As an HVAC engineer,
I want to draw room boundaries on a floor plan,
So that I can visualize room locations.

**Acceptance Criteria:**
- [ ] Canvas editor with PDF background import
- [ ] Rectangle drawing tool for rooms
- [ ] Wall drawing tool for boundaries
- [ ] Scale calibration tool
- [ ] Room assignment to drawn polygons
- [ ] Save and return to workbench

**Priority:** P0
**PRD Reference:** F3-001 through F3-010
**Test Cases:** TC-3.1.1 through TC-3.1.5

---

### US-3.2: Heatmap Visualization

**User Story:**
As an HVAC engineer,
I want to see cooling load as a heatmap on the floor plan,
So that I can identify high-load areas visually.

**Acceptance Criteria:**
- [ ] Rooms colored by load value (blue→red gradient)
- [ ] Legend shows load scale
- [ ] Click room to see details
- [ ] Hover shows tooltip with load values
- [ ] 100 rooms render in < 3 seconds
- [ ] Toggle between heatmap and process-code colors

**Priority:** P0
**PRD Reference:** F3-011 through F3-015
**Test Cases:** TC-7.1.1 through TC-7.1.5

## Module 4: Static Calculation

### US-4.1: Static Load Calculation

**User Story:**
As an HVAC engineer,
I want to calculate static cooling loads for all rooms,
So that I can determine equipment sizing.

**Acceptance Criteria:**
- [ ] One-click calculation trigger
- [ ] Calculates: terminal load, fresh air load, total load
- [ ] Results grouped by water temperature tier
- [ ] Comparison with Excel reference (< 0.1% deviation)
- [ ] Progress bar during batch calculation
- [ ] Errors reported with room identification

**Priority:** P0
**PRD Reference:** F4-001 through F4-010
**Test Cases:** TC-4.1.1 through TC-4.2.6

---

### US-4.2: Real-Time Preview

**User Story:**
As an HVAC engineer,
I want to see calculation results immediately when I change parameters,
So that I can understand the impact of changes.

**Acceptance Criteria:**
- [ ] Preview updates within 500ms of parameter change
- [ ] Shows: terminal load, fresh air load, total load, load density
- [ ] Debounced to prevent excessive calculations
- [ ] Cache for unchanged parameters
- [ ] Visual indicator of "calculating" state

**Priority:** P0
**PRD Reference:** F4-011 through F4-013
**Test Cases:** TC-4.3.1 through TC-4.3.3

---

## Module 5: Load Analysis & Cooling Station

### US-5.1: Load Analysis Dashboard

**User Story:**
As an HVAC engineer,
I want to analyze load distribution by category and location,
So that I can understand cooling requirements.

**Acceptance Criteria:**
- [ ] Bar chart: load by category (civil, lighting, equipment, fresh air)
- [ ] Pie chart: load distribution by water tier
- [ ] Treemap: load by building/floor/room
- [ ] Table with sortable columns
- [ ] Filter by building, floor, water tier
- [ ] Export to Excel

**Priority:** P0
**PRD Reference:** F5-001 through F5-010
**Test Cases:** TC-5.1.1 through TC-5.1.5

---

### US-5.2: Cooling Station Configuration

**User Story:**
As an HVAC engineer,
I want to configure chillers and validate sizing,
So that I can ensure the cooling system meets requirements.

**Acceptance Criteria:**
- [ ] Add/edit/delete chillers
- [ ] Configure: type, capacity (RT), count, temperatures
- [ ] Validation rules:
  - N+1 redundancy check
  - Capacity vs load check
  - Part load ratio check
  - Low load warning
  - Water temp match
- [ ] Visual validation results (pass/warn/fail)
- [ ] Multi-plan comparison table

**Priority:** P0
**PRD Reference:** F5-011 through F5-020
**Test Cases:** TC-5.2.1 through TC-5.2.5

---

### US-5.3: P&ID Generation

**User Story:**
As an HVAC engineer,
I want to generate a P&ID system diagram,
So that I can visualize the cooling system layout.

**Acceptance Criteria:**
- [ ] Auto-generate SVG P&ID from chiller configuration
- [ ] Shows: chillers, pumps, pipes, valves
- [ ] Interactive: click component for details
- [ ] Export as SVG/PNG
- [ ] Update when configuration changes

**Priority:** P0
**PRD Reference:** F5-021 through F5-025
**Test Cases:** TC-5.3.1 through TC-5.3.3

## Module 6: Dynamic Simulation

### US-6.1: Weather-Driven Simulation

**User Story:**
As an HVAC engineer,
I want to run dynamic simulation using hourly weather data,
So that I can see annual load variations.

**Acceptance Criteria:**
- [ ] Simulation options: weather-driven or coefficient method
- [ ] Select years to simulate (1-3 years)
- [ ] Scope: all buildings or selected building/rooms
- [ ] Async execution with progress tracking
- [ ] Results: hourly load for 8760h × N years
- [ ] Completion notification via WebSocket

**Priority:** P0
**PRD Reference:** F6-001 through F6-010
**Test Cases:** TC-6.1.1 through TC-6.1.5

---

### US-6.2: Simulation Results

**User Story:**
As an HVAC engineer,
I want to view simulation results with interactive charts,
So that I can analyze load patterns.

**Acceptance Criteria:**
- [ ] Line chart: hourly load over time
- [ ] Zoom levels: year → month → day
- [ ] Tooltip shows: datetime, outdoor temp, load
- [ ] Statistics: max, min, average, total energy
- [ ] Duration curve: hours at each load level
- [ ] Export to CSV

**Priority:** P0
**PRD Reference:** F6-011 through F6-015
**Test Cases:** TC-7.1.1 through TC-7.2.4

## Definition of Done

A user story is **done** when:

- [ ] All acceptance criteria met
- [ ] Code reviewed and approved
- [ ] Unit tests written and passing
- [ ] Integration tests passing
- [ ] Documentation updated
- [ ] No critical/high defects
- [ ] Product owner accepted
- [ ] Deployed to staging
