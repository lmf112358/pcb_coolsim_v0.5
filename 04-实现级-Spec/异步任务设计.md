## 1. 概述

长耗时操作（动态仿真、报告导出、批量静态计算、气象拉取）以 **Celery + Redis** 异步执行，避免阻塞 API 响应。本文档定义：

- Celery + Redis 任务架构与 app 内任务分布；
- 任务接口签名与入参；
- 实现规范（任务状态机、进度回传、失败重试与超时）；
- 任务监控与 WebSocket 进度推送（对接 API 11）。

**强制约束**：所有异步任务对同一份输入必须**幂等**——重复入队或 worker 重试不得产生重复/错误结果（以唯一业务键 upsert 或 skip）。

## 2. 任务架构（Celery + Redis）

### 2.1 基础设施

- **Broker**：Redis（list/stream），承载任务分发。
- **Result Backend**：Redis，仅存任务终态与元信息（不存大体量结果）。
- **WS 通道**：Django Channels + Redis Channel Layer，用于任务进度推送。
- 配置见架构 8.1（docker-compose 含 redis + celery worker）。

### 2.2 任务分布（按 app）

| 任务（name） | 所在 app / 模块 | 触发方 | 对应需求 |
|--------------|----------------|--------|---------|
| calculate_project_static | calculations/tasks.py | StaticLoadService.calculate_project | F4-001（批量，API 7.2） |
| run_dynamic_simulation | simulations/tasks.py | DynamicSimulationService.start_simulation | F6-001（API 7.4） |
| export_static_report | exports/tasks.py | ReportExportService.export_static_report | F8-001（API 9.1） |
| export_equipment_list | exports/tasks.py | ReportExportService.export_equipment_list | F8-001（API 9.2） |
| export_calculation_book | exports/tasks.py | ReportExportService.export_calculation_book | F8-001 |

## 3. 任务接口定义

### 3.1 动态仿真（F6-001）

```python
# simulations/tasks.py
from celery import shared_task
from asgiref.sync import async_to_sync
from channels.layers import get_channel_layer

@shared_task(bind=True, queue="simulation",
             max_retries=2, soft_time_limit=600, time_limit=900)
def run_dynamic_simulation(self, *, project_id: int,
                            simulation_type: str,
                            years: list[int], start_date: str,
                            building_ids: list[int] | None = None,
                            room_ids: list[int] | None = None) -> dict:
    """逐时动态仿真（8760h x N 年）。
    入参全部为可序列化基础类型（Celery 不传 ORM 对象）。
    返回 {success, project_id, total_hours, total_rooms}。"""
```

## 4. 实现规范

### 4.1 任务状态机

Celery 内置状态 + 自定义 PROGRESS，状态流转：

```
PENDING  --(worker 接收)-->  STARTED
STARTED  --(处理中, 周期性)-->  PROGRESS (自定义, 携带 progress/total)
PROGRESS --(正常结束)-->  SUCCESS
PROGRESS --(异常且耗尽重试)-->  FAILURE
STARTED  --(异常且耗尽重试)-->  FAILURE
任意态   --(被撤销)-->  REVOKED
```

- **PENDING**：已入队未执行（API 返回 task_id 后即此态）。
- **STARTED**：worker 开始执行（Celery 需 task_track_started=True）。
- **PROGRESS**：通过 self.update_state(state="PROGRESS", meta={...}) 上报进度（非终止态）。
- **SUCCESS / FAILURE**：终态，结果写入 Redis backend。

### 4.2 进度回传 WebSocket（对接 API 11）

WebSocket 订阅地址：`ws://<host>/ws/tasks/{task_id}/`（API 11.1）。Worker 用 Channel Layer 向 group `tasks_{task_id}` 推送三类消息，**字段与 API 11 严格一致**：

```python
def _notify(task_id: str, payload: dict):
    layer = get_channel_layer()
    async_to_sync(layer.group_send)(f"tasks_{task_id}", payload)

# 进度（对应 API 11.1 progress）
_notify(task_id, {
    "type": "progress",
    "data": {
        "task_id": task_id, "status": "processing",
        "progress": 45, "total_items": 135, "completed_items": 61,
        "current_item": "Processing room: 电镀车间",
        "message": "Calculating static load for room 61/135",
    },
})

# 完成（对应 API 11.1 completed）
_notify(task_id, {
    "type": "completed",
    "data": {
        "task_id": task_id, "status": "completed",
        "result_url": "/api/v1/calculations/static/1/",
        "message": "Static calculation completed for 135 rooms",
    },
})

# 错误（对应 API 11.1 error）
_notify(task_id, {
    "type": "error",
    "data": {
        "task_id": task_id, "status": "failed",
        "error": {"code": "CALCULATION_ERROR",
                  "message": "Invalid parameters for room ID 45", "room_id": 45},
    },
})
```

> 动态仿真完成消息 result_url 用 `/api/v1/calculations/dynamic/{project_id}/`（API 7.5）。

### 4.3 仿真 / 导出任务的持久化边界（重要）

任务**只通过 WebSocket / Redis result backend 回传进度与终态**；其计算结果落库目标在 PRD v0.5.1 的 15 张表中**未定义**（见 6 待确认）。在存储表确定前：

- **动态仿真**：在大体量与表未定义前，任务**不写业务结果表**，仅回传聚合并行结果（max/min/avg/total_energy 等汇总指标）于 SUCCESS 的 meta 中；如需逐时明细，待 simulation_result 表定义后补写（见 6）。
- **报告导出**：任务将文件写入对象存储（MinIO/S3，架构 2.2），仅回传可下载 URL（API 9.3 由 ReportExportService.download 取回）；文件元数据表未定义，列为待确认。
- **批量静态计算**：结果写入 15 张表内已定义的 room_load_result / room_air_volume_result / room_load_summary / load_summary（确定可落库）。

## 5. 失败重试与超时

### 5.1 重试

- 用 `@shared_task(bind=True, max_retries=N)`，异常分支 `raise self.retry(exc=e, countdown=backoff)`。
- **可重试错误**：Redis 抖动、DB 瞬时连接失败、外部气象 API 超时——指数退避（countdown = 2 ** self.request.retries）。
- **不可重试错误**：参数非法（CalculationError / ValidationError）、除零、唯一约束冲突——直接 raise，转 FAILURE，不发 retry。
- 重试时仍需推送 `error`/PROGRESS，保证前端可见；最终 FAILURE 推送 API 11.1 error 消息。

### 5.2 超时

| 任务 | soft_time_limit | time_limit | 行为 |
|------|----------------|-----------|------|
| run_dynamic_simulation | 600s | 900s | soft 触发 SoftTimeLimitExceeded -> 清理并 FAILURE；hard 强杀 |
| export_* | 300s | 600s | 同上 |
| calculate_project_static | 300s | 600s | 同上 |
| fetch_weather_data | 120s | 180s | 同上 |

soft_time_limit 内捕获 `SoftTimeLimitExceeded` 做资源清理与友好 FAILURE；time_limit 为硬上限，超时 worker 直接终止进程（需 worker 配置 `--time-limit`）。

## 6. 任务监控与可观测性

- **进度查询**：前端订阅 WebSocket（首选）；后端可经 Celery `AsyncResult(task_id).state/result` 读 Redis backend 终态（不轮询 DB）。
- **Worker 监控**：Flower / `celery -A config inspect active`；告警规则见架构 9.3（失败率 > 10% 触发 Critical）。
- **日志**：每个任务以 task_id 为 logger 前缀，记录 start/fail/success 与关键里程碑（INFO 级），便于排障。
- **队列隔离**：simulation / export / calc / io 分队列，避免重计算阻塞导出（见 2.2）。
