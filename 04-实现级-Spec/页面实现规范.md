## 1. 概述

本文档是「实现级 Spec」的前端页面部分，面向**前端工程师直接编码**。它给出每个页面的**组件树结构、状态管理方案、API 调用时机、加载态/错误态/空态**处理，落地到可编码程度（含组件骨架与 React Query hook 签名）。

技术栈基线（与前序文档一致）：

- 框架：React 18 + TypeScript
- 服务端状态：React Query（TanStack Query v5）
- 客户端 UI 状态：React Context（见《状态管理实现.md》）
- 基础组件库：Ant Design 5（24 栅格、表单、表格、模态、消息）
- 图表：ECharts 5.x（折线/面积/柱状/饼图/树图/持续时间曲线）
- 2D 画布：Fabric.js（编辑与查看渲染）
- 地图：Leaflet 1.9 + 高德/OSM 瓦片

页面集合（共 6 个页面；工作台内 5 个 Tab）：

| 页面 | 路由建议 | 入口 | 锚点 |
|------|----------|------|------|
| 登录页 | `/login` | 应用启动 | - |
| 地图首页 | `/map` | 登录成功 | - |
| 项目工作台 | `/project/:projectId` | 点击地图项目 | 5 个 Tab |
| 2D 编辑页 | `/project/:projectId/floor/:floorId/editor` | 工作台 Tab1 选中楼层→编辑 2D | F3-001~F3-013 |
| 对话采集页（Page 6） | `/project/:projectId/conversation` | 工作台 Tab1 顶部「对话式采集」按钮 | F2-046~F2-061 |
| 系统设置页 | `/settings` | 导航条设置图标 | F9-001~F9-015 |

> 全局约束：禁止把「冷站配置 / Cooling Station / P&ID / 水蓄冷」当作模块描写（PRD v0.5.1 已移除，仅保留负荷分析）。工作台 Tab 编号遵循本分支锚点——基础信息 / 静态冷量 / 动态仿真 / 2D 可视化 / 负荷分析；PRD §3.1 中的「Tab3」因冷站移除已不存在，故不实现。

## 2. 全局实现约定（所有页面共享）

### 2.1 路由与布局骨架

```
<App>
  <ThemeProvider>          // 暗/浅主题（Context，见状态管理实现）
  <LocaleProvider>         // i18n（zh/en）
  <AuthGuard>              // 未登录跳转 /login，token 过期自动 refresh
    <QueryClientProvider>  // React Query 根
      <Router>
        <LoginPage/>            // 独立布局，无导航条
        <MapHomePage/>          // 含 NavBar
        <ProjectWorkbench/>     // 含 NavBar + TabBar + 树 + 内容
        <Floor2DEditorPage/>    // 独立全屏，无 NavBar
        <ConversationPage/>     // 独立全屏三栏（Page 6）
        <SettingsPage/>         // 含 NavBar
```

### 2.2 加载态 / 错误态 / 空态基线

所有依赖 React Query 的页面统一遵循：

- **加载态**：首屏用 `Skeleton`（匹配布局骨架，脉冲动画）；局部用 `Spin`（居中，可选文案）。见设计系统 §8.1。
- **错误态**：`error` 分支渲染错误卡片 + `重试` 按钮（调用 `refetch()`）；瞬时错误用 `message.error` / `notification`（设计系统 §8.3）。
- **空态**：`Empty` 组件 + 引导操作（如「+ 新建」），见设计系统 §8.2。

统一错误拦截：在 `QueryClient` 的 `queryFn` 外层包 `handleApiError`，将 `{error:{code,message,details}}` 翻译为 i18n 文案并弹出 `notification`（关键错误）/ `message`（瞬时错误）。

### 2.3 组件树约定记号

本规范用缩进表示父子关系；`(hook)` 表示该组件内部消费 React Query；`(ctx)` 表示消费 Context；`[props]` 表示来自父级的 props 注入。

## 3. 登录页（/login）

### 3.1 组件树

```
<LoginPage>
  <LoginLayout>                      // 左 Logo 区 / 右表单区（设计系统 §2.1）
    <BrandPanel/>
    <LoginForm (ctx: theme, locale)>
      <Input username/>
      <Input.Password password/>
      <Checkbox rememberMe/>
      <Button submit (hook: useLoginMutation)/>
      <Link forgotPassword/>
```

### 3.2 状态管理方案

- 本地 `useState`：`username / password / rememberMe / loading`。
- 提交：`useLoginMutation()`（React Query `useMutation`），成功后写入 `AuthContext`（`setTokens`）并 `navigate('/map')`。
- `rememberMe`：存入 `localStorage` 用户名（设计系统 §2.3）。

### 3.3 API 调用时机

| 时机 | 调用 | 说明 |
|------|------|------|
| 提交表单 | `POST /api/v1/auth/login/` | 校验：用户名≥3 字符、密码≥6 字符（页面总览 §2.4）；失败 `message.error` |
| `useTokenRefreshMutation` | `POST /api/v1/auth/refresh/` | 401 且存在 refresh_token 时自动调用（见状态管理实现 §3.4） |

### 3.4 加载 / 错误 / 空态

- 加载：按钮内 `Spin` + disabled。
- 错误：`message.error`（5s 自动消失，设计系统 §2.2）。
- 无空态。

## 4. 地图首页（/map）

### 4.1 组件树

```
<MapHomePage (ctx: auth, theme, locale)>
  <NavBar/>
  <MapContainer (hook: useProjects)>
    <LeafletMap>
      <ProjectMarker/> × N        // 状态着色（绿/蓝/灰，页面总览 §3.2）
    <ProjectSummaryCard (hook: useProjectSummary)/>  // 点击 marker 滑出
    <SearchBox (debounce 300ms)/>  // 下拉结果，点击定位
    <NewProjectFab/>               // 右下浮动按钮
  <NewProjectModal (hook: useCreateProjectMutation)/>
```

### 4.2 状态管理方案

- `useProjects()`：列表查询，支持 `search / status` 过滤。
- 选中 marker：`useState<number|null>` 本地态驱动 `ProjectSummaryCard`。
- 新建项目：`useCreateProjectMutation`，成功后 `invalidateQueries(['projects'])` 并打开天气加载态。

### 4.3 API 调用时机

| 时机 | 调用 | 说明 |
|------|------|------|
| 进入页面 | `GET /api/v1/projects/` | 分页 + 搜索；marker 渲染 |
| 点击 marker | `GET /api/v1/projects/{id}/`（摘要） | 滑出卡片 |
| 搜索输入（防抖 300ms） | `GET /api/v1/projects/?search=` | 结果下拉 |
| 双击 marker / 点「进入」 | - | `navigate('/project/{id}')` |
| 创建项目 | `POST /api/v1/projects/` | 触发异步天气拉取（Celery），返回 `weather_task_id`；轮询或 WebSocket 通知 `weather_data_status` 变 `available` 后刷新卡片 |
| 城市选择 | - | 自动填充室外设计参数（模块一 §4.2） |

### 4.4 加载 / 错误 / 空态

- 加载：地图底图加载用 `Spin` 遮罩；marker 区域 `Skeleton`。
- 错误：天气拉取失败 → `notification.warning`（不阻断进入工作台）。
- 空态：无项目时地图中央 `Empty` + 「+ 新建项目」。

## 5. 项目工作台（/project/:projectId）

工作台是核心页面，包含外壳（NavBar + TabBar + 左侧树 + 右侧内容）。5 个 Tab 共享同一棵层级树与当前选中态。

### 5.1 外壳组件树

```
<ProjectWorkbench (ctx: selection, theme, locale) (hook: useProject, useProjectTree)>
  <NavBar/>
  <WorkbenchHeader>  // 返回地图 + 项目名
  <TabBar tabs=[基础信息,静态冷量,动态仿真,2D可视化,负荷分析]/>
  <div layout>
    <TreePanel (hook: useProjectTree) (ctx: selection)>   // Tab1/2/3 可见；Tab4/5 隐藏
      <TreeSearch (debounce)/>
      <HierarchyTree/>    // 项目→建筑→楼层→功能区域（四级虚拟滚动）
    <ContentArea>
      <Tab1BasicConfig/> | <Tab2StaticCalc/> | <Tab3DynamicSim/>
      <Tab4Heatmap/>      | <Tab5LoadAnalysis/>
  <ConversationEntryButton/>   // Tab1 顶部「对话式采集」入口
```

### 5.2 状态管理方案（外壳）

- 当前选中节点：`SelectionContext`（项目/建筑/楼层/房间 ID + 层级类型），见状态管理实现 §4。
- 当前 Tab：`useState<WorkbenchTab>` 本地态（或 URL query `?tab=` 持久化，刷新不丢）。
- `useProjectTree(projectId)`：四级层级查询，支持树内增删改后失效刷新。
- **Tab 间联动**：切换 Tab 保留 `SelectionContext`；Tab2/3/4/5 复用同一选中节点自动定位（页面总览 §4.2、PRD §3.1「切换 Tab 不丢失上下文」）。

### 5.3 API 调用时机（外壳）

| 时机 | 调用 | 说明 |
|------|------|------|
| 进入工作台 | `GET /api/v1/projects/{id}/` + `GET /api/v1/projects/{id}/tree/` | 项目元信息 + 四级树 |
| 选择树节点 | - | 更新 `SelectionContext`；各 Tab 据此拉取自身数据 |
| 切换 Tab | - | 仅渲染对应 Tab 内容组件，触发该 Tab 的查询 |

### 5.4 加载 / 错误 / 空态（外壳）

- 加载：Tree 用 `Skeleton`；内容区随 Tab 各自加载态。
- 错误：树加载失败 → `Empty` + 重试；项目不存在（404）→ 错误页 + 返回地图。
- 空态：树无节点 → `Empty` + 「+ 新建建筑/楼层」引导（视层级）。

## 6. Tab1 基础信息（Basic Configuration）

### 6.1 组件树

```
<Tab1BasicConfig (ctx: selection) (hook: useRoom, useRoomPreview, useCalcStaticMutation)>
  <DetailForm>
    <SectionBasicInfo/>     // 房间名/编号/面积/层高/体积(自动)
    <SectionThermalReq/>    // 设计温湿度(展示)/计算温湿度/洁净度
    <SectionLoadParams/>    // 土建/照明/人员/设备/排风加热 等指标
    <SectionAirVolume/>     // 各类排风/总排风(自动)/压差
    <SectionWaterConfig/>   // 末端冷冻水档（下拉：低/中温）
    <AutoSaveIndicator/>    // 30s 自动保存（设计系统 §8.5）
    <ActionToolbar>
      <Button 编辑2D (disabled 未选楼层)/>
      <Button 计算静态负荷 (hook: useCalcStaticMutation)/>
      <Button 保存 (hook: useSaveRoomMutation)/>
      <Button 对话式采集 (navigate Page6)/>
  <CalcPreviewPanel (hook: useRoomPreview)/>  // 底部 sticky，实时预览
```

### 6.2 状态管理方案

- 表单：`useForm`（Ant Design）受控；初始值来自 `useRoom(roomId)`。
- 实时预览：`useRoomPreview(roomId, paramsHash)`（防抖 500ms），见状态管理实现 §3.2。
- 自动保存：监听表单 dirty，`debounce` + 定时 30s 调 `useSaveRoomMutation`，`AutoSaveIndicator` 显「Saving…→Saved」。
- 计算：点击「计算静态负荷」→ `useCalcStaticMutation`，成功后失效 `staticResults / heatmap` 查询，并 `notification.success`。

### 6.3 API 调用时机

| 时机 | 调用 | 说明 |
|------|------|------|
| 选中房间节点 | `GET /api/v1/rooms/{id}/` | 填充表单 |
| 参数变更（防抖 500ms） | `POST /api/v1/calculations/preview/` | 单节点增量预览（F4-034）；校验失败返回错误，不计算（F4-037） |
| 点击保存 / 自动保存 | `PUT /api/v1/rooms/{id}/` | 乐观更新 `useRoom` 缓存（状态管理实现 §3.3） |
| 点击计算静态负荷 | `POST /api/v1/rooms/{id}/calculate-static/` 或批量 `POST /api/v1/calculations/batch/` | 后台任务；WebSocket 进度；完成刷新结果 |
| 编辑 2D（已选楼层） | - | `navigate('/project/{pid}/floor/{fid}/editor')` |
| 对话式采集 | - | `navigate('/project/{pid}/conversation')` |

### 6.4 加载 / 错误 / 空态

- 加载：表单 `Skeleton`；预览面板 `Spin`。
- 错误：字段校验失败 → 行内 `ValidateStatus.error`（设计系统 §8.3）；保存失败 → `message.error` + 保留表单。
- 空态：未选节点 → 内容区 `Empty`（提示选择左侧树节点）；选中建筑/楼层节点 → 展示其汇总（聚合已有结果，非全量重算，F4-036）。

## 8. Tab3 动态仿真（Dynamic Simulation）

### 8.1 组件树

```
<Tab3DynamicSim (ctx: selection) (hook: useSimulation, useSimulationHourly, useRunSimMutation)>
  <SimStatusBar/>                 // 状态/最后运行时间/进度
  <RunSimDialog (hook: useRunSimMutation)/>  // 类型/年份/范围
  <StatCards/>                    // 峰值/谷值/均值/总能耗
  <LoadCurveChart (hook: useSimulationHourly)/>   // 8760×3 逐时曲线（F7-001）
  <DurationCurveChart/>           // 负荷持续时间曲线（F7-022）
  <Toolbar> <ExportCSV/> </Toolbar>
```

### 8.2 状态管理方案

- `useSimulation(projectId, batchId)`：仿真汇总（极值、能耗）。
- `useSimulationHourly({projectId, roomId?, year, month, aggregation})`：逐时数据，前端按可视宽度 LTTB 降采样（F7-012~F7-016）。
- 运行：`useRunSimMutation` → 返回 `task_id` + `websocket_url`；订阅 WebSocket 进度；完成 `invalidateQueries(['simulation'...])`。

### 8.3 API 调用时机

| 时机 | 调用 | 说明 |
|------|------|------|
| 进入 Tab | `GET /api/v1/calculations/dynamic/{projectId}/` | 取最近批次汇总 |
| 运行仿真 | `POST /api/v1/projects/{id}/simulate/` | 校验气象数据缺失则提示先获取（F6-021） |
| 曲线渲染 | `GET .../hourly-data/` 或按粒度聚合端点 | 带 year/month/aggregation；首屏全量拉后前端降采样 |
| 缩放/切换粒度 | - | 本地 state 变更重取或前端重采样 |

### 8.4 加载 / 错误 / 空态

- 加载：曲线 `Spin` + 骨架；长任务显示进度条（已计算/总数）。
- 错误：气象缺失 → `notification.warning` + 引导去设置页获取；任务失败 → `notification.error`。
- 空态：**未运行** → `Empty`（「请点击『运行动态仿真』」）；不支持 Tab 内无数据时不渲染图表。

## 9. Tab4 2D 可视化（Heatmap，F3-014~F3-024）

### 9.1 组件树

```
<Tab4Heatmap (ctx: selection) (hook: useFloorPlan, useHeatmapData)>
  <FloorSelector/>                // 切换楼层
  <HeatmapCanvas (Fabric.js)/>     // 外墙+色块+比例尺+指北针+图例

  <LayerToggle/> <Legend (连续/5级)/> <ModeSwitch (总/末端/新风/冷指标)/>

```

### 9.2 状态管理方案

- `useFloorPlan(floorId)`：平面图 JSON（outline/blocks/scale/compass，PRD §7.4）。
- `useHeatmapData(floorId, mode)`：各 block 的负荷值（按模式：总/末端/新风/冷指标）。
- 模式/楼层切换：本地 state → 重取 `useHeatmapData`。

### 9.3 API 调用时机

| 时机 | 调用 | 说明 |
|------|------|------|
| 进入 Tab / 切楼层 | `GET .../floors/{id}/plan/` + 负荷聚合端点 | 平面图 + 着色数据 |
| 冷量更新后 | - | 失效 `useHeatmapData` 实现 <1s 刷新（F3-024） |
| 点击色块 | - | 本地选中态 → `DetailPanel` 拉该房间明细 |

### 9.4 加载 / 错误 / 空态

- 加载：画布 `Spin`；100 区块渲染目标 <3s（F3-023），用 Fabric.js 批量渲染 + 离屏缓冲。
- 错误：平面图缺失 → `Empty`（「该楼层尚未在 2D 编辑页绘制平面图」）。
- 空态：无关联房间 → 灰块标「未关联」（F3-019）。

### 10.3 API 调用时机

| 时机 | 调用 | 说明 |
|------|------|------|
| 进入 Tab | 负荷分析 + 预测场景列表查询 | - |
| 新建场景 | `POST /api/v1/forecasts/scenarios/` | 默认 7 天、一段 100% 负荷率（F10-013） |
| 选场景/版本 | `GET .../forecasts/{scenarioId}/?version=` | 预测结果 |
| 天气 API 模式 | 每小时 Celery beat 自动更新（active 场景）；手动刷新按钮 | 显示最后更新时间（F10-007） |
| 手动 CSV | `POST` 上传 → 重新计算 | - |
| 导出 | `POST /api/v1/exports/...` 或预测 CSV 端点 | - |

### 10.4 加载 / 错误 / 空态

- 加载：图表 `Skeleton`；预测曲线 `Spin`。
- 错误：天气获取失败 → `notification.warning`；预测计算异常 → `message.error`。
- 空态：无场景 → `Empty` + 「+ 新建预测场景」；场景无结果 → 「点击重新计算」。

### 11.3 API 调用时机

## 12. 对话采集页（Page 6，F2-046~F2-061）

> 入口：Tab1 顶部「对话式采集」按钮 → 独立全屏三栏（PRD §3.1 页面六、§6.10）。视觉严格复用设计系统色板/字体/间距/主题/i18n（设计系统 §5.9），不另立设计语言。

### 12.1 组件树

```
<ConversationPage (ctx: selection, theme) (hook: useConversationSession, useSendMessageMutation)>
  <NavBar variant=conversation>   // 返回 / 会话名 / 总进度条 / 保存态 / 导出 / 新会话
  <StageNav (hook: useConversationSession)/>   // 六阶段 ①~⑥，状态点（未/当前/已完成）
  <ChatMain>
    <MessageList> <BubbleSystem/> <BubbleUser/> <SummaryCard/> <ToolCard/> </MessageList>
    <Composer> <Input (Enter 发送)/> <ChipRow (快捷芯片)/> </Composer>
  <StructuredPreview (hook: useConversationSession)/>  // 实时数据树 + 当前区域摘要 + 缺失项
```

### 12.2 状态管理方案

- `useConversationSession(projectId)`：拉取 `conversation_session`（current_stage / stage_status / draft_payload），断点续采恢复（F2-057）。
- 聊天流：消息数组本地 `useState` + 服务端回显；`useSendMessageMutation` 发送用户作答，返回 `assistant_message + extracted_fields + next_stage?`。
- 阶段切换：点已完成节点跳转 → `PATCH stage` 持久化（F2-047/58）。
- 结构化预览：订阅 `draft_payload` 实时派生数据树（右侧栏，F2-053）。

### 12.3 API 调用时机（候选契约，待确认，见 §13）

| 时机 | 调用 | 说明 |
|------|------|------|
| 进入页面 | `GET /api/v1/projects/{id}/conversation/session/` | 取会话状态；无则初始化① |
| ① 展示确认 | 仅展示已关联城市/气象（地图页已拉取），不重复请求（F2-054） | - |
| 每阶段完成「保存」 | `PATCH /api/v1/projects/{id}/conversation/stage/` | 写 `draft_payload` + `current_stage`（逐区域提交即落库，F2-060） |
| 用户发送作答 | `POST /api/v1/projects/{id}/conversation/message/` | 意图抽取→字段回写同源模型 |
| ⑥ 汇总确认 | `POST .../conversation/confirm/` | 标记区域/项目完成，room.status: draft→active（F2-058） |
| 断点续采 | 复用 `GET session`（服务端持久化） | 刷新/重开从 `current_stage` 恢复（F2-057） |
| 导出 | `GET .../conversation/export/?fmt=csv|json` | 与模块八对齐（F2-059） |

### 12.4 加载 / 错误 / 空态

- 加载：消息流首屏 `Skeleton`；`ToolCard` 异步结果用状态点（进行中=主色/成功=OK/失败=危险，设计系统 §5.9）。
- 错误：意图抽取失败 → `BubbleSystem` 提示「未理解，请换种说法或选择芯片」；保存失败 → `message.error`。
- 空态：无对话 → 系统首条提问气泡（①阶段展示确认）；缺失项 → 右侧栏 Warning 语义色提示（F2-053）。
