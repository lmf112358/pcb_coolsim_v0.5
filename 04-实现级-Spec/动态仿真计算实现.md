## 1. 文档概述

### 1.1 目的

定义 PCB 冷量仿真系统「动态仿真负荷计算（模块六）」的核心计算逻辑，覆盖两种仿真方式（气象数据驱动、比例系数法）的逐时算法、8760h 主循环、与静态计算的衔接，以及输入/输出字段映射。与《静态冷量计算实现.md》配套：静态计算产出 Q_terminal（末端负荷）、V_fresh_air（新风量）等"固定量"，动态仿真在此基础上让新风负荷随逐时气象变化（F6-004、F6-005）。

### 1.2 适用范围

- 方式一：气象数据驱动仿真（F6-001~F6-007），精度要求与独立脚本验算偏差 < 1%（G3）
- 方式二：比例系数法仿真（F6-008~F6-011），近似法，无精度验收
- 逐时主循环与批次管理（F6-016~F6-019）
- 性能边界：8760h × 3 年 × 1000+ 功能区域 < 30 秒（G4 / F6-016）

### 1.3 确定性等级定义

| 等级 | 标记 | 含义 |
|------|------|------|
| 已确认 | ✅ | 公式来源明确，经 psychrolib / PRD 确认，可直接实现 |
| 部分确认 | ⚠️ | 公式框架已有，部分参数待确认，可实现框架 + 占位 |
| 待确认 | ❓ | 公式或表结构未定，代码中留接口占位，待后续补充 |

### 1.4 与《静态冷量计算实现.md》的衔接

动态仿真**完全复用**静态计算的以下产物与函数，不重新实现：

| 复用项 | 来源（静态文档） | 动态仿真中的角色 |
|---|---|---|
| `calculate_enthalpy()` 焓值函数 | §3.1.0 | 方式一逐时室外焓值、室内恒定焓值 |
| `RoomCalcResult.terminal_load` | §3.2 / §3.5 | Q_terminal，全年固定（设计工况） |
| `RoomCalcResult.fresh_air_volume` | §3.3 | V_fresh_air，全年固定（设计工况） |
| 负值截断规则 | §3.4 / F4-014 | 新风负荷可负、总负荷 < 0 截断为 0（F6-006，与静态统一） |
| 公式可替换架构（CalcStep 接口、桩模式） | §5 | 动态仿真沿用相同接口 `execute(context) → dict` |

关键差异：静态计算按 `room_id × season_id` 产出单值；动态仿真按 `room_id × hour(t)` 产出 8760×N 条序列，室内焓值全年恒定、仅室外焓值逐时变化。

## 2. 仿真算法总览

### 2.1 两种仿真方式对比

| 维度 | 方式一：气象驱动 | 方式二：比例系数法 |
|---|---|---|
| 输入 | WeatherRecord 逐时气象（3 年） | 统一比例系数表（ADR-0003）+ 静态负荷 |
| 公式 | Q(t)=Q_terminal+ρ·V·(h_out(t)−h_in)/3600 | Q(t)=Q_static×k(t) |
| 精度 | < 1%（G3 验收） | 近似，无精度验收 |
| 计算量 | 大（需逐时焓值） | 小（查表） |
| 降级 | 无气象则提示先获取（F6-021） | 无气象用国标夏季设计温度（F6-011） |
| PRD | F6-001~F6-007 | F6-008~F6-011 |

### 2.2 主循环数据流

```
project_id, years=[y1,y2,y3], water_temp_config_id(s), simulation_type
        │
        ▼
┌─────────────── 加载静态固定量（一次性）──────────────┐
│  rooms: room_id, indoor_calc_temp/humidity,            │
│         terminal_load(Q_terminal),                    │
│         fresh_air_volume(V_fresh_air)                 │
│  water_temp_config: supply_temp / return_temp          │
│  (方式二) 统一比例系数表 k = f(outdoor_temp, 100%)      │
└───────────────────────────┬──────────────────────────┘
                            ▼
┌───────────── 逐时主循环 (hour t = 0 .. 26279) ─────────────┐
│  方式一: h_out(t)=calc_enthalpy(weather[t])                 │
│          Q_fresh(t)=ρ·V_fresh·(h_out(t)−h_in)/3600         │
│  方式二: k(t)=lookup(outdoor_temp[t]); Q(t)=Q_static·k(t)   │
│  Q_total(t)=Q_terminal + Q_fresh(t); 截断 Q_total<0→0      │
│  写入 DynamicLoadHourly(room_id, t, Q_fresh,Q_total,...)   │
└───────────────────────────┬──────────────────────────┘
                            ▼
        按区域/水温/时段聚合 → LoadSummary 逐时序列（见 8760h 数据处理实现.md）
```

### 2.3 数据组织维度

- 主键维度：`project_id × calc_batch_id × room_id × timestamp`
- 水温维度：`water_temp_config_id`（方式一默认 h_s 定义 A，见静态 §3.4.1，各水温 fresh_air_load 由同一 h_out 推得）
- 区域维度：`room → floor → building → project`，聚合见《8760h 数据处理实现.md》

## 3. 方式一：气象数据驱动仿真算法（F6-001~F6-007）

**确定性：✅ 已确认（焓值函数复用 psychrolib）；⚠️ 部分确认（h_s 定义 A/B，v0.5 默认 A）**

### 3.1 气象数据获取（F6-001）

输入来源 `WeatherRecord` 表（PRD F4-046 命名；静态规范 §6.4 别名 `weather_hourly`，表名待确认统一）。每城市缓存最近连续 3 年逐时数据，闰年 8784 / 平年 8760，总量约 26280~26304 条。

| 数据库表.字段 | 说明 | 用途 |
|---|---|---|
| WeatherRecord.city_id | 城市 | 关联项目城市 |
| WeatherRecord.datetime | 时间戳 | 逐时索引 t |
| WeatherRecord.temp_dry | 干球温度(℃) | 室外焓值输入 / 方式二查表 |
| WeatherRecord.temp_wet | 湿球温度(℃) | 室外焓值输入（input_type='wb'） |
| WeatherRecord.humidity | 相对湿度(%) | 室外焓值输入（input_type='rh'，可选） |
| WeatherRecord.pressure | 大气压(hPa) | 焓值计算 |
| WeatherRecord.wind_speed / solar_radiation | 风速 / 太阳辐射 | v0.5 入库但暂不参与计算（F1-020） |

筛选条件：`project → city → WeatherRecord WHERE datetime IN 所选年份`，按 `datetime` 升序，得到有序序列 `weather[0..T-1]`。

### 3.2 室外焓值计算（F6-002）

逐时调用《静态冷量计算实现.md》§3.1.0 的 `calculate_enthalpy()`，input_type='wb'（干球+湿球）或 'rh'：

```python
outdoor_enthalpy[t] = calculate_enthalpy(
    temp_dry             = weather[t].temp_dry,
    humidity_or_wet_bulb = weather[t].temp_wet,   # 或 humidity
    pressure_hpa         = weather[t].pressure,
    input_type           = 'wb'                   # 气象驱动优先湿球
)
```

约 26280 次计算须向量化（F6-007 / F6-017，< 1 秒），见 §5.2。

### 3.3 室内焓值（F6-003）

室内温湿度全年恒定（PCB 洁净间 23±2℃ / 55±5%），直接复用静态值：

```python
indoor_enthalpy = calculate_enthalpy(
    temp_dry             = room.indoor_calc_temp,
    humidity_or_wet_bulb = room.indoor_calc_humidity,
    pressure_hpa         = weather[t].pressure,   # 室外大气压（年内变化小，可用首条或逐时）
    input_type           = 'rh'
)
# 注意：indoor_enthalpy 与 t 无关，循环外预计算一次即可
```

### 3.4 逐时新风负荷（F6-004）

```
Q_fresh_air(t) = ρ × V_fresh_air × ( h_outdoor(t) − h_indoor ) / 3600
```

- ρ = DefaultConfig.air_density（默认 1.2 kg/m³，PRD §15.3 已统一，无 1.2 vs 1.12 歧义）
- V_fresh_air = `RoomCalcResult.fresh_air_volume`（m³/h，静态结果，全年固定）
- h_outdoor(t) = §3.2；h_indoor = §3.3
- 允许 Q_fresh_air(t) < 0（冬季/过渡季室外焓低于室内）

### 3.5 逐时总负荷（F6-005）

```
Q_dynamic(t) = Q_terminal + Q_fresh_air(t)
```

- Q_terminal = `RoomCalcResult.terminal_load`（kW，静态结果，全年固定）

### 3.6 负值处理（F6-006，与静态统一）

```
Q_fresh_air(t) 允许为负（参与计算，不截断）
若 Q_dynamic(t) < 0：Q_dynamic(t) = 0          # 总负荷截断为 0
极值统计 Q_min 取 Q_dynamic(t) > 0 的最小值（F4-014）
```

### 3.7 向量化加速（F6-007 / F6-017 / F6-018）

- 室外焓值：NumPy 向量化 `vectorized_enthalpy(temp_dry[], temp_wet[], pressure[])` → 数组，< 1 秒
- 逐时负荷：NumPy 广播 `Q_fresh = ρ * V_fresh * (h_out - h_in) / 3600`，避免 Python 循环
- 房间维度：房间参数向量化后与小时数组广播（F6-018）

## 4. 方式二：比例系数法仿真算法（F6-008~F6-011）

**确定性：✅ 已确认（公式）；⚠️ 系数值待暖通校准确认（ADR-0003）**

### 4.1 统一比例系数表（ADR-0003）

系统内置权威映射表（PRD §14.8），维度：室外温度区间 × 生产负荷率 → 比例系数 k。动态仿真方式二取"负荷率=100%"列。项目级可覆盖（v0.5 用系统默认，v0.6 支持自定义）。

| 温度区间 | k(100%) |
|---|---|
| < 5℃ | 0.8 |
| 5~15℃ | 0.9 |
| 15~25℃ | 1.0 |
| 25~35℃ | 1.1 |
| > 35℃ | 1.2 |

非标准温度使用双线性插值（PRD §14.8）。表实体名（DB 表/字段）**待确认**（ADR-0003 仅定义映射逻辑，数据库设计未列该表）。

### 4.2 查表得到 k(t)（F6-008 / F6-009）

```
对每小时 t：
    temp = weather[t].temp_dry          # 室外干球温度
    k(t) = lookup_coefficient(temp, production_rate=1.0)   # ADR-0003 100% 列
```

- `lookup_coefficient` 实现温度区间定位 + 双线性插值
- 无气象数据场景见 §4.4

### 4.3 逐时负荷（F6-010）

```
Q_dynamic(t) = Q_static × k(t)
```

- Q_static = 静态总负荷（推荐取 `RoomLoadByWaterTemp.total_load` 以包含完整负荷；**取哪个静态值待确认**，见待确认 D3）
- 同样适用 §3.6 负值/截断规则（总负荷 < 0 截断为 0）

### 4.4 无气象数据降级（F6-011）

```
若 WeatherRecord 缺失：
    temp_representative = city_config.temp_dry_ac_summer  # 国标夏季设计温度
    k = lookup_coefficient(temp_representative, 1.0)       # 退化单一代表值
    Q_dynamic(t) = Q_static × k   # 所有 t 相同（常数曲线）
```

## 5. 8760h 逐时计算主循环（F6-016~F6-019）

### 5.1 主循环伪代码（气象驱动）

```python
def simulate_weather_driven(project_id, years, room_ids, water_temp_config_ids):
    batch_id = create_calc_batch(project_id, 'weather_driven', years)   # F7-031
    weather = load_weather_series(project_id, years)   # 有序 WeatherRecord 序列
    rooms   = load_rooms_static(project_id, room_ids)  # 含 terminal_load, fresh_air_volume, h_indoor

    T = len(weather)
    buf = []
    for t in range(T):
        h_out = vectorized_enthalpy(weather[t])                       # F6-002
        for room in rooms:
            q_fresh = RHO * room.v_fresh * (h_out - room.h_indoor) / 3600.0   # F6-004
            q_total = room.q_terminal + q_fresh                                # F6-005
            if q_total < 0: q_total = 0.0                                      # F6-006
            buf.append((batch_id, room.id, weather[t].datetime,
                        h_out, q_fresh, room.q_terminal, q_total))
        if len(buf) >= 2000:
            flush_dynamic_load_hourly(buf); buf.clear()   # 分批落库，见 8760h 数据处理实现.md
    flush_dynamic_load_hourly(buf)
    return batch_id
```

### 5.2 主循环伪代码（比例系数法）

```python
def simulate_coefficient(project_id, years, room_ids):
    batch_id = create_calc_batch(project_id, 'coefficient', years)
    weather = load_weather_series(project_id, years)
    rooms   = load_rooms_static(project_id, room_ids)
    coeff   = load_coefficient_table(project_id)        # ADR-0003
    for t in range(len(weather)):
        k = coeff.lookup(weather[t].temp_dry, rate=1.0) # F6-009
        for room in rooms:
            q = room.q_static * k                        # F6-010
            if q < 0: q = 0.0
            buf.append((batch_id, room.id, weather[t].datetime, k, q))
    flush_dynamic_load_hourly(buf)
    return batch_id
```

### 5.3 批次管理（F7-031）

每次仿真生成唯一 `calc_batch_id`（UUID 或自增+时间戳），结果全部绑定该批次，支持历史回查（F7-032）与删除（F7-033）。两种方式结果独立存储、可同时运行对比（F6-014 / F6-015）。

### 5.4 输入字段映射（动态仿真复用静态结果）

| 数据库表.字段 | 类型 | 角色 | 来源 |
|---|---|---|---|
| RoomCalcResult.terminal_load | [RESULT] | Q_terminal（固定） | 静态 §3.5 |
| RoomCalcResult.fresh_air_volume | [CALC] | V_fresh_air（固定） | 静态 §3.3 |
| room.indoor_calc_temp / indoor_calc_humidity | [INPUT] | 室内焓值输入 | 静态 §3.1.2 |
| WeatherRecord.temp_dry / temp_wet / pressure | [INPUT] | 室外焓值输入 | F6-001 / F4-046 |
| water_temperature_config.supply_temp / return_temp | [INPUT] | 水温分类 | 静态 §3.4 |
| 统一比例系数表（ADR-0003） | [INPUT] | k(t) 查表 | F6-008 |

> 注：任务所列 `room_air_volume_parameter / RoomCalcResult` 为静态计算产出，动态仿真**作为输入复用**（非重新产出）；动态仿真的新增产出为逐时序列，落库实体见 §5.5。

### 5.5 输出字段映射

动态仿真产出两类结果：

**(a) 逐时明细 → `DynamicLoadHourly`（TimescaleDB 超表，PRD §19 命名；别名 `room_hourly_load_result` 见静态 §6.4，表名待确认统一）**

| 字段 | 类型 | 说明 | 对应计算 |
|---|---|---|---|
| project_id | BIGINT | 项目 | 入参 |
| calc_batch_id | BIGINT/UUID | 计算批次 | F7-031 |
| room_id | BIGINT | 房间（建筑/项目聚合行为 NULL） | 循环变量 |
| building_id / floor_id | BIGINT | 区域（聚合行有值） | 聚合 |
| scope | VARCHAR | room/building/project | 聚合层级 |
| water_temp_config_id | BIGINT | 水温配置 | 入参 |
| timestamp / datetime | TIMESTAMP | 逐时时间戳 | weather[t] |
| outdoor_temp | DECIMAL | 室外干球温度 | weather |
| outdoor_enthalpy | DECIMAL | 室外焓值 | F6-002 |
| fresh_air_load | DECIMAL | 新风冷负荷(kW) | F6-004 |
| terminal_load | DECIMAL | 末端负荷(kW) | Q_terminal |
| total_load | DECIMAL | 总负荷(kW) | F6-005 / 截断 |
| simulation_type | VARCHAR | weather_driven / coefficient | 入参 |

**(b) 逐时汇总序列 → `LoadSummary`（按水温/区域/时段聚合，见《8760h 数据处理实现.md》§5）**

`LoadSummary` 现有 schema（DB §4.14）无时间列；逐时序列需在 `LoadSummary` 增加 `timestamp` 列或扩展存储，**具体方案待确认**（与 03 分区策略 / DB 设计协同）。字段语义复用：`fresh_air_load / terminal_load / extra_load / total_load / scope / category / water_temp_config_id`。

## 6. 计算精度与性能要求

| 指标 | 要求 | 来源 | 实现要点 |
|---|---|---|---|
| 计算精度 | 与独立脚本验算偏差 < 1% | G3 | 仅方式一；psychrolib 标准焓值 + 公式一致 |
| 总时效 | 8760h×3年×1000+ 区域 < 30 秒 | G4 / F6-016 | 向量化 + 房间批处理 + 批量落库 |
| 室外焓 | 向量化 ~26280 次 < 1 秒 | F6-017 / F6-007 | NumPy 向量化 |
| 房间负荷 | 广播避免 Python 循环 | F6-018 | NumPy 广播 |
| 存储 | TimescaleDB 超表 + (project_id, calc_batch_id) 索引 | F6-019 | 见 8760h 数据处理实现.md |

边界条件：

- 气象缺失：方式一触发"先获取气象"提示（F6-021）；方式二降级（F6-011）
- 空值：人员/设备参数为空按 0（沿用静态 §3.2 规则）
- 数值溢出：极端焓差导致 Q 异常时记录日志并截断（参考静态 §9 错误处理）
