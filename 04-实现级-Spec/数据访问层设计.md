## 1. 概述

数据访问层（DAL）通过 **Repository 模式** 封装所有 ORM 访问，确保视图层与服务层不直接书写 QuerySet 链或 raw SQL。本文档定义：

- Repository 模式与分层结构；
- 按项目到建筑到楼层到房间层级的查询构建器；
- 事务管理（批量计算 / Excel 导入的事务范围）；
- 与数据库设计 5 索引的协同策略。

**强制约束**：服务层与视图层禁止 Model.objects.raw() / connection.cursor().execute() 直接读业务数据；所有访问经 Repository。

## 2. Repository 模式

### 2.1 分层结构

```
Service Layer
     | 调用
     v
Repository（每聚合根一个）
     | 封装
     v
Django ORM Models  ->  PostgreSQL（索引见 5）
```

每个 Repository 只负责其聚合根表的读写与关联查询，不含业务规则。通用基类提供分页、exists、bulk 操作。

### 2.2 通用基类

```python
# common/repositories.py
from django.db import models

class BaseRepository:
    model: type[models.Model]

    def get(self, pk: int) -> models.Model:
        obj = self.model.objects.filter(pk=pk).first()
        if obj is None:
            raise ResourceNotFoundError(f"{self.model.__name__} id={pk} 不存在")
        return obj

    def filter_paginated(self, queryset, page: int, page_size: int):
        from django.core.paginator import Paginator
        paginator = Paginator(queryset, page_size)
        page_obj = paginator.get_page(page)
        return {
            "items": list(page_obj.object_list),
            "pagination": {
                "page": page_obj.number,
                "page_size": page_size,
                "total": paginator.count,
                "total_pages": paginator.num_pages,
            },
        }

    def exists(self, **filters) -> bool:
        return self.model.objects.filter(**filters).exists()
```

### 2.3 各聚合根 Repository（对应 15 张表）

```python
# projects/repositories.py
class ProjectRepository(BaseRepository):
    model = Project
    def create(self, *, creator, **data) -> Project: ...
    def list_for_user(self, user, *, search="", status="") -> "QuerySet":
        """默认仅返回 user 为成员的项目（数据隔离，配合 5 索引）。"""

class BuildingRepository(BaseRepository):
    model = Building
    def list_by_project(self, project_id: int) -> "QuerySet":
        return Building.objects.filter(project_id=project_id)   # 命中 5 索引 (project_id)

class FloorRepository(BaseRepository):
    model = Floor
    def list_by_building(self, building_id: int) -> "QuerySet":
        return Floor.objects.filter(building_id=building_id)    # 命中 5 索引 (building_id)

# rooms/repositories.py
class RoomRepository(BaseRepository):
    model = Room
    def list_by_floor(self, floor_id: int, *, search="", status=None) -> "QuerySet":
        qs = Room.objects.filter(floor_id=floor_id)             # 命中 5 索引 (floor_id)
        if search:
            qs = qs.filter(Q(room_name__icontains=search) | Q(room_code__icontains=search))
        if status:
            qs = qs.filter(status=status)                        # 对话草稿过滤 status='draft'
        return qs
    def list_by_building(self, building_id: int) -> "QuerySet":
        """跨楼层：经 floor 反查（见 3 查询构建器）。"""

# calculations/repositories.py
class RoomLoadResultRepository(BaseRepository):
    model = RoomLoadResult
    def upsert(self, room_id, season_id, **fields) -> RoomLoadResult:
        """UNIQUE(room_id,season_id) -> update_or_create。"""

class RoomAirVolumeResultRepository(BaseRepository):
    model = RoomAirVolumeResult
    def upsert(self, room_id, season_id, **fields) -> RoomAirVolumeResult: ...

class RoomLoadSummaryRepository(BaseRepository):
    model = RoomLoadSummary
    def upsert(self, room_id, season_id, water_temp_config_id, **fields) -> RoomLoadSummary:
        """UNIQUE(room_id,season_id,water_temp_config_id) -> update_or_create。"""
    def list_by_water_tier(self, water_temp_config_id, season_id) -> "QuerySet":
        """命中 5 索引 (water_temp_config_id, season_id)。"""

class LoadSummaryRepository(BaseRepository):
    model = LoadSummary
    def rebuild_for_project(self, project_id, season_id=None) -> None:
        """先按 (project_id,scope,season_id) 删除，再批量插入三级汇总。"""
    def list_by_scope(self, project_id, scope, season_id=None) -> "QuerySet":
        """命中 5 索引 (project_id, season_id, scope)。"""

# conversation/repositories.py
class ConversationSessionRepository(BaseRepository):
    model = ConversationSession
    def save_stage(self, session_id, current_stage, stage_status, draft_payload) -> None: ...
```

## 3. 查询构建器（层级过滤）

房间是最小计算单元，所有查询须能沿 project -> building -> floor -> room 下钻。提供组合式查询构建器，避免视图层拼 QuerySet。

```python
# rooms/query_builder.py
class RoomQueryBuilder:
    def __init__(self):
        self._qs = Room.objects.all()

    def in_project(self, project_id: int) -> "RoomQueryBuilder":
        self._qs = self._qs.filter(floor__building__project_id=project_id)
        return self

    def in_building(self, building_id: int) -> "RoomQueryBuilder":
        self._qs = self._qs.filter(floor__building_id=building_id)
        return self

    def in_floor(self, floor_id: int) -> "RoomQueryBuilder":
        self._qs = self._qs.filter(floor_id=floor_id)
        return self

    def in_rooms(self, room_ids: list[int]) -> "RoomQueryBuilder":
        if room_ids:
            self._qs = self._qs.filter(id__in=room_ids)
        return self

    def with_status(self, status: str) -> "RoomQueryBuilder":
        self._qs = self._qs.filter(status=status)
        return self

    def active_only(self) -> "RoomQueryBuilder":
        return self.with_status("active")

    def build(self) -> "QuerySet":
        return self._qs

# 用法（服务层）：
#   rooms = RoomQueryBuilder().in_project(pid).in_building(bid).active_only().build()
```

构建器亦可用于 room_load_summary / load_summary 的层级聚合查询（传入 project/building/floor 过滤条件）。所有外键穿透过滤（floor__building__project_id 等）均走 5 外键索引，无需额外索引。

## 4. 事务管理

### 4.1 原则

- **事务所有权归服务层**（见 服务层设计.md 4.3）。Repository 方法本身不开启事务；批量/导入类 Repository 方法可接收「已处于 atomic 上下文」的假设，或在方法内用 atomic() 仅包裹自身写入。
- 跨多表的写操作（create_project、aggregate）由服务层统一 atomic() 包住多个 Repository 调用。

### 4.2 批量静态计算的事务范围

```python
# calculations/services.py  （配合 Celery 任务 calculate_project_static）
@transaction.atomic()                   # 单房原子，失败仅回滚本房
def _calc_one(room, season):
    bundle = engine.run_pipeline(room, season)        # 纯计算
    RoomLoadResultRepository().upsert(room.id, season.id, **bundle.load_result)
    RoomAirVolumeResultRepository().upsert(room.id, season.id, **bundle.air_volume_result)
    for wt in water_configs:
        RoomLoadSummaryRepository().upsert(room.id, season.id, wt.id, **bundle.summary[wt.id])
# 主循环：逐房调用 _calc_one；捕获 CalculationError 记日志并跳过，不中断整体。
# 全部房间完成后，服务层另起 transaction.atomic() 调 LoadAggregationService.aggregate()。
```

### 4.3 Excel 导入的事务范围

模块-02 的 Excel 导入为「解析 + 四类校验 + 落库」：

- 解析与校验阶段**不落库**；
- 校验通过后，整次导入在一个 transaction.atomic() 内完成：building/floor/room/room_load_parameter/room_air_volume_parameter/extra_load 批量 bulk_create（chunk_size=500 控制内存）；
- 导入中任一行非法 -> 整批回滚并返回失败行号（原子性，避免半成品）。

```python
with transaction.atomic():
    Room.objects.bulk_create(room_objs, batch_size=500)
    RoomLoadParameter.objects.bulk_create(param_objs, batch_size=500)
    # ... 其余表同理
```

### 4.4 对话式采集的事务范围

按模块-02 3.2「保存即落库」：**每个阶段确认即一次 atomic() 提交** conversation_session 的 current_stage/stage_status/draft_payload 与对应的 room（status='draft'）/extra_load 等，支持断点续采（4.15）。

## 5. 与数据库设计 5 索引的协同

Repository 的所有过滤/连接必须使用 5 已建索引列，避免全表扫描：

| 查询场景 | 使用的索引（5） | 注意 |
|---------|----------------|------|
| 项目下建筑 | building(project_id) | list_by_project |
| 建筑下楼层 | floor(building_id) | list_by_building |
| 楼层下房间 | room(floor_id) | list_by_floor |
| 房间负荷/风量（按季） | room_load_result(room_id,season_id) 等唯一索引 | upsert 命中，防重复 |
| 按水温汇总负荷 | room_load_summary(water_temp_config_id,season_id) | list_by_water_tier |
| 项目级汇总 | load_summary(project_id,season_id,scope) | list_by_scope |
| 额外负荷查询 | extra_load(project_id,season_id,category) / (building_id,season_id) | 按项目/建筑 |

**N+1 防护**：序列化「项目到建筑到楼层到房间」树时，Repository 返回 QuerySet 须带 select_related('floor__building__project') 与 prefetch_related('room_load_summary')，由视图/序列化器 Prefetch 控制深度；禁止在循环内逐对象 .room 访问触发额外查询。

**索引未覆盖的查询**：全文搜索（room_name/room_code LIKE）无专门索引，依赖 5 的 floor_id 索引先收窄范围后再内存过滤；跨项目聚合类重报表查询建议走只读副本（架构 7.3）——具体副本方案待确认。
