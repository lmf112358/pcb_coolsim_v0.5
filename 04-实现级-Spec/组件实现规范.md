## 1. 概述

本文档是「实现级 Spec」的组件部分，在前序「接口/规范定义」（设计系统 §5、接口级 README 的组件职责）之上，给出**可直接编码的组件实现指引**：组件内部结构、状态、性能优化、组件间通信。本文不重复 props 字典（见设计系统），而是落到 hook/组件骨架与性能策略。

组件分层：

- **通用组件（Generic）**：表格、表单、图表（ECharts 封装）、热力图（react-konva 封装）、模态、Toast——与业务无关，可复用。
- **业务组件（Business）**：树形导航（四级层级）、2D 编辑器、负荷曲线、对话式采集对话流、结构化预览侧栏——封装领域逻辑。

## 2. 通用组件实现

### 2.1 DataTable（通用表格）

基于 Ant Design `Table`，封装排序/筛选/分页/导出/虚拟滚动。

```tsx
interface DataTableProps<T> {
  queryKey: QueryKey;                 // 关联 React Query，便于失效
  columns: ColumnType<T>[];
  fetch: (params: TableParams) => Promise<{ rows: T[]; total: number }>;
  rowKey: keyof T;
  exportable?: boolean;
  virtual?: boolean;                  // 大数据量开启
}
```

**实现要点**：

- 服务端排序/筛选：`onChange` 把 `sorter/filters` 合并进 `fetch` 参数；分页 `pagination` 受控。
- 虚拟滚动：当 `virtual` 且行数 > 200，使用 `react-window` 的 `FixedSizeList` 包裹 `Table`（设计系统行高 48/36px），避免 1000+ 行 DOM 膨胀（F3-023、性能需求 §17.1）。
- 空态：内联 `Empty`；错误态：`result.error` 渲染重试。

### 2.2 FormSection（通用表单区块）

封装设计系统 §5.4 的字段组：标签在上、行内校验、防抖反馈。

```tsx
function Field({ name, label, rules, debounceFeedback = true }: FieldProps) {
  // useForm.Item + 防抖校验提示
}
```

- 校验：Ant Design `rules`；失焦 inline（设计系统 §8.3）；`debounceFeedback` 对远程查重等场景防抖 300ms。

### 2.3 Chart 封装（ECharts）

统一封装 `ReactECharts`，处理主题切换、容器自适应、LTTB 降采样入口。

```tsx
interface ChartProps {
  option: EChartsOption;
  height?: number;
  onEvents?: Record<string, (params: any) => void>;  // 点击柱/扇区下钻
  resample?: (data: number[][], width: number) => number[][]; // 可选降采样
}
```

- 主题：订阅 `ThemeContext`，`dark/light` 切换时 `setOption(themeOption, true)` 不合并。
- 自适应：`ResizeObserver` 监听容器 → `chart.resize()`。
- 大数据：见 §4.3（性能）。

### 2.4 HeatmapCanvas（通用热力图，react-konva）

封装 **react-konva** 的 `Stage / Layer / Line / Rect / Text`，渲染外墙轮廓 + 房间色块 + 比例尺 + 指北针 + 图例；支持两种着色模式（冷量热力 / 工艺编码）与四种显示模式（总/末端/新风/冷指标）。

```tsx
interface HeatmapCanvasProps {
  plan: FloorPlanJSON;                 // PRD §7.4 / 模块-03 §2.3
  blocks: HeatBlock[];                 // 含 room_id, load 值, tier, vertices?
  colorMode: 'heat' | 'process';
  displayMode: 'total' | 'terminal' | 'fresh' | 'density';
  onSelectBlock: (roomId: number) => void;
}
```

- 着色：冷量模式用蓝→红连续渐变（设计系统 §2.5），按 `load/maxLoad` 映射；工艺模式按 F3-016 优先级判定（温控精度>洁净度>压差），`legend_code` 来自平面图 JSON 或由 Room 字段实时映射。
- 性能：100 区块目标 <3s（F3-023）——单 `Layer` 批量挂载节点 + Konva `cache()` 缓存静态图元；色值变更只更新对应节点 `fill`，不重建 Stage。
- 交互：点击 block → `onSelectBlock`（F3-020）；缩放/平移通过 `Stage` 的 `scaleX/Y` 与 `position()` 实现，配合 `draggable` 拖拽视口。

### 2.5 Modal / Toast

直接复用 Ant Design `Modal`（设计系统 §5.7：宽 520/680/800，ESC/遮罩关闭）与 `message/notification`（§5.8）。错误拦截层统一调用（见《页面实现规范》§2.2）。

## 3. 业务组件实现

### 3.1 TreeNav（树形导航，四级层级）

```tsx
interface HierarchyNode {
  id: number;
  name: string;
  type: 'project' | 'building' | 'floor' | 'room';
  children?: HierarchyNode[];
  status?: 'draft' | 'active';
}
function TreeNav({ projectId }: { projectId: number }) {
  const { data } = useProjectTree(projectId);     // React Query
  const { selected, select } = useSelection();     // Context
  return <Fragment>
    <TreeSearch onSearch={debounce(300)} />
    <VirtualTree                // 四级虚拟滚动（模块二 §2.1）
      treeData={data}
      selectedKeys={[selected.id]}
      onSelect={(node) => select(node)}   // 更新 SelectionContext
    />
  </Fragment>;
}
```

- 虚拟滚动：四级深度 + 1000+ 房间，用 `rc-virtual-list` 渲染可见节点。
- 实时过滤：搜索 `debounce 300ms` 高亮匹配（页面总览 §3.2）。
- 选中联动：写 `SelectionContext`，Tab 间/各 Tab 内容据此重取。

### 3.2 Floor2DEditor（2D 编辑器，F3-001~F3-013）

组合 §2.4 的画布能力 + 工具状态机。**画布交互态用 Zustand 局部 store**（`useAppStore`：PDF 文档、区域数组、绘制工具、选中集、视图变换、剪贴板、历史栈），与 React Query（Room 关联数据、保存）分层：

```tsx
type Tool = 'select' | 'rect' | 'polygon' | 'scale' | 'compass';

// useAppStore（Zustand，仅编辑器内部，随卸载销毁）
interface EditorState {
  pdfDoc: PdfDocState | null;          // pdfjs-dist 加载的 PDF
  regions: Region[];                   // 平面图 blocks（含 vertices/style/z_index/locked）
  tool: Tool;                          // V/R/P 切换
  selectedIds: string[];               // 选中区域 id 集
  viewport: { scale: number; x: number; y: number };  // 0.1~5
  clipboard: Region[];                 // Ctrl+C/V 偏移 20px
  history: { past: Region[][]; future: Region[][] };  // undo/redo 上限 50
}

function Floor2DEditor({ floorId }: { floorId: number }) {
  const { data: plan } = useFloorPlan(floorId);        // React Query：GET 平面图 JSON
  const { data: rooms } = useRoomsOfFloor(floorId);    // React Query：未关联 Room 候选
  const save = useSavePlanMutation(floorId);           // PUT 平面图 JSON
  // hydrate：plan 到达 → 写入 useAppStore.regions
  // 保存：从 useAppStore.regions 序列化为 plan JSON → save.mutateAsync
}
```

- **快捷键**：`V/R/P` 切换工具；`Ctrl+C/V` 复制粘贴（新 id 偏移 20px）；`Delete` 删除；`Ctrl+A` 全选；滚轮以鼠标为中心缩放（0.1~5x）；`空格+拖拽`平移；`Esc` 取消。
- **Transformer**：选中后挂载 Konva `Transformer` 支持边角缩放/旋转；`locked=true` 的区域禁用变换。
- 关联：绘制完成弹 `Select`（列出 `useRoomsOfFloor` 中未关联 Room，F3-004）。
- 撤销/重做：操作入 `history.past/future`，上限 50 步。

### 3.3 LoadCurveChart（负荷曲线，F7-001~F7-016）

基于 §2.3 封装，专用于 8760×3 逐时曲线：

```tsx
function LoadCurveChart({ projectId, roomId, year, month, aggregation }: Props) {
  const { data, isFetching } = useSimulationHourly({ projectId, roomId, year, month, aggregation });
  const width = useContainerWidth();                 // ResizeObserver
  const sampled = useMemo(
    () => lttb(data.points, clamp(width, 2000, 5000)),  // F7-012/14
    [data, width]
  );
  return <Chart option={buildLineOption(sampled, { type, referenceLine, aggregate })}
                onEvents={{ 'datazoom': onZoomResample }} />;
}
```

- 降采样：LTTB 保留波形（F7-012）；首次 <3s（F7-013）；缩放后重新降采样（F7-015）。
- tooltip：悬停从**完整数据**取最近时间点精确值（F7-016）。
- 参考线：静态冷量标准值水平线（F7-003）；多曲线叠加/图例显隐（F7-006/010）。

### 3.4 ConversationFlow（对话式采集对话流，F2-046~F2-061）

三栏中的中部，渲染消息流 + 输入区 + 芯片。

```tsx
interface ChatMessage {
  id: string;
  role: 'system' | 'user' | 'tool' | 'summary';
  text: string;
  payload?: Record<string, unknown>;   // 结构化摘要/工具结果
  status?: 'running' | 'ok' | 'fail';  // ToolCard 状态点
}
function ConversationFlow({ sessionId }: { sessionId: string }) {
  const [messages, setMessages] = useState<ChatMessage[]>([]);
  const send = useSendMessageMutation(sessionId);
  const onSend = (text: string, chip?: string) =>
    send.mutateAsync({ text: chip ?? text });  // Enter 发送 / 芯片一键作答
  return <div>
    <MessageList items={messages}
      render={(m) => m.role === 'summary'
        ? <SummaryCard m={m} onConfirm onEdit onSkip onLater />   // F2-051
        : m.role === 'tool'
          ? <ToolCard m={m} />                                      // F2-053 工具结果
          : <Bubble m={m} />} />
    <Composer onSend={onSend} chips={currentStageChips} />        // 快捷芯片 F2-050
  </div>;
}
```

- 主动引导：每轮系统气泡带示例作答（F2-048）；上下文记忆由后端 SOP 驱动（F2-052）。
- 指令：支持「修改 XXX / 回退 / 删除」（F2-049 容错），由 `useSendMessageMutation` 透传。
- **快捷芯片（Chip）**：每阶段预设高频作答芯片（如阶段②「低温 7/12°C」「中温 12/17°C」），一键填充发送（吸收类cursor原型 engine.js 的预设作答机制）。
- **命令式跳转**：用户输入「修改建筑信息 / 回退 / 重新开始 / 跳过本阶段」等指令，由后端 `IntentExtractionService` 识别后驱动 `SopDriverService` 跳转阶段，前端仅渲染响应。
- **SummaryCard 四动作**：确认 / 修改 / 跳过 / 稍后（F2-051），对应 `onConfirm | onEdit | onSkip | onLater` 回调。
- **ToolCard 状态点**：`running`（主色脉冲）/ `ok`（成功色）/ `fail`（危险色），用于异步工具结果（如气象拉取、Excel 解析）的实时反馈。

### 3.5 StructuredPreview（结构化预览侧栏，F2-053）

```tsx
function StructuredPreview({ draftPayload }: { draftPayload: DraftPayload }) {

```

## 4. 组件间通信

### 4.1 通信方式选择

| 关系 | 方式 | 示例 |
|------|------|------|
| 父子 | props + 回调 | `HeatmapCanvas onSelectBlock`、`SummaryCard onConfirm` |
| 跨 Tab / 跨页面 | Context | `SelectionContext`（当前选中节点）、`ThemeContext`、`LocaleContext` |
| 服务端数据 | React Query 缓存 | `useProjectTree` 被树与各 Tab 共享，失效即全员刷新 |
| 一次性指令 | 命令式 ref / 事件 | 编辑器 undo/redo（useReducer 内部） |

### 4.2 状态提升原则

- 仅「需要被兄弟/父级消费」的态才提升：如当前选中节点提升到 `SelectionContext`；当前 Tab 提升到工作台本地 `useState`。
- 纯展示态留在组件内：`Composer` 的输入文本、`HeatmapCanvas` 的缩放视口。
- 服务端数据**不**放入 Context，统一走 React Query（见《状态管理实现.md》§3），避免双源不一致。

### 4.3 性能优化

- **虚拟列表**：`TreeNav`（四级）、`DataTable`（`virtual`）、`MessageList`（长对话）用 `rc-virtual-list` / `react-window`。
- **防抖**：树搜索 300ms、表单实时预览 500ms、自动保存 30s（设计系统 §8.5）、聊天输入可选 200ms 草稿。
- **记忆化**：`useMemo` 派生图表 `option`、预览树、降采样数据；`React.memo` 包裹纯展示气泡/卡片；`useCallback` 稳定回调避免子组件重渲染。
- **大数据渲染**：ECharts LTTB 降采样（目标 2000~5000 点，F7-014）；react-konva 单 Layer 批量节点 + Konva `cache()`（F3-023）；避免逐点 `setOption` / 逐节点重挂。
- **代码分割**：`Floor2DEditorPage`、`ConversationPage` 用 `React.lazy` 懒加载（Konva/ECharts/pdfjs-dist 体积大）。

## 5. 待确认（Open Questions）

1. **对话采集 UI 组件库归属**：`SummaryCard / ToolCard / Chip` 的精确 props 与 i18n key 命名待《对话采集接口级 Spec》落定（目前按设计系统 §5.9 视觉约束实现）。
2. **HeatmapCanvas 工艺编码判定参数来源**：F3-016 的温控精度/洁净度/压差取值来自房间参数，需确认字段名与「未设置时默认灰」的兜底（F3-019）。
3. **ExcelImport 校验反馈结构**：四类校验（必填/范围/重复/类型）的错误数组 schema 待接口级定义，组件侧先以 `{row, col, field, message}[]` 占位。
4. **LoadCurveChart 后端聚合端点**：逐时数据是否由后端按 year/month/aggregation 预聚合，还是前端一次性拉全量后降采样，影响 `useSimulationHourly` 入参设计（本文按「前端降采样」实现，待接口级确认）。
