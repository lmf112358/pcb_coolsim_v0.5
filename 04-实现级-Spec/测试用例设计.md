## 1. 概述

本文档把《测试策略.md》的分层方法与《测试计划.md》的计算用例落为**可执行**的测试设计，对齐其 TC 编号，并补充对话式采集专项（TC-2.4 / TC-2.5 / TC-2.6）。目标：工程师可直接套 pytest / Jest 模板编码，且每条 PRD 需求可被测试回溯。

**对齐声明**：本文档不重复《测试策略.md》的质量目标（后端 80%、计算引擎 90%、前端 70%），而是在其框架下给出落地模板；用例编号与策略完全一致，新增对话式采集用例沿用 TC-2.4/2.5/2.6。

## 3. Mock 策略（外部依赖隔离）

| 依赖 | Mock 手段 | 说明 |
|------|-----------|------|
| Celery | `CELERY_TASK_ALWAYS_EAGER=True` + `task_always_eager`；单元/集成测试不启 broker | 批量计算（F4-028）、气象拉取（F1-019）、动态仿真（F6-001）转为同步 |
| Redis | 测试配置 `CACHE/RESULT_BACKEND` 指向 `locmem` 或 `fakeredis` | 避免真实 Redis；WebSocket 进度用内存通道 |
| 气象 API | `responses` / `requests_mock` 返回 fixtures（西安样本） | F1-019 / F1-022 降级路径必测 |
| psychrolib | 真实库（公式确定性高），不 mock | 仅用边界参数验证（测试计划 TC-CALC-1.x） |
| 数据库 | pytest-django + testcontainers Postgres | 每个用例独立事务回滚 |

**示例：气象 API mock（对齐 F1-022 降级）**

```python
import requests_mock


def test_weather_api_failure_keeps_project(api_client, requests_mock):
    requests_mock.post("https://weather.example/fetch", status_code=500)
    resp = api_client.post("/api/v1/projects/", {"project_name": "X", "city_id": 1})
    assert resp.status_code == 201
    assert resp.json()["data"]["weather_status"] == "missing"   # F1-022
```

## 4. 覆盖率目标与门禁

- 计算引擎（calculations/*）：行覆盖 90%，函数覆盖 90%（property-based 用 hypothesis 覆盖边界）。
- 后端总体：行覆盖 80%；`ServiceResult.fail` 分支必覆盖。
- 前端：组件覆盖 70%；表单提交 / 错误态必覆盖。
- CI 门禁：单元 < 80% 或计算引擎 < 90% 则构建失败（见 §6）。

## 5. 可执行用例模板（单元 / 集成）

**单元：末端负荷（对齐 F4-001~F4-006 / 测试计划 TC-CALC-2.1）**

```python
import pytest
from decimal import Decimal
from services.static_load import RoomStaticLoadService


@pytest.mark.parametrize("area,civil,lighting,expected", [
    (500, 50, 20, 35000),     # (500*50 + 500*20)/1000 = 35 kW
    (200, 45, 18, 12600),
])
def test_terminal_load(db, area, civil, lighting, expected):
    room = Room.objects.create(floor_id=1, area=area, height=4)
    param = RoomLoadParameter.objects.create(
        room=room, season_id=1, civil_load_index=civil, lighting_load_index=lighting)
    RoomStaticLoadService()._calc_terminal(room, param)
    r = RoomLoadResult.objects.get(room=room, season_id=1)
    assert r.terminal_load == pytest.approx(Decimal(expected), rel=0.001)
```

### 6.1 TC-2.4 会话流与六阶段推进（P0，Integration）

```python
def test_conversation_six_stage_flow(api_client, project):
    # 创建/恢复会话（TC-2.4.1）
    s = api_client.post("/api/v1/conversation/sessions/",
                        {"project_id": project.id}).json()["data"]
    assert s["current_stage"] == "s1_project"
    # 发送消息推进阶段（TC-2.4.2）
    r = api_client.post(f"/api/v1/conversation/sessions/{s['session_id']}/message/",
                        {"message": "3 栋，每栋 5 层"}).json()["data"]
    assert r["stage"] == "s3_building"          # 阶段推进
    assert r["extracted"]["building_count"] == 3
    # 阶段①展示确认不持久化采集（TC-2.4.3，E2E）
```

### 6.2 TC-2.5 断点续采与草稿恢复（P0/P1，Integration + E2E）

```python
def test_resume_restores_stage_and_draft(api_client, project):
    # 逐区域保存写入 draft_payload（TC-2.4.4 / TC-2.5.1）
    s = api_client.post("/api/v1/conversation/sessions/",
                        {"project_id": project.id}).json()["data"]
    api_client.put(f"/api/v1/conversation/sessions/{s['session_id']}/draft/",
                   {"draft_payload": {"rooms": [{"room_name": "光刻间", "status": "draft"}]}})
    # 刷新/重开恢复（TC-2.5.1）
    resumed = api_client.get(f"/api/v1/conversation/sessions/{s['session_id']}/").json()["data"]
    assert resumed["current_stage"] == s["current_stage"]
    assert resumed["draft_payload"]["rooms"][0]["status"] == "draft"
    # 最终提交：room.status draft -> active（TC-2.5.2）
    api_client.post(f"/api/v1/conversation/sessions/{s['session_id']}/finalize/", {})
    assert Room.objects.get(room_name="光刻间").status == "active"
```
