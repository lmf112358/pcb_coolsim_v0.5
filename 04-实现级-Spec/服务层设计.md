> 版本：1.1（已对齐 PRD v0.5.1 §15 计算逻辑基线）
> 日期：2026-07-14
> 状态：已完成
> PRD 引用：F1-001（JWT 认证）、F2-001（数据采集 / 树形录入）、F4-001（静态冷量计算）
> 依赖文档：系统架构设计.md、API 总览.md、数据库设计.md 4、模块-01/02/04、ADR-0001 / ADR-0002

---

## 1. 概述

服务层位于「视图/控制器层（DRF ViewSet）」与「数据访问层（Repository）/计算引擎」之间，承载全部业务逻辑与事务边界。本文档定义：

- Django app 划分与服务清单；
- 各服务的类/方法签名与职责；
- 实现规范（职责边界、异常处理、事务边界）；
- Django 下的依赖注入方式（视图不写业务逻辑）。

**强制约束**：视图层（ViewSet / APIView）只做「请求解析 + 鉴权 + 调用服务 + 序列化响应」，不得包含计算、聚合、落库等业务逻辑。业务逻辑一律下沉到服务层。

---

## 2. 服务层架构

### 2.1 分层关系

```
DRF ViewSet / APIView
      |  (仅做参数校验、鉴权、调用)
      v
Service Layer  (业务逻辑、事务边界、编排)
      |  (依赖)
      |---> Repository Layer  (ORM 查询封装，见 数据访问层设计.md)
      |---> Calculation Engine (纯函数：焓值/负荷/风量，见 计算逻辑/静态冷量计算实现.md)
      +---> Celery Tasks     (异步：动态仿真/报告导出/批量静态，见 异步任务设计.md)
```

## 3. 服务接口定义

> 约定：参数为关键字参数；返回值为领域对象或 DTO（dataclass / dict），**不直接返回 ORM QuerySet 给视图**（由视图层序列化器转换）。异常以自定义异常抛出，由统一异常中间件转 HTTP 响应（见 4.2）。

# accounts/services.py
class AuthService:
    def login(self, username: str, password: str) -> LoginResult:
        """校验凭证，签发 Access(15min)+Refresh(7d) Token。
        失败抛 InvalidCredentialsError -> HTTP 401。"""

    def refresh(self, refresh_token: str) -> TokenRefreshResult:
        """校验 Refresh Token，轮换并返回新 Access Token。
        过期/失效抛 TokenExpiredError / InvalidTokenError -> HTTP 401。"""

    def logout(self, refresh_token: str) -> None:
        """将 Refresh Token 加入黑名单，返回 204。"""

class ProjectIsolationService:
    def assert_user_in_project(self, user, project_id: int) -> Project:
        """校验 user 是否为 project 成员；否则抛 PermissionDeniedError -> HTTP 403。
        所有 project/building/floor/room 级写入前必须调用。"""

    def filter_visible_projects(self, user, queryset) -> "QuerySet":
        """按用户成员关系过滤 project 集合，杜绝越权横向访问。"""

## 4. 实现规范

### 4.1 职责边界

- **视图层**：仅解析请求体、校验基础格式（由序列化器完成）、调用服务、序列化返回。禁止写 Model.objects.create/filter、禁止写计算。
- **服务层**：持有业务规则与事务边界；通过 Repository 读写数据；通过 engine 计算；编排 Celery 任务。
- **Repository 层**：只封装 ORM 查询/批量写入，不含业务规则（见 数据访问层设计.md）。
- **Calculation Engine**：无副作用的纯函数，输入 dict/标量，输出 dict；不直接访问 DB。

### 4.2 异常处理

统一异常基类 DomainError(code: str, message: str, http_status: int, details: list | None = None)。由 DRF 异常处理器映射为统一响应体（API 5.2）：

| 异常类 | code | HTTP | 触发场景 |
|--------|------|------|---------|
| InvalidCredentialsError | INVALID_CREDENTIALS | 401 | 登录失败 |
| TokenExpiredError / InvalidTokenError | TOKEN_EXPIRED / INVALID_TOKEN | 401 | Token 失效 |
| PermissionDeniedError | INSUFFICIENT_PERMISSIONS | 403 | 越权 |
| ResourceNotFoundError | RESOURCE_NOT_FOUND | 404 | 资源不存在 |
| DuplicateResourceError | DUPLICATE_RESOURCE | 409 | 唯一约束冲突 |
| ValidationError（业务） | VALIDATION_ERROR | 400 | 字段校验失败 |
| CalculationError | CALCULATION_ERROR | 422 | 计算参数非法（除零/焓值非法） |
| WeatherDataMissingError | WEATHER_DATA_MISSING | 422 | 仿真缺气象（表见 异步任务设计.md 6 待确认） |
| ExportNotReadyError | （复用 409/202） | 409 | 导出文件未就绪 |

服务内部对第三方/外部异常（Redis、Celery、psychrolib 极端态）一律封装为上述领域异常，禁止将原始栈抛到视图层。

### 4.3 事务边界

- **单资源写操作**（create/update/delete 单条）：服务方法内 with transaction.atomic():。
- **含聚合的写操作**（如 create_project 建项目+配置+成员）：整体一个 atomic()。
- **批量静态计算**：单房计算在各自 atomic() 子事务内完成，单房失败仅记日志、跳过，不回滚其他房间；聚合 aggregate() 单独 atomic()。
- **对话式采集**：每阶段「保存即落库」——每次确认即一个 atomic() 提交（断点续采语义，模块-02 3.2/3.3）。
- **Repository 不开启事务**：事务所有权归服务层，保证边界清晰、可测试。

```python
from django.db import transaction

class RoomService:
    def create_room(self, **kwargs):
        with transaction.atomic():
            room = RoomRepository.create(**kwargs)          # 单表落库（含负荷/风量/温湿度参数）
        return room
```

## 5. 依赖注入（Django 下的实践）

Django 无原生 DI 容器；采用「显式构造注入 + 轻量服务工厂」：

- 服务类依赖（Repository、Engine、ChannelLayer、Celery app）通过 __init__ 注入，不内联 from xxx import repo 后直接调用全局对象。
- 提供 apps.<app>.services 模块级工厂函数，集中装配依赖，视图只调用工厂。

```python
# projects/services.py
class ProjectService:
    def __init__(self, project_repo, building_repo, floor_repo,
                 isolation: ProjectIsolationService, weather_task):
        self._project_repo = project_repo
        self._building_repo = building_repo
        self._floor_repo = floor_repo
        self._isolation = isolation
        self._weather_task = weather_task   # Celery task 引用，便于测试替换

    def create_project(self, creator, **data):
        with transaction.atomic():
            proj = self._project_repo.create(creator=creator, **data)
            self._weather_task.delay(proj.id)   # 入队异步气象拉取
        return proj

# projects/service_factory.py  （装配点）
def get_project_service() -> ProjectService:
    return ProjectService(
        project_repo=ProjectRepository(),
        building_repo=BuildingRepository(),
        floor_repo=FloorRepository(),
        isolation=ProjectIsolationService(),
        weather_task=fetch_weather_data,
    )

# projects/views.py  （视图零业务逻辑）
class ProjectViewSet(viewsets.ModelViewSet):
    def perform_create(self, serializer):
        svc = get_project_service()
        proj = svc.create_project(creator=self.request.user, **serializer.validated_data)
        self._created = proj
```

测试时通过替换工厂或构造注入 mock，实现服务层单测与 Django ORM 解耦。
