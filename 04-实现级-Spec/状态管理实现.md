## 1. 概述

本文档落地前端状态管理方案，分两层：

- **服务端状态**：React Query（TanStack Query v5）管理所有 API 数据：查询键值设计、失效策略、乐观更新。
- **客户端 UI 状态**：React Context 管理纯前端态：当前选中节点（项目/建筑/楼层/房间）、主题、语言、当前 Tab。

原则：**服务端数据不进 Context**（避免双源不一致）；Context 只放「跨页面共享的 UI 选择态」与「全局偏好」。

## 2. 状态分层总览

```
服务端状态（React Query 缓存）
  ├─ projects / projectTree / room / roomPreview
  ├─ staticResults / simulation / simulationHourly

本地组件状态（useState/useReducer）
  ├─ 当前 Tab、表单输入、编辑器历史栈、聊天消息数组、筛选/排序
```

## 3. React Query 使用规范

### 3.1 QueryClient 全局配置

```ts
export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 30_000,          // 30s 内不重新请求（匹配预览缓存 TTL）
      gcTime: 5 * 60_000,         // 5min 垃圾回收
      retry: 1,
      refetchOnWindowFocus: false,
      throwOnError: false,
    },
    mutations: { retry: 0 },
  },
});
```

### 3.2 查询键值（Query Key）设计

键值用「数组 + 参数对象」结构，便于按前缀失效：

```ts
// 项目与层级
['projects', { search, status }]          // 地图首页列表
['project', projectId]                    // 项目元信息
['projectTree', projectId]                // 四级层级树（F2-001 共享）

// 房间与计算
['room', roomId]                          // 房间详情（Tab1 表单）
['roomPreview', roomId, paramsHash]       // 实时预览（F4-034，debounce 500ms）
['staticResults', projectId, { scope, sort, page }]  // Tab2 结果表
['loadSummary', projectId]                // 汇总卡

// 仿真与可视化
['simulation', projectId, batchId]        // 仿真汇总
['simulationHourly', { projectId, roomId?, year, month, aggregation }]  // F7-001
['floorPlan', floorId]                    // 平面图 JSON（PRD §7.4）
['heatmapData', floorId, mode]            // 着色数据（F3-017/22）
['loadAnalysis', projectId, dimension]    // 负荷分析五维
['forecastScenarios', projectId]
['forecastResult', scenarioId, version?]  // 负荷预测 168 点

// 对话采集（候选，待接口级确认）
['conversationSession', projectId]        // F2-057 断点续采
```

`paramsHash`：对预览参数做稳定序列化（如 `JSON.stringify` 排序键）后 `hash`，确保同参命中缓存。

### 3.3 失效（Invalidation）策略

| 触发 | 失效键值 |
|------|----------|
| 保存/自动保存房间 | `['room', roomId]`、`['projectTree', projectId]`（树汇总/状态）、`['staticResults', projectId]`（若已算） |
| 计算静态负荷完成 | `['staticResults', projectId]`、`['loadSummary', projectId]`、`['heatmapData', floorId]`（F3-024 <1s 刷新） |
| 运行动态仿真完成 | `['simulation', projectId]`、`['simulationHourly', ...]`、`['heatmapData', floorId]` |
| 对话采集阶段保存/确认 | `['conversationSession', projectId]`、`['projectTree', projectId]`（回写同源模型，F2-060） |
| 新建/删除建筑楼层房间 | `['projectTree', projectId]` |

> 失效用 `queryClient.invalidateQueries({ queryKey: ['staticResults', projectId] })`，触发后台重取；列表类用 `refetchType: 'active'`。

### 3.4 乐观更新（Optimistic Update）

**房间保存**（Tab1）：

```ts
const saveRoom = useMutation({
  mutationFn: (body) => api.put(`/rooms/${roomId}/`, body),
  onMutate: async (body) => {
    await queryClient.cancelQueries({ queryKey: ['room', roomId] });
    const prev = queryClient.getQueryData(['room', roomId]);
    queryClient.setQueryData(['room', roomId], { ...prev, ...body });  // 立即回显
    return { prev };
  },
  onError: (_e, _b, ctx) => {            // 失败回滚 + 提示
    queryClient.setQueryData(['room', roomId], ctx?.prev);
    message.error(t('save_failed'));
  },
  onSettled: () => queryClient.invalidateQueries({ queryKey: ['room', roomId] }),
});
```

**对话采集阶段保存**：`onMutate` 直接 `setQueryData(['conversationSession', projectId], draft)`，实现右侧栏实时联动（F2-053）与断点续采本地可恢复（§5）。

### 3.5 Token 自动刷新（F1-001 / F1-004）

```ts
// API 客户端拦截器
api.interceptors.response.use(
  (r) => r,
  async (error) => {
    if (error.response?.status === 401 && !error.config._retry) {
      error.config._retry = true;
      const newAccess = await refreshToken();      // POST /auth/refresh/
      if (newAccess) return api(error.config);      // 重放原请求
    }
    return Promise.reject(error);
  }
);
```

- `refresh_token` 存 `httpOnly` Cookie 或内存（模块一 §6.2）；刷新失败 → 清除 `AuthContext` 并跳 `/login`。

## 4. Context 状态管理

### 4.1 AuthContext（F1-001）

```ts
interface AuthState {
  user: User | null;
  accessToken: string | null;
  login: (u: string, p: string) => Promise<void>;
  logout: () => Promise<void>;
}
// 登录成功写 access/refresh；导航条用户菜单显示角色（模块一 4 角色）
```

### 4.2 SelectionContext（当前选中态，F2-001 联动）

```ts
type NodeType = 'project' | 'building' | 'floor' | 'room';

interface SelectionState {
  projectId: number;
  node: { id: number; type: NodeType; name: string } | null;
  select: (node: { id: number; type: NodeType; name: string }) => void;
}

// 工作台内所有 Tab 消费同一 SelectionContext：
// - Tab1 表单按 node(room) 拉取 useRoom
// - Tab2/3 结果按 node 过滤 scope
// - Tab4 按 node(floor) 拉平面图
// - 切换 Tab 保留 node（PRD §3.1 不丢失上下文）
```

```tsx
const SelectionContext = createContext<SelectionState>(null!);
export const useSelection = () => useContext(SelectionContext);
```

### 4.3 ThemeContext / LocaleContext

- `ThemeContext`：`'dark' | 'light'`，初始读 `localStorage`，默认跟随系统（`prefers-color-scheme`）；切换写 `data-theme` 属性（设计系统 §6.2）。
- `LocaleContext`：`'zh' | 'en'`，包裹 `react-i18next` 的 `i18n` 实例；所有文案走语言包（设计系统 §7）。

## 5. 断点续采（对话式采集 Resume）的本地状态恢复

对话采集（F2-057）要求刷新/重开从 `current_stage` 继续。双保险策略：

1. **服务端持久化（权威）**：每次阶段保存 `PATCH .../conversation/stage/` 写 `conversation_session.current_stage / stage_status / draft_payload`（模块二 §3.3）。进入页面 `GET .../session/` 即恢复。
2. **本地草稿兜底（体验）**：在 `onMutate` 乐观写入 `conversationSession` 缓存的同时，将 `draft_payload` 镜像到 `sessionStorage['conv_draft_' + projectId]`（非敏感、可丢失）。若网络中断，`useConversationSession` 的 `initialData` 优先读 `sessionStorage` 渲染，待网络恢复再与服务端对齐。

```ts
function useConversationSession(projectId: number) {
  return useQuery({
    queryKey: ['conversationSession', projectId],
    queryFn: () => api.get(`/projects/${projectId}/conversation/session/`),
    initialData: () => readDraftFromSession(projectId),  // 本地兜底
  });
}
```

- `room.status` 草稿态：`draft`（对话产出未确认）→ ⑥ 确认后转 `active`（F2-058），由 `useSendMessageMutation` 的 confirm 步骤触发，成功后失效 `projectTree`。

## 6. 状态更新流程（以 Tab1 改参→预览→保存为例）

```
用户改参
  └─ 表单 onChange → 防抖 500ms
       └─ useRoomPreview(roomId, paramsHash)  // POST /calculations/preview/
            └─ 成功 → 底部 CalcPreviewPanel 显示分项 + 合计（F4-035）
            └─ 校验失败 → 行内错误，不计算（F4-037）
点击保存 / 30s 自动保存
  └─ useMutation onMutate 乐观更新 ['room', roomId]
       └─ PUT /rooms/{id}/
            └─ onSuccess → 失效 ['projectTree']（树状态/汇总）
            └─ onError   → 回滚 + message.error
点击「计算静态负荷」
  └─ useCalcStaticMutation → POST /calculate-static/ (后台任务)
       └─ WebSocket 进度 → 完成 → 失效 ['staticResults','heatmapData']
            └─ Tab2/Tab4 自动刷新（PRD §3.1 联动）
```

## 7. 与服务端缓存一致性

- 单一数据源：所有展示数据来自 React Query 缓存；写操作经 `mutate` + 失效，避免组件内 copy 与缓存漂移。
- 预览 vs 落库：预览（`roomPreview`）为瞬时值**不**写入 `room` 缓存，只有保存才更新 `room`（模块二 §2.2「预览不落库」）。
- 跨通道一致：对话/Tab1/Excel 共享 `projectTree` 与 `room` 缓存，任一通道写入后失效，三通道立即可见（F2-060/061）。

## 8. 待确认（Open Questions）

1. **对话 session 端点与字段**：`conversation_session` 的 `current_stage / stage_status / draft_payload` 具体结构与端点路径待接口级 Spec 确认（本文 §3.2/§5 为候选）。`stage_status` 建议为 `{ [stage: number]: 'pending'|'done'|'skipped' }`。
2. **room.status 枚举值**：草稿 `draft` 与正式 `active` 之外的状态（如 `archived`）是否影响树着色待确认。
3. **预览接口返回结构**：`POST /calculations/preview/` 的响应字段（分项负荷明细）需与模块四 §6.1 `RoomCalcResult` 对齐，组件侧类型待接口级落定。
4. **Token 存储方式**：`refresh_token` 用 `httpOnly` Cookie 还是内存/SPA 存储，影响 `refreshToken()` 实现与 XSS 防护策略（模块一 §6.2 建议 Cookie）。
