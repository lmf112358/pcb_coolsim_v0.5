## 2. 逐时数据存储方案（F6-019, F7-030）

### 2.1 存储实体

PRD §19 数据模型命名为 `DynamicLoadHourly`（动态仿真逐时结果，TimescaleDB 超表）。静态规范 §6.4 以 `room_hourly_load_result` 作为 Phase 2 表别名。**表名统一待确认（见待确认 D5）**，下文以 `DynamicLoadHourly` 为准。

该表为时序超表，承载房间级与聚合级（building / project）逐时行，以 `scope` 区分层级。

### 2.2 表结构（建议字段，均源自已定义概念，无新增业务实体）

| 字段 | 类型 | 必填 | 说明 | 来源 |
|---|---|---|---|---|
| id | BIGSERIAL PK | 是 | 主键 | - |
| project_id | BIGINT FK | 是 | 项目 | 入参 |
| calc_batch_id | BIGINT/UUID | 是 | 计算批次 | F7-031 |
| room_id | BIGINT FK | 否 | 房间（聚合行 NULL） | 动态仿真 |
| floor_id | BIGINT FK | 否 | 楼层（聚合行有值） | 聚合 |
| building_id | BIGINT FK | 否 | 建筑（聚合行有值） | 聚合 |
| scope | VARCHAR(20) | 是 | room/building/project | 聚合层级 |
| water_temp_config_id | BIGINT FK | 否 | 水温配置 | 动态仿真 |
| simulation_type | VARCHAR(20) | 是 | weather_driven / coefficient | 动态仿真 |
| ts | TIMESTAMP | 是 | 逐时时间戳（分块键） | weather[t] |
| year | SMALLINT | 否 | 年 | 派生 |
| hour_of_year | SMALLINT | 否 | 年内小时 0~8783 | 派生 |

### 2.3 分区策略（按时间/项目分区）

依据 PRD F6-019「TimescaleDB 超表，按时间列分块 + (project_id, calc_batch_id) 索引」与 03 接口级 Spec 分区策略（待创建）：

- **时间分块**：以 `ts` 为 chunk_time_column，按时间（建议 chunk_size = 1 年）自动分块，利于按年/月/日聚合与过期数据管理。
- **项目/批次索引**：复合索引 `(project_id, calc_batch_id)`，支撑按项目 + 批次的快速过滤与回查（F7-032）。
- **区域聚合索引**：`(project_id, scope, building_id, ts)`、`(project_id, scope, floor_id, ts)` 支撑多区域叠加对比（F7-007 / F7-011）。
- **水温索引**：`(project_id, water_temp_config_id, ts)` 支撑按水温分类查询（F7-004 等）。

> 注：详细 chunk_size、保留策略、压缩策略在《03-接口级-Spec/数据库/分区策略.md》（当前 ⏳ 待创建）中定义，本处给出动态仿真所需的索引最小集。

### 2.4 建表脚本（TimescaleDB）

```sql
CREATE TABLE dynamic_load_hourly (
    id                   BIGSERIAL,
    project_id           BIGINT       NOT NULL,
    calc_batch_id        BIGINT       NOT NULL,
    room_id              BIGINT       NULL,
    floor_id             BIGINT       NULL,
    building_id          BIGINT       NULL,
    scope                VARCHAR(20)  NOT NULL,
    water_temp_config_id BIGINT       NULL,
    simulation_type      VARCHAR(20)  NOT NULL,
    ts                   TIMESTAMP    NOT NULL,
    year                 SMALLINT     NULL,
    hour_of_year         SMALLINT     NULL,
    outdoor_temp         DECIMAL(5,2) NULL,
    outdoor_enthalpy     DECIMAL(8,4) NULL,
    fresh_air_load       DECIMAL(12,4) NULL,
    terminal_load        DECIMAL(12,4) NULL,
    total_load           DECIMAL(12,4) NOT NULL,
    created_at           TIMESTAMP    DEFAULT NOW()
);

SELECT create_hypertable('dynamic_load_hourly', 'ts',
                         chunk_time_interval => INTERVAL '1 year');

CREATE INDEX idx_dlh_project_batch ON dynamic_load_hourly (project_id, calc_batch_id);
CREATE INDEX idx_dlh_scope_bld     ON dynamic_load_hourly (project_id, scope, building_id, ts);
CREATE INDEX idx_dlh_scope_floor   ON dynamic_load_hourly (project_id, scope, floor_id, ts);
CREATE INDEX idx_dlh_water         ON dynamic_load_hourly (project_id, water_temp_config_id, ts);
```

## 3. 数据落库流程（F7-030 / F7-031）

### 3.1 批次生成

仿真开始时生成 `calc_batch_id`（推荐雪花/UUID 或 `batch_seq.nextval` + 时间戳），写入批次元数据（项目、运行时间、气象范围、方式），结果行全部携带该 ID（F7-031）。

### 3.2 批量写入

为达成 < 30 秒时效，**禁止逐行 INSERT**，采用：

- 内存缓冲（每 1000~5000 行 flush 一次）
- TimescaleDB / PostgreSQL `COPY` 或 `executemany` 批量写入
- 房间维度并行：将房间分片到多进程，各进程独立缓冲落库（参考模块-06 §4.1 并行）

```python
def flush_batch(rows):
    # rows: List[Tuple[...]] 与 §2.2 字段顺序一致
    with connection.cursor() as cur:
        cur.executemany(
            """INSERT INTO dynamic_load_hourly
               (project_id, calc_batch_id, room_id, floor_id, building_id,
                scope, water_temp_config_id, simulation_type, ts, year,
                hour_of_year, outdoor_temp, outdoor_enthalpy,
                fresh_air_load, terminal_load, total_load)
               VALUES (%s,%s,%s,%s,%s,%s,%s,%s,%s,%s,%s,%s,%s,%s,%s,%s)""",
            rows
        )
```

### 3.3 落库时序图

```
simulate() ──► create_calc_batch() ──► 逐时主循环(填充 buffer)
                                         │ buffer 满 1000~5000
                                         ▼
                                   COPY / executemany ──► DynamicLoadHourly(超表)
                                         │ 循环结束
                                         ▼
                                  flush 剩余 ──► 触发聚合(§5) ──► load_summary 逐时序列
                                         ▼
                                  WebSocket 完成通知
```

## 4. 查询优化（F7-032 回查 / F7-001~F7-016 取数）

### 4.1 按区域聚合查询

前端按 功能区域/楼层/建筑/项目（F7-011）取数：直接过滤 `scope` + 对应 ID。

```sql
-- 单房间逐时曲线（F7-001）
SELECT ts, total_load FROM dynamic_load_hourly
WHERE project_id=%s AND calc_batch_id=%s AND room_id=%s
ORDER BY ts;

-- 建筑逐时汇总叠加（F7-007）
SELECT ts, SUM(total_load) FROM dynamic_load_hourly
WHERE project_id=%s AND calc_batch_id=%s AND scope='building' AND building_id=%s
GROUP BY ts ORDER BY ts;
```

### 4.2 按水温聚合查询

```sql
-- 按水温分类的逐时负荷（F7-004 / F7-006 对比）
SELECT water_temp_config_id, ts, SUM(total_load) AS load
FROM dynamic_load_hourly
WHERE project_id=%s AND calc_batch_id=%s AND scope='project'
GROUP BY water_temp_config_id, ts ORDER BY ts;
```

### 4.3 按时段聚合查询

利用 `date_trunc` 实现 年/月/日 视图（F7-004）与 平均/最大/最小 切换（F7-005）：

```sql
-- 月视图 + 平均值
SELECT date_trunc('month', ts) AS mon,
       AVG(total_load), MAX(total_load), MIN(total_load)
FROM dynamic_load_hourly
WHERE project_id=%s AND calc_batch_id=%s AND scope='project'
GROUP BY mon ORDER BY mon;
```

### 4.4 索引与降采样协同

- 完整逐时数据存于后端（F7-014）；前端按可视宽度动态降采样（LTTB，F7-012 / F7-015），降采样点数 2000~5000。
- 悬停精确值：前端缩放后用原始 `ts` 回查最近点（F7-016）。
- 历史批次列表：按 `calc_batch_id` 聚合元数据查询（F7-032）；删除批次 `DELETE WHERE calc_batch_id=%s`（F7-033）。

## 5. 聚合算法（按水温分类汇总至 room_load_summary / load_summary）

> 说明：静态计算的 `room_load_summary`、`load_summary` 以 `(room, season, water_temp)` 为单值主键（无时间维度）。动态仿真的"逐时序列"需在时间维度上展开。两种落地方案，**方案待 DB 设计确认（D6）**：
> - 方案 A：`load_summary` 增加 `ts` 列，逐时写入 scope/category 聚合行（复用现有字段语义）。
> - 方案 B：`DynamicLoadHourly` 已存 room + building + project 三级逐时行，聚合查询直接在超表上按 `scope` 完成，不额外写 `load_summary`。
> 下文以「超表内按 scope 聚合 + 必要时回写 load_summary」描述算法，字段语义与 DB §4.12 / §4.14 一致。

### 5.1 房间级 → 按水温分类（对应 room_load_summary 语义）

每个房间逐时按 `water_temp_config_id` 分类汇总新风/末端/总负荷：

```sql
INSERT INTO dynamic_load_hourly
  (project_id, calc_batch_id, room_id, scope, water_temp_config_id,
   simulation_type, ts, fresh_air_load, terminal_load, total_load)
SELECT project_id, calc_batch_id, room_id, 'room', water_temp_config_id,
       simulation_type, ts,
       SUM(fresh_air_load), SUM(terminal_load), SUM(total_load)
FROM dynamic_load_hourly
WHERE project_id=%s AND calc_batch_id=%s AND scope='room'
GROUP BY project_id, calc_batch_id, room_id, water_temp_config_id, simulation_type, ts;
```

### 5.2 建筑/项目级 → load_summary 语义（category 维度）

按 `category`（新风负荷/末端负荷/合计）与 `scope` 聚合：

```sql
-- 项目级逐时合计
SELECT ts,
       SUM(fresh_air_load) FILTER (WHERE category='新风负荷') AS fa,
       SUM(terminal_load)  FILTER (WHERE category='末端负荷') AS tl,
       SUM(total_load)     FILTER (WHERE category='合计')     AS tot
FROM dynamic_load_hourly
WHERE project_id=%s AND calc_batch_id=%s AND scope='project'
GROUP BY ts ORDER BY ts;
```

`extra_load`（PCW、配电室空调等，DB §4.13）按 `building_id` 有值/空 并入对应层级（沿用静态 §4.14 汇总规则）。

### 5.3 聚合层级规则（复用 DB §4.14）

| scope | building_id | floor_id | 数据来源 |
|---|---|---|---|
| floor | 有值 | 有值 | 该楼层所有房间逐时聚合 |
| building | 有值 | NULL | 该建筑所有楼层 + extra_load(building_id 有值) |
| project | NULL | NULL | 所有建筑 + extra_load(building_id 为空) |
