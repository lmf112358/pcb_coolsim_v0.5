## 1. 功能概述

模块九提供系统级与项目级的全局配置，以及贯穿全站的全局交互规范。包含五个 Tab：
1. 冷冻水温度配置（Tab1）
2. 默认值配置（Tab2，四级覆盖）
3. 国标参数查询（Tab3，只读）
4. 气象数据管理（Tab4）
5. 全局交互：中英文切换、暗色/浅色主题切换（右上角固定按钮，偏好持久化）

| 需求 ID | 需求描述 | 优先级 | 验收标准 |

| F9-009 | 优先级：功能区域显式值 > 楼层覆盖 > 建筑覆盖 > 项目覆盖 > 系统默认值 | P0 | 优先级正确 |
| F9-010 | 新建功能区域时自动从最近层级的配置继承参数 | P0 | 继承正确 |

**覆盖解析逻辑（实现核心）：**
```python
def resolve_default(project_id, building_id, floor_id, key):
    # 优先级低→高：system_default < project < building < floor < room_explicit
    if room_explicit := RoomLoadParameter.objects.filter(...).first():
        return room_explicit.get(key)          # 功能区域显式值最高
    if floor := FloorDefault.objects.filter(floor_id=floor_id, key=key).first():
        return floor.value
    if building := BuildingDefault.objects.filter(building_id=building_id, key=key).first():
        return building.value
    if project := ProjectDefault.objects.filter(project_id=project_id, key=key).first():
        return project.value
    return SystemDefault.objects.get(key=key).value
```
**待确认：** 四级覆盖的存储表（ProjectDefault/BuildingDefault/FloorDefault/SystemDefault 或统一 `default_config` 表）在 数据库设计 §4 中未定义，依赖 ADR-0006 补齐；压差渗透风量系数表（§15.2 的 k 系数）亦需在此落表。

## 4. 接口（引用 API总览 §10、§8）

### 4.1 已定义端点（§10）

**GET `/api/v1/settings/water-temperature/?project={project_id}`**（§10.1）— 返回该项目的冷冻水配置列表。
**PUT `/api/v1/settings/water-temperature/{id}/`**（§10.2）— 编辑单条配置（`name`/`supply_temp`/`return_temp`）。
**GET `/api/v1/settings/defaults/`**（§10.3）— 返回 `system_defaults` 与 `project_defaults` 的分层默认值。

> 注：§10.3 当前仅返回部分字段示例（indoor_calc_temp 等），需扩展为覆盖 F9-007 全部配置项，并支持 project/building/floor 维度写入。新增/删除冷冻水配置（F9-002）缺少对应的 POST/DELETE 端点，需在 03-接口级-Spec 补充。

### 4.2 复用端点（§8 气象数据管理）

- `GET /api/v1/weather/`（§8.1）
- `POST /api/v1/weather/fetch/`（§8.2）
- `POST /api/v1/weather/upload/`（§8.3）
