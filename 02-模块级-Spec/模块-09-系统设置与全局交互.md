## 1. 模块概述

### 1.1 功能职责

v0.5 实现精简版系统设置，核心聚焦于计算参数的模板化管理和全局配置的四级覆盖机制。

**v0.5 核心功能：**
- 冷冻水温度配置（项目级 CRUD）
- 默认值配置（四级覆盖：系统级 → 项目级 → 建筑级 → 楼层级）
- 国标参数查询（只读）
- 气象数据管理（查看、重拉、手动上传）

**v0.5 排除功能（P2，后续版本）：**
- 中英文切换
- 暗色/浅色主题切换

**v0.5 设计决策：**
- 计算参数采用模板化方案：系统级预置默认值，项目创建时选模板，参数按模块分组存储，项目级可覆盖系统级默认值

### 1.2 核心 PRD 需求

| PRD ID | 需求描述 | 优先级 |

## 4. 业务逻辑

### 4.1 四级覆盖机制

```python
# 四级覆盖解析服务
class ConfigOverrideService:
    """
    四级覆盖服务

    PRD 引用：F9-008 ~ F9-010
    Spec 引用：模块-09 Section 4.1
    """

    def get_effective_value(self, param_group, param_key, room_id):
        """
        获取参数的有效值（考虑四级覆盖）

        优先级：功能区域显式值 > 楼层 > 建筑 > 项目 > 系统
        """
        # 1. 获取功能区域所属层级
        room = Room.objects.select_related(
            'floor', 'floor__building', 'floor__building__project'
        ).get(id=room_id)

        # 2. 检查功能区域是否有显式值
        if room.has_explicit_value(param_group, param_key):
            return room.get_explicit_value(param_group, param_key)

        # 3. 按优先级逐级查找
        hierarchy = [
            ('floor', room.floor_id),
            ('building', room.floor.building_id),
            ('project', room.floor.building.project_id),
            ('system', None)
        ]

        for level, obj_id in hierarchy:
            value = self._find_config_value(level, obj_id, param_group, param_key)
            if value is not None:
                return value

        return None

    def _find_config_value(self, level, obj_id, param_group, param_key):
        """查找指定层级的配置值"""
        filters = {
            'level': level,
            'param_group': param_group,
            'param_key': param_key
        }

        if level == 'floor':
            filters['floor_id'] = obj_id
        elif level == 'building':
            filters['building_id'] = obj_id
        elif level == 'project':
            filters['project_id'] = obj_id

        config = DefaultConfigValue.objects.filter(**filters).first()
        return config.param_value if config else None
```

### 4.2 参数继承流程

```python
# 新建功能区域时的参数继承
def inherit_params_for_new_room(project_id, building_id, floor_id):
    """
    新建功能区域时自动继承参数

    PRD 引用：F9-010
    Spec 引用：模块-09 Section 4.2
    """
    # 1. 获取所有参数分组和键名
    all_params = DefaultConfigValue.objects.values_list(
        'param_group', 'param_key'
    ).distinct()

    inherited = {}

    for group, key in all_params:
        # 2. 按优先级查找
        for level, obj_id in [
            ('floor', floor_id),
            ('building', building_id),
            ('project', project_id),
            ('system', None)
        ]:
            value = find_config_value(level, obj_id, group, key)
            if value is not None:
                inherited[key] = {
                    'value': value,
                    'source': level,
                    'source_label': get_level_label(level)
                }
                break

    return inherited
```

### 4.3 冷冻水配置管理流程

```
1. 用户进入系统设置页 Tab1（冷冻水配置）
2. 加载当前配置列表：
   a. 系统级预置配置（不可删除，可查看）
   b. 项目级自定义配置（可编辑/删除）
3. 用户操作：
   a. 新增：填写名称、供水温度、回水温度
   b. 编辑：修改项目级配置（系统级不可编辑）
   c. 删除：删除项目级配置（系统级不可删除）
4. 校验：
   a. 供水温度 < 回水温度
   b. 温度范围合理（0°C ~ 20°C）
   c. 名称不重复（项目内唯一）
5. 保存成功后，更新关联的冷站方案引用
```

### 4.4 气象数据管理流程

```
1. 用户进入系统设置页 Tab4（气象数据管理）
2. 加载气象数据概况列表
3. 用户操作：
   a. 查看详情：点击城市行展开详情
   b. 重新拉取：
      - 选择城市和年份
      - 点击"重新拉取"按钮
      - 提交 Celery 异步任务
      - 轮询任务状态直到完成
      - 完成后刷新概况列表
   c. 手动上传：
      - 选择城市
      - 上传 CSV 或 EPW 文件
      - 解析文件，校验格式
      - 标记缺失小时
      - 更新概况列表
4. 数据缺失处理：
   a. 系统检测缺失小时
   b. 自动标记为插补值
   c. 在概况中显示缺失率
```

## 6. 性能优化

### 6.1 四级覆盖查询优化

**优化方案：**
- 使用 Redis 缓存系统级配置（TTL: 1 小时）
- 项目级配置缓存在项目上下文中
- 使用 `select_related` 和 `prefetch_related` 减少查询次数
- 批量获取参数值（避免 N+1 查询）

### 6.2 国标参数查询优化

**优化方案：**
- 预加载所有城市参数到内存（数据量小）
- 使用前端本地搜索（减少 API 调用）
- 缓存城市列表（TTL: 24 小时）

### 6.3 气象数据管理优化

**优化方案：**
- 气象数据概况使用物化视图或缓存
- 异步任务使用 Celery，避免阻塞主线程
- 上传文件使用流式解析，避免内存溢出
