## 1. 功能概述

模块八提供 v0.5 的基础导出能力：支持固定模板的 PDF 报告与 Excel/CSV 数据导出。导出为**异步任务**，由 Celery worker 执行，前端通过任务 ID 订阅 WebSocket 进度，完成后从统一下载端点获取文件。

**导出范围（v0.5 实现）：**
- 静态计算报告（PDF）：项目概述 + 冷负荷计算（方法/边界/各功能区域明细/汇总）+ 冷量构成分析 + 引用标准清单与系数依据来源，支持在线预览。
- 设备清单（Excel）：水泵/冷却塔的型号/规格/数量/能效参数，按水温系统分 sheet。
- 负荷计算书（Excel）：每个功能区域的完整冷负荷计算过程（含所有系数和公式），与设计院 Excel 计算书列映射对齐。
- 仿真数据（CSV）：动态仿真逐时数据，时间戳 + 总负荷 + 新风负荷 + 末端负荷 + 室外温度，支持按功能区域/楼层/建筑/项目粒度导出，每功能区域约 26280 行。

**严格约束（与 PRD v0.5.1 一致）：**
- 本模块**不包含**「冷站配置报告 / Cooling Station 报告 / F8-002 冷站报告端点」。F8-002 已在 v0.5.1 移除，导出内容仅限上述 4 类。「冷站 / Cooling Station / P&ID / 水蓄冷」不再作为模块描写，通用 HVAC 词仅作物理名词出现。
- 通用 HVAC 术语（如 chiller、pump、cooling tower）仅在设备清单的物理名词语境下使用，不引申为系统级冷站概念。

## 2. 功能详述（按 PRD §12 小节展开）

### 2.1 静态计算报告（PDF）— PRD §12.2 / F8-001~F8-004

| 需求 ID | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| F8-001 | 一键生成静态冷量计算报告 PDF | P0 | PDF 生成 < 30 秒 |
| F8-002 | 报告内容：项目概述 + 冷负荷计算（方法/边界/各功能区域明细/汇总）+ 冷量构成分析 | P0 | 内容完整 |
| F8-003 | 报告含引用标准清单和所有系数依据来源 | P0 | 依据标注完整 |
| F8-004 | 报告支持在线预览 | P0 | 预览正常 |

**实现要点：**
- 触发：`POST /api/v1/exports/static-report/{project_id}/`，提交后返回 `task_id`，由 Celery 任务 `generate_static_report` 异步渲染。
- 报告数据源：
  - 项目概述：`project`、`building`、`floor`、`room` 层级关系。
  - 冷负荷计算明细：逐功能区域读取 `room_load_result`（4.9）的 `terminal_load` 及分项（civil/lighting/personnel/electric/heated），新风负荷 `fresh_air_load = total_load − terminal_load`。
  - 按水温分类汇总：`room_load_summary`（4.12）+ `load_summary`（4.14）的 `category`/`water_temp_config_id` 维度。
  - 冷量构成分析：`load_summary` 中 `category`（新风负荷/末端负荷/PCW/配电室空调/工艺热水/消防池保温/消防池护层/合计）占比。
  - 引用标准与系数依据：来自 `room_load_parameter`（4.8）输入系数 + `coefficient_matrix`（ADR-0003，若用于静态则取 100% 列）+ 国标参数 `city_config`（4.5）。
- 在线预览：Celery 任务完成后将 PDF 写入对象存储/文件系统，预览通过下载端点（§9.3）以 `Content-Disposition: inline` 返回；前端内嵌 `<iframe>`/PDF.js 渲染。
- 超时保护：单项目全量渲染目标 < 30s，超出时给出进度反馈（WebSocket）。

### 2.2 设备清单（Excel）— PRD §12.3 / F8-008~F8-009

| 需求 ID | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| F8-008 | 导出设备清单 Excel：水泵/冷却塔的型号/规格/数量/能效参数 | P0 | Excel 格式正确 |
| F8-009 | 设备清单按水温系统分 sheet | P0 | sheet 划分清晰 |

**实现要点：**
- 触发：`POST /api/v1/exports/equipment-list/{project_id}/`。
- 分 sheet 规则：每个 `water_temperature_config`（4.6）一条水温系统对应一个 sheet（如「低温冷冻水 7/12」「中温冷冻水 12/17」）。
- 设备字段（型号/规格/数量/能效参数）：**当前数据库设计 §4 未定义设备主数据表**（见 §4 待确认），v0.5 由计算结果派生 + 配置项拼装：数量由 `load_summary` 各水温 `total_load` 经选型规则反算（选型规则待确认）；型号/规格/能效参数由系统预设模板填充。
- 任务：`generate_equipment_list`（Celery）。

### 2.3 负荷计算书（Excel）— PRD §12.4 / F8-010~F8-011

| 需求 ID | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| F8-010 | 导出负荷计算书 Excel：每个功能区域的完整冷负荷计算过程（含所有系数和公式） | P0 | 计算过程完整可追溯 |
| F8-011 | 计算书与设计院 Excel 计算书列映射对齐 | P0 | 格式兼容 |

**实现要点：**
- 每个功能区域一行/多行，完整展开 `room_load_parameter`（4.8）输入 → `room_load_result`（4.9）计算，列对齐设计院模板（列映射见 数据库设计 §8.1）。
- 含公式文本列（如 `civil_load = civil_load_index × area / 1000`），保证可追溯。
- 触发端点：**API总览 §9 当前仅定义 static-report 与 equipment-list 两个导出端点，负荷计算书导出的专用端点尚未定义**（见 §5 待确认），建议新增 `POST /api/v1/exports/load-calculation-book/{project_id}/`。

### 2.4 仿真数据导出（CSV）— PRD §12.5 / F8-012~F8-014

| 需求 ID | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| F8-012 | 导出动态仿真逐时数据 CSV：时间戳 + 总负荷 + 新风负荷 + 末端负荷 + 室外温度 | P0 | 数据完整 |
| F8-013 | 支持按功能区域/楼层/建筑/项目粒度导出 | P0 | 粒度选择正确 |
| F8-014 | 每功能区域约 26280 行数据 | P0 | 行数正确 |

**实现要点：**
- 数据源：动态仿真结果表（模块六 `simulation_result`）。每行=`datetime` + `total_load` + `fresh_air_load` + `terminal_load` + `outdoor_temp`。
- 粒度：通过 `room_id`→`floor_id`→`building_id`→`project_id` 过滤；项目级为全量聚合后的逐时序列。
- 行数校验：单功能区域 8760h × 3 年 = 26280 行（与模块六一致）。
- 触发端点：**API总览 §9 未定义仿真数据 CSV 导出端点**（见 §5 待确认），建议新增 `POST /api/v1/exports/simulation-csv/{project_id}/`。

### 2.5 按需导出 — PRD §12.6 / F8-015~F8-016

| 需求 ID | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| F8-015 | 导出前提供范围选择：全项目 / 指定建筑 / 指定楼层 / 指定功能区域（多选） | P2 | 范围选择正确 |
| F8-016 | 导出内容根据选择范围自动裁剪 | P2 | 裁剪正确 |

**实现要点：**
- 所有导出请求体统一支持 `scope` 字段：`{"scope": "project" | "buildings" | "floors" | "rooms", "ids": [...], "language": "zh"|"en"}`。
- 裁剪逻辑：在数据查询层按所选 `building_ids`/`floor_ids`/`room_ids` 过滤，再渲染。
- 现有端点 9.1/9.2 已含 `building_ids` 占位，需补齐 `floors`/`rooms` 与多选语义。

### 2.6 编号说明

PRD §12 实际出现的编号为 **F8-001~F8-004、F8-008~F8-016**。**F8-005~F8-007 在本文档中未出现**，与「冷站配置报告（原 F8-002）已在 v0.5.1 移除」一致，视为随冷站报告一并删除，不复用其编号。

## 4. 接口（引用 API总览 §9）

### 4.1 已定义端点

**POST `/api/v1/exports/static-report/{project_id}/`**（§9.1）
```json
// Request
{ "format": "pdf", "building_ids": null, "include_details": true, "language": "zh" }
// Response (202)
{ "success": true, "data": { "task_id": "export-static-20260709-001", "status": "processing", "estimated_time_seconds": 30 } }
```

**POST `/api/v1/exports/equipment-list/{project_id}/`**（§9.2）
```json
// Request
{ "format": "excel", "building_ids": [1, 2] }
// Response (202)
{ "success": true, "data": { "task_id": "export-equipment-20260709-001", "status": "processing" } }
```

**GET `/api/v1/exports/download/{task_id}/`**（§9.3）
- Response (200)：文件下载，`Content-Type` 为 `application/pdf` 或 Excel/CSV；预览时附 `Content-Disposition: inline`。

### 4.2 异步任务与进度（ADR-0002）

```python
# tasks.py
from celery import shared_task

@shared_task(bind=True)
def generate_static_report(self, project_id: int, params: dict):
    # 1. 按 scope 裁剪数据
    # 2. 渲染 PDF（reportlab / weasyprint）
    # 3. 落盘并返回 file_path
    # 4. 通过 WebSocket 通知（type=completed, result_url=/api/v1/exports/download/{task_id}/）
    self.update_state(state='PROGRESS', meta={'progress': 60, 'message': 'Rendering PDF...'})
```

- 前端订阅：`ws://host/ws/tasks/{task_id}/`（API总览 §11.1）。
- broker/result backend：Redis（ADR-0002）。

### 4.3 缺失端点（待确认，需在 03-接口级-Spec 补充）

| 仿真数据 CSV | `POST /api/v1/exports/simulation-csv/{project_id}/` | F8-012~F8-014 |

## 6. 待确认

1. **导出任务表 `export_task` 未定义**：数据库设计 §4 无此表，依赖 ADR-0006 补齐。
2. **设备主数据表未定义**：水泵/冷却塔型号规格无既有表，依赖 ADR-0006 补齐；v0.5 暂以派生 + 预设模板实现。
3. **负荷计算书 / 仿真数据 CSV 导出端点缺失**：API总览 §9 仅定义 static-report 与 equipment-list，需在 03-接口级-Spec 补充（见 §4.3）。
4. **下载端点 content-type 扩展**：§9.3 需支持 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` 与 `text/csv`。
5. **F8-005~F8-007 编号缺口**：随冷站报告移除，不再复用。
6. **ADR-0006 状态**：本任务要求「依赖 ADR-0006 补齐」，但仓库当前仅存在 ADR-0001~ADR-0005（无 ADR-0006），weather_data / 比例系数表 / 预测相关表的 §4 增补均受其阻塞。
