## 1. 功能概述

### 1.1 目的
为 HVAC 工程师提供楼层平面图的可视化标注与查看能力：在编辑场景中通过 Canvas 画布导入 PDF 底图、绘制功能区域矩形与建筑外墙轮廓、标定比例尺与指北针，并将整层平面图以 JSON 持久化；在查看场景中渲染 2D 平面图，支持冷量热力图与工艺要求编码两种着色模式，联动功能区域详情面板，辅助识别高负荷区域。

### 1.2 关键特性
- PDF 底图导入（v0.5 仅支持单页 PDF，不支持 .dwg/.dxf）：基于 **pdfjs-dist** 渲染，默认 **150 DPI**；自动提取 PDF 元信息（mediaBox / cropBox / rotation / userUnit）用于精确换算。
- 矩形绘制工具关联房间（Room），外墙多边形轮廓绘制（支持 L 形、U 形等不规则形状）；支持 **Transformer 交互**（拖拽边角缩放、旋转、置顶 z-index、锁定 locked）。
- 比例尺标定（pixels_per_meter）与指北针设置。
- **绘制快捷键**：`V` 选择 / `R` 矩形 / `P` 多边形绘制；`Ctrl+C/V` 复制粘贴（偏移 20px 新 ID）；`Delete` 删除；`Ctrl+A` 全选；滚轮以鼠标为中心缩放（0.1~5x）；`空格+拖拽`平移；`Esc` 取消当前操作。
- 平面图 JSON 覆盖式保存，底图仅作编辑参考、不随平面图持久化到查看组件。
- 查看场景双模式着色：冷量热力图（蓝→红连续渐变）/ 工艺要求编码（7 色，按优先级判定）。
- 点击色块联动右侧详情面板（基本参数、末端负荷分项、负荷构成饼图、按水温分类柱状图、新风负荷明细）。
- 显示模式切换：总负荷 / 末端负荷 / 新风负荷 / 冷指标 (W/m²)。
- 性能：单楼层 100 个功能区域渲染 < 3 秒；冷量数据更新后热力图着色 < 1 秒刷新。
- 画布引擎：**Konva + react-konva** 实现对象模型（Stage/Layer/Rect/Line/Text/Transformer），缩放/平移/拖拽交互基于 Konva 内置能力；画布编辑器内部状态（PDF 文档、区域数组、绘制工具、选中集、视图变换、剪贴板、历史栈）使用 **Zustand** 局部 store 管理，与 React Query（服务端数据态）分层。

## 2. 功能详述（按 PRD 小节展开）

### 2.1 §7.2 Canvas 编辑器工作流（F3-001 ~ F3-013）

**(1) 底图导入（F3-001 ~ F3-003、F3-012、F3-013）**
- 入口：每个楼层独立上传一张单页 PDF，由 pdfjs-dist 渲染为画布背景层（Konva Image 节点），默认 150 DPI（F3-001）。
- PDF 元信息：渲染时提取 `mediaBox / cropBox / rotation / userUnit`，存入平面图 JSON 的 `metadata.pdf_page_info`（见 §2.3），用于后续精确还原与坐标换算。
- 交互：滚轮以鼠标位置为中心缩放（0.1~5x），`空格+拖拽`平移视口（F3-002）。
- 替换：若 Floor 已有底图，上传新文件需二次确认后替换旧文件（F3-003）。
- 底图路径：保存到 Floor 表的 `floor_plan_file` 字段（F3-013）。**注意：当前 §4.3 floor 表未定义该字段，见 §6 待确认。**
- 边界：底图仅在编辑阶段作为参考，不随平面图数据持久化到查看组件（F3-012）。

**(2) 功能区域绘制与关联（F3-004 ~ F3-006）**
- 矩形绘制：按 `R` 切换矩形工具，在底图上拖拽（橡皮筋预览）绘制矩形，松开后弹出功能区域选择下拉框，列出该楼层下所有尚未被关联的 Room 记录（F3-004）。关联依据为平面图 JSON 的 `blocks[].room_id`，需过滤已在本层 blocks 中出现的 room_id。
- 多边形绘制：按 `P` 切换多边形工具，点击加点，靠近起始点闭合或双击结束。
- 标签：关联后方块显示功能区域名称标签（F3-005）。
- 编辑：按 `V` 切换选择工具；已绘制方块支持拖拽移动、Konva Transformer 拖拽边角缩放/旋转、右键菜单（更换关联/删除方块/置顶/锁定）、选中高亮（F3-006）。`Ctrl+C/V` 复制粘贴（新 ID 偏移 20px），`Delete` 删除，`Ctrl+A` 全选。

**(3) 外墙轮廓与标注（F3-007 ~ F3-010）**
- 多边形轮廓：沿底图外墙描点，点击起始点闭合；支持不规则形状（L 形、U 形），顶点可拖拽调整（F3-007）。
- 样式：轮廓线 4px 深灰色粗线（F3-008）。
- 比例尺：画线段并输入实际距离，系统计算 `pixels_per_meter = reference_line_pixels / reference_line_meters`，比例尺显示在左下角（F3-009）。
- 指北针：默认正上方为北，可拖拽旋转，`north_angle` 显示在右上角（F3-010）。

**(4) 保存（F3-011）**
- 整层平面图数据以 JSON 格式提交后端，覆盖旧数据，保存后返回项目工作台 Tab1（F3-011）。JSON 结构见 §2.3。

### 2.2 §7.3 楼层详情页 2D 可视化渲染（F3-014 ~ F3-024）

**(1) 基础渲染（F3-014、F3-018、F3-019、F3-021）**
- 渲染元素：外墙轮廓 + 功能区域色块 + 比例尺 + 指北针 + 图例（F3-014）。
- 每个色块显示功能区域名称和尺寸标注（F3-018）。
- 未关联方块灰色标注"未关联"（F3-019）。
- 支持缩放和平移（F3-021）。

**(2) 颜色编码（F3-015、F3-016、F3-017）**
- 双模式可切换（F3-015）：
  - 冷量热力图模式：按 `total_load` 映射蓝→红连续渐变色阶，可叠加 5 级分级图例（见模块七 §11.4 / PRD §11.4）。
  - 工艺要求编码模式（7 色，按优先级判定，高覆盖低）：① 温控精度 ±1°C→红；② ±2°C→橙；③ 洁净度 ISO7→黄；④ ISO8→绿；⑤ ISO7.5→蓝；⑥ 正压区→紫；⑦ 负压/普通→灰。判定顺序：温控精度 > 洁净度 > 压差（F3-016）。
- 冷量热力图按 `total_load` 着色（F3-017），数据源为 `RoomLoadByWaterTemp.total_load`（按当前水温分类）或 `RoomCalcResult.terminal_load` 组合。

**(3) 联动与显示模式（F3-020、F3-022）**
- 点击色块联动右侧详情面板：基本参数卡片 + 末端负荷分项明细 + 负荷构成饼图 + 按水温分类柱状图 + 新风负荷明细；数据实时（F3-020）。
- 显示模式切换：总负荷 / 末端负荷 / 新风负荷 / 冷指标 (W/m² = 总负荷 / 面积)（F3-022）。

**(4) 性能（F3-023、F3-024）**
- 单楼层 100 个功能区域渲染 < 3 秒（F3-023），基于 react-konva 单 Layer 批量节点 + Konva `cache()` 策略。
- 冷量数据更新后热力图着色 < 1 秒刷新（F3-024）。建议查看侧通过 WebSocket 或轮询感知 `RoomLoadByWaterTemp` 变更后局部重绘。

### 2.5 坐标与精度规范（v1.1 新增，吸收 pdf-canvas-tool 双轨坐标思想）

本平台底图仅作编辑参考、不持久化到查看组件，故采用**简化版单坐标系**（不强制 PDF 坐标系双轨）：

- **操作坐标系**：画布像素坐标，原点左上、Y 向下，直接绑定 Konva 节点 `x/y`。
- **比例换算**：所有几何量（面积/周长）以 `scale.pixels_per_meter` 换算为物理单位；保存时若 block 关联 Room 的多边形面积与 `Room.area` 偏差 >5%，提示用户确认是否更新 `Room.area`（见数据流设计.md）。
- **顶点顺序**：多边形 `vertices` 在 Y-down 坐标系下采用**顺时针**约定（Shoelace 面积为正），便于面积/自相交检测一致。
- **精度**：坐标与尺寸保留小数点后 2 位（像素级足够，避免浮点累积）；`pixels_per_meter` 保留 4 位。
- **退化与自交**：保存前前端校验——顶点数 ≥3、面积 > 0、非自相交；异常 block 标记 `metadata.invalid=true` 并在 UI 高亮提示，不阻断整层保存。

### 2.3 §7.4 平面图数据结构（JSON）

保存与读取的统一结构（F3-011、F3-014）。v1.1 在 v1 基础上**向后兼容扩展可选字段**（标注 ✚ 的为 v1.1 新增，旧数据缺失时按默认值处理）：
```json
{
  "version": 1,
  "outline": {
    "points": [{"x": 10, "y": 10}, {"x": 500, "y": 10}, {"x": 500, "y": 300}, {"x": 10, "y": 300}]
  },
  "blocks": [
    {
      "id": "b1", "x": 120, "y": 200, "width": 80, "height": 60, "room_id": 101,
      "vertices": [{"x":120,"y":200},{"x":200,"y":200},{"x":200,"y":260},{"x":120,"y":260}],
      "z_index": 1, "locked": false, "visible": true,
      "legend_code": "cleanliness_iso8",
      "style": {"stroke_width": 2, "stroke_color": "#374151", "fill_opacity": 0.35}
    }
  ],
  "scale": {"reference_line_pixels": 150, "reference_line_meters": 10, "pixels_per_meter": 15.0},
  "compass": {"north_angle": 0},
  "metadata": {
    "pdf_page_info": {"page": 1, "mediaBox": [0,0,595,842], "cropBox": [0,0,595,842], "rotation": 0, "userUnit": 1},
    "render_dpi": 150
  }
}
```
- `blocks[].room_id` 为功能区域与 Room 记录的关联键；`room_id` 为空表示未关联（对应 F3-019 灰色块）。
- ✚ `blocks[].vertices`：多边形顶点数组；矩形时可省略（由 x/y/width/height 推导 4 角点），不规则形状（L/U 形）必填。
- ✚ `blocks[].z_index` / `locked` / `visible`：图层排序、锁定、显隐控制。
- ✚ `blocks[].legend_code`：图例分类码（如 `cleanliness_iso8` / `temp_precision_2`），由 Room 的洁净度/温控精度字段映射，用于查看场景工艺编码着色（F3-016）。映射规则见 §6 待确认 5。
- ✚ `blocks[].style`：样式覆盖（线宽/线色/填充透明度），未指定时按图例默认配色。
- ✚ `metadata.pdf_page_info`：PDF 渲染元信息，用于精确还原底图坐标系（仅编辑期使用，不参与查看渲染）。
- ✚ `metadata.render_dpi`：底图渲染 DPI（72/150/300），默认 150。
- 坐标单位：画布像素（原点左上，Y 向下）；比例尺用于像素↔米换算。坐标与精度规范见 §2.5。

## 6. 待确认

1. **floor 表缺失 floor_plan_file 字段**：PRD F3-013 要求将底图路径写入 Floor 表 `floor_plan_file`，但 §4.3 未定义该字段。待确认采用「DDL 扩展 floor 表」还是「新增 floor_plan 表统一存储底图路径与平面图 JSON」。
2. **平面图 JSON 无持久化表**：§4 无存储 §2.3 结构的表，建议新增 `floor_plan` 表（见 §3.2），或确认由 floor 表 JSON 字段承载。
3. **US 覆盖缺口**：F3-016 ~ F3-024 未被现有 US-3.1/US-3.2 完全覆盖，需补充用户故事验收。
4. **热力图数据源口径**：冷量热力图按 `RoomLoadByWaterTemp.total_load`（需指定 water_temp_config_id）还是聚合 `LoadSummary`；未计算房间（无 summary）应作"未关联/未计算"灰显，待确认渲染降级策略。
5. **底图存储位置**：PDF 文件的物理存储（对象存储/本地路径）与访问鉴权策略未定义。
6. **图例 legend_code 映射规则**：`blocks[].legend_code` 与 `Room.cleanliness_level` / `design_temp_requirement` 的映射（如 ISO8→`cleanliness_iso8`、温控精度±2°C→`temp_precision_2`），需与 F3-016 工艺编码优先级判定（温控精度>洁净度>压差）对齐，待确认枚举全集。
7. **.pctdata 导出包不引入**：pdf-canvas-tool 原型的 `.pctdata` ZIP 包（manifest.json + source.pdf + pages + thumbnails + checksums.sha256 + 双轨坐标）适用于"标注数据作为独立产物交付下游"的场景；本平台平面图 JSON 直接存 `Floor` 表、底图存 MinIO，无独立产物导出需求，故仅吸收其"坐标精度规范、PDF 元信息、图例分类"思想，不引入 ZIP 包格式。
