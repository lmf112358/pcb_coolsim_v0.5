## 1. 模块概述

### 1.1 用途
管理用户认证、项目增删改查（CRUD）操作，以及基于地图的项目仪表盘。

### 1.2 核心功能
- 基于 JWT 的认证（Access + Refresh 令牌）
- 4 角色权限系统（Admin、PM、Engineer、Viewer）
- 集成城市气象数据的项目 CRUD
- 带项目标记点的地图仪表盘
- 项目搜索与筛选

## 4. 业务逻辑

### 4.1 认证流程

```
1. 用户提交凭据
2. 校验用户名/密码
3. 生成 Access 令牌（15 分钟有效期）
4. 生成 Refresh 令牌（7 天有效期）
5. 将令牌返回给客户端

令牌刷新时：
1. 客户端发送已过期的 Access 令牌 + 有效的 Refresh 令牌
2. 校验 Refresh 令牌
3. 生成新的 Access 令牌
4. 返回新的 Access 令牌

登出时：
1. 客户端发送 Refresh 令牌
2. 将 Refresh 令牌加入黑名单
3. 返回成功
```

### 4.2 项目创建流程

```
1. 用户提交项目数据
2. 校验必填字段
3. 从 CityConfig 中查找城市
4. 自动填充室外设计参数
5. 创建项目记录
6. 创建默认水温配置（7/12、12/17）
7. 触发 Celery 任务：fetch_weather_data(project_id)
8. 返回项目及气象任务 ID

异步气象获取：
1. Celery worker 接收任务
2. 调用外部气象 API
3. 解析并校验数据
4. 存储到 WeatherData 表
5. 更新 project.weather_data_status = 'available'
6. 发送 WebSocket 通知
```

### 4.3 权限校验流程

```
对于每个 API 请求：
1. 从 Authorization 请求头中提取 JWT
2. 校验令牌签名与过期时间
3. 从令牌中加载用户
4. 校验 user.is_active
5. 对于项目级端点：
   a. 检查用户是否为项目成员
   b. 检查项目级角色权限
6. 允许或拒绝请求
```

## 5. 校验规则

### 5.1 项目校验

| 字段 | 规则 | 错误消息 |
|-------|------|---------------|
| project_name | 必填，最多 200 字符 | "项目名称不能为空" / "Project name required" |
| city_id | 必填，必须存在于 CityConfig | "请选择有效的城市" / "Invalid city" |
| location | 可选，最多 200 字符 | - |
| description | 可选，最多 500 字符 | - |

### 5.2 用户校验

| 字段 | 规则 | 错误消息 |
|-------|------|---------------|
| username | 必填，唯一，邮箱格式 | "用户名已存在" / "Username taken" |
| password | 必填，最少 8 字符，需满足复杂度 | "密码强度不足" / "Password too weak" |
| role | 必填，有效选项 | "无效的角色" / "Invalid role" |

## 6. 安全考量

### 6.1 密码安全
- 使用 bcrypt 哈希（cost 因子 12）
- 禁止记录或返回密码
- 强制密码复杂度（最少 8 字符，含 1 个大写字母、1 个数字、1 个特殊字符）

### 6.2 令牌安全
- Access 令牌：15 分钟有效期
- Refresh 令牌：7 天有效期
- 在数据库中存储 Refresh 令牌哈希
- 登出时加入黑名单
- 使用时轮换 Refresh 令牌

### 6.3 数据隔离
- 项目查询按用户成员资格过滤
- 禁止跨项目数据泄露
- 基于 URL 的访问校验（无法通过 URL 访问其他用户的项目）
