## 1. Module Overview

### 1.1 Purpose
Manages user authentication, project CRUD operations, and the map-based project dashboard.

### 1.2 Key Features
- JWT-based authentication (Access + Refresh tokens)
- 4-role permission system (Admin, PM, Engineer, Viewer)
- Project CRUD with city-based weather data integration
- Map dashboard with project markers
- Project search and filtering

## 4. Business Logic

### 4.1 Authentication Flow

```
1. User submits credentials
2. Validate username/password
3. Generate Access Token (15 min TTL)
4. Generate Refresh Token (7 days TTL)
5. Return tokens to client

On Token Refresh:
1. Client sends expired Access Token + valid Refresh Token
2. Validate Refresh Token
3. Generate new Access Token
4. Return new Access Token

On Logout:
1. Client sends Refresh Token
2. Blacklist Refresh Token
3. Return success
```

### 4.2 Project Creation Flow

```
1. User submits project data
2. Validate required fields
3. Look up city from CityConfig
4. Auto-fill outdoor design parameters
5. Create project record
6. Create default water temperature configs (7/12, 12/17)
7. Trigger Celery task: fetch_weather_data(project_id)
8. Return project with weather task ID

Async Weather Fetch:
1. Celery worker receives task
2. Call external weather API
3. Parse and validate data
4. Store in WeatherData table
5. Update project.weather_data_status = 'available'
6. Send WebSocket notification
```

### 4.3 Permission Check Flow

```
For each API request:
1. Extract JWT from Authorization header
2. Validate token signature and expiry
3. Load user from token
4. Check user.is_active
5. For project-specific endpoints:
   a. Check if user is project member
   b. Check project-level role permissions
6. Allow or deny request
```

## 5. Validation Rules

### 5.1 Project Validation

| Field | Rule | Error Message |
|-------|------|---------------|
| project_name | Required, max 200 chars | "项目名称不能为空" / "Project name required" |
| city_id | Required, must exist in CityConfig | "请选择有效的城市" / "Invalid city" |
| location | Optional, max 200 chars | - |
| description | Optional, max 500 chars | - |

### 5.2 User Validation

| Field | Rule | Error Message |
|-------|------|---------------|
| username | Required, unique, email format | "用户名已存在" / "Username taken" |
| password | Required, min 8 chars, complexity | "密码强度不足" / "Password too weak" |
| role | Required, valid choice | "无效的角色" / "Invalid role" |

## 6. Security Considerations

### 6.1 Password Security
- Hash with bcrypt (cost factor 12)
- Never log or return passwords
- Enforce password complexity (min 8 chars, 1 uppercase, 1 number, 1 special)

### 6.2 Token Security
- Access Token: 15 minute TTL
- Refresh Token: 7 day TTL
- Store Refresh Token hash in database
- Blacklist on logout
- Rotate Refresh Token on use

### 6.3 Data Isolation
- Project queries filtered by user membership
- No cross-project data leakage
- URL-based access checks (can't access other user's project via URL)
