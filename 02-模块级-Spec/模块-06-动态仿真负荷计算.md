## 1. 功能概述

### 1.1 目的

使用多年逐时气象数据（8760 小时 × 3 年 ≈ 26280 个数据点）执行动态冷负荷仿真，为设备选型与能耗分析提供真实的年度负荷曲线。两种方式复用静态计算的 Q_terminal（末端负荷，桥梁），仅新风负荷随时间变化。

### 1.2 关键特性

- **方式一：气象数据驱动**（推荐）—— 基于真实历史气象逐时计算
- **方式二：比例系数法** —— 查 RatioCoefficient 表取负荷率=100% 列，按室外温度查表
- 多年仿真（1-3 年可选）
- 基于 WebSocket 的进度跟踪
- 结果落 TimescaleDB 超表 + 聚合统计

### 1.3 v0.5 范围说明（来自 PRD §10.1 / §15.4）

- **末端负荷 Q_terminal 是桥梁**，从静态计算结果 `RoomCalcResult.terminal_load` 取，不在动态阶段重算
- 新风负荷逐时变化，公式与静态一致（定义A，ρ=1.2）
- 总负荷 < 0 截断为 0（与静态统一，F6-006 / F4-014）
- v0.5.1 无 season_config 表（7 月高温和 1 月低温由气象数据本身区分）
- 生产负荷率（F6-013）v0.5 默认系数 = 1.0，预留接口，v0.6 接入实际生产曲线

## 2. 架构设计

### 2.1 两种仿真方式

```
末端负荷 Q_terminal（来自静态 RoomCalcResult.terminal_load，桥梁）
        │
        ├──→ 方式一：气象数据驱动（推荐，精度 < 1%）
        │      Q_dynamic(t) = Q_terminal + Q_fresh_air(t)
        │      Q_fresh_air(t) = ρ × V_fresh × (h_outdoor(t) − h_indoor) / 3600
        │      h_outdoor(t) 由逐时气象 psychrolib 计算（约 26280 次，NumPy 向量化 < 1s）
        │
        └──→ 方式二：比例系数法（近似，无气象时可用）
               Q_dynamic(t) = Q_static × k(t)
               k(t) 查 RatioCoefficient 表取"负荷率=100%"列，按室外温度查表
```

> 两种方式结果独立存储（F6-015），可同时运行对比。方式二为近似法，精度不适用 < 1% 口径（仅方式一适用，见 SAC-3）。

### 2.2 数据流

```
用户请求（POST /api/v1/projects/{id}/simulate/）
    ↓
校验 + 创建 Celery 任务（SimulationRun）
    ↓ 异步
Celery Worker
    ├── 加载气象数据（WeatherRecord，约 26280 条）
    ├── 加载房间静态结果（RoomCalcResult.terminal_load / fresh_air_volume / h_indoor）
    ├── 执行仿真（方式一或方式二）
    ├── 落库 DynamicLoadHourly（TimescaleDB 超表）
    ├── 聚合到 DynamicLoadSummary
    └── WebSocket 推送进度 + 完成通知
```

### 2.3 组件结构

```
simulations app/
├── engine/
│   ├── weather_driven.py     # 方式一：气象驱动
│   ├── ratio_coefficient.py  # 方式二：比例系数法（查 RatioCoefficient）
│   ├── enthalpy_vec.py       # NumPy 向量化焓值
│   └── aggregator.py         # 结果聚合
├── tasks.py                  # Celery 任务（run_dynamic_simulation）
└── views.py                  # API 端点
```

## 3. 方式一：气象数据驱动（F6-001 ~ F6-007）

### 3.1 核心公式

```
Q_dynamic(t) = Q_terminal + Q_fresh_air(t)
Q_fresh_air(t) = ρ × V_fresh_air × (h_outdoor(t) − h_indoor) / 3600    (kW)

Q_terminal  从 RoomCalcResult.terminal_load 取（桥梁，不重算）
V_fresh_air 从 RoomCalcResult.fresh_air_volume 取（静态算好的新风量）
h_indoor    从 RoomCalcResult.indoor_enthalpy_calc 取（全年恒定）
h_outdoor(t) 由逐时气象 psychrolib 计算
ρ = DefaultConfig.air_density（默认 1.2）
```

### 3.2 负值截断（与静态统一，F6-006）

- 新风负荷 Q_fresh_air(t) 可为负（冬季室外焓低于室内）
- 总负荷 Q_dynamic(t) < 0 时截断为 0
- 极值统计 Q_min 取 > 0 的有意义最小值

### 3.3 焓值向量化（F6-002 / F6-007 / F6-017）

室外焓值约 26280 次计算使用 NumPy 向量化，目标 < 1 秒：

```python
def simulate_weather_driven(project_id, years, room_ids=None):
    batch = create_calc_batch(project_id, 'weather_driven', years)
    weather = load_weather_series(project_id, years)        # WeatherRecord 序列
    # Q_terminal / V_fresh / h_in 全部来自静态 RoomCalcResult（桥梁）
    rooms = load_rooms_static(project_id, room_ids)
    T = len(weather)
    buf = []
    for t in range(T):
        h_out = vectorized_enthalpy(weather[t])            # F6-002，NumPy 向量化
        for r in rooms:
            q_fresh = RHO * r.fresh_air_volume * (h_out - r.h_indoor) / 3600   # F6-004
            q_total = r.terminal_load + q_fresh                                # F6-005
            if q_total < 0:
                q_total = 0.0                                                  # F6-006 截断
            buf.append((batch.id, r.id, ..., r.terminal_water_temp_config_id,
                        'weather_driven', weather[t].datetime,
                        weather[t].temp_dry, h_out, q_fresh, r.terminal_load, q_total))
        if len(buf) >= 2000:
            flush_dynamic_load_hourly(buf); buf.clear()
    flush_dynamic_load_hourly(buf)
    aggregate_dynamic(batch.id)
    return batch.id
```

## 4. 方式二：比例系数法（F6-008 ~ F6-011）

### 4.1 核心公式（PRD §15.4 / §14.8 / ADR-0003）

```
Q_dynamic(t) = Q_static × k(t)

k(t) 查 RatioCoefficient 表（PRD §14.8 统一映射表），取"负荷率=100%"列，按室外温度查表
Q_static = 静态设计总负荷（来自 RoomLoadByWaterTemp.total_load）
```

> **v0.5.1 修订：** 删除 v1.x 的 season/hour 二维系数矩阵（coefficient_matrix[season][hour][rate]）。改为查 RatioCoefficient 表取负荷率=100% 列，按室外温度查表（ADR-0003 两表合并为一张权威表）。

### 4.2 查表实现

```python
def simulate_coefficient(project_id, years, room_ids=None):
    batch = create_calc_batch(project_id, 'ratio_coefficient', years)
    weather = load_weather_series(project_id, years)
    rooms = load_rooms_static(project_id, room_ids)         # 含 Q_static
    # 查 RatioCoefficient 表（PRD §14.8），取负荷率=100% 列
    coeff = load_ratio_coefficient(project_id)              # ADR-0003，项目级可覆盖
    buf = []
    for t in range(len(weather)):
        k = coeff.lookup(outdoor_temp=weather[t].temp_dry, rate=1.0)   # F6-008/009
        for r in rooms:
            q = r.q_static * k                                # F6-010
            if q < 0:
                q = 0.0
            buf.append((batch.id, r.id, ..., r.terminal_water_temp_config_id,
                        'ratio_coefficient', weather[t].datetime,
                        weather[t].temp_dry, None, None, r.q_static, q))
        if len(buf) >= 2000:
            flush_dynamic_load_hourly(buf); buf.clear()
    flush_dynamic_load_hourly(buf)
    return batch.id
```

### 4.3 无气象降级（F6-011）

如项目缺气象数据，退化为使用国标夏季设计温度作为单一代表值（常数曲线）：

```python
def simulate_coefficient_fallback(project_id):
    temp = city_config(project_id).temp_dry_ac_summer        # 国标夏季设计温度
    k = coeff.lookup(temp, rate=1.0)
    for r in rooms:
        q = r.q_static * k     # 所有 t 相同（常数曲线）
```

## 5. 依赖模块四（Q_terminal 桥梁）

动态仿真**不在本模块重算末端负荷**，明确从静态计算结果取：

| 动态输入 | 来源 | 说明 |
|----------|------|------|
| Q_terminal | `RoomCalcResult.terminal_load` | 末端负荷桥梁，静态算好后动态直接读 |
| V_fresh_air | `RoomCalcResult.fresh_air_volume` | 静态算好的新风量（简单加法） |
| h_indoor | `RoomCalcResult.indoor_enthalpy_calc` | 室内焓，全年恒定 |
| Q_static | `RoomLoadByWaterTemp.total_load` | 方式二用的静态设计总负荷 |
| terminal_water_temp_config_id | `Room.terminal_water_temp_config_id` | 逐时结果按水温归档 |

> 必须先完成模块四静态计算，动态仿真才能运行（F6-021 触发前检查）。

## 6. 数据存储（TimescaleDB 超表）

### 6.1 DynamicLoadHourly（逐时结果，F6-019）

**TimescaleDB 超表**（不是普通表），按 `time` 分区 + `(project_id, calc_batch_id)` 索引：

| 字段 | 类型 | 说明 |
|------|------|------|
| project_id / calc_batch_id | BIGINT | 项目 + 批次 |
| room_id / floor_id / building_id | BIGINT | scope 标识（可为 NULL 表层级） |
| scope | VARCHAR | room / floor / building / project |
| water_temp_config_id | BIGINT | 按水温归档（ADR-0001） |
| simulation_type | VARCHAR | weather_driven / ratio_coefficient |
| time | TIMESTAMPTZ | 逐时时间戳（分区键） |
| outdoor_temp | DECIMAL | 该时刻室外温度 |
| outdoor_enthalpy | DECIMAL | 该时刻室外焓值（方式一） |
| fresh_air_load | DECIMAL | 新风冷负荷（方式一） |
| terminal_load | DECIMAL | 末端负荷（桥梁） |
| total_load | DECIMAL | 总负荷（截断后） |

### 6.2 DynamicLoadSummary（聚合统计）

峰值/均值/最小值/CV-RMSE，按 room/floor/building/project + water_temp 维度聚合。

### 6.3 SimulationRun（仿真任务）

mode: weather_driven / ratio_coefficient；status；progress；result_summary（对齐 CeleryTaskMeta）。

## 7. Celery 任务与进度

```python
@shared_task(bind=True)
def run_dynamic_simulation(self, project_id, simulation_type, years, room_ids=None):
    """simulation_type in {'weather_driven', 'ratio_coefficient'}。"""
    # 1. 检查气象（F6-021）
    if not has_weather(project_id, years):
        if simulation_type == 'weather_driven':
            raise WeatherDataMissingError()
        # 方式二可降级（F6-011）
    # 2. 执行
    if simulation_type == 'weather_driven':
        simulate_weather_driven(project_id, years, room_ids)
    else:
        simulate_coefficient(project_id, years, room_ids)
    # 3. 聚合 + 通知（F6-023）
    aggregate_dynamic(batch.id)
    send_websocket_notification(project_id, 'simulation_complete')
```

- F6-020：项目工作台 Tab4 提供"运行动态仿真"按钮
- F6-022：后台执行，WebSocket 推送进度（已计算/总数）
- F6-023：完成后通知用户
- F6-014/F6-015：两种方式结果独立存储，可同时运行对比

## 10. 错误处理

| 错误 | 原因 | 处理方式 |
|------|------|----------|
| 缺气象数据 | 所请求年份无数据（WEATHER_DATA_MISSING，422） | 方式一报错；方式二降级（F6-011）或提示用方式二 |
| 房间缺静态结果 | 未先跑静态 | 提示先完成静态计算（F6-021） |
| 计算溢出 | 极值 | 限制最大值，告警（CALCULATION_ERROR，422） |
| 数据库错误 | 连接问题 | 重试 3 次 |
| 内存超限 | 房间过多 | 分批处理 |

## 11. 测试策略

- 单元：方式一与独立 Python 脚本验算偏差 < 1%（SAC-3，仅方式一）；方式二系数查表正确
- 集成：完整仿真流水线，结果落 DynamicLoadHourly，计数 = 8760 × 年数 × 房间数
- 性能：1000 房间 × 3 年 < 30 秒（F6-016）；焓值 26280 次 < 1 秒（F6-017）
